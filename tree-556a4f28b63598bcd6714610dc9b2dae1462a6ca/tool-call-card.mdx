# ToolCallCard

Interactive tool-call chrome for agent transcripts: a semantic actor rail,
compact diamond/verb/details row, sunken expanded output, full lifecycle status,
risk/egress, inline expand, and fullscreen zoom. Host owns execution, cancel,
permission policy, and the deterministic paint tick. Never binds a provider
protocol.

## Live terminal (Ghostty-class)

One focused interactive surface — the same TermRock paint path as the lookbook
and [Components](/docs/components) pages. **Not SVG.** Focus the frame; use keys
or click to step multi-state packs when available.

## When to use / when not

| Use ToolCallCard | Prefer |
|------------------|--------|
| Interactive tool rows in agent UI | — |
| Paint-only one-shot summary | [ToolCard](/docs/components/tool-card) if present / thin Card |
| Full command stdout chrome | [TerminalOutput](/docs/handbook/terminal-output) |
| Permission grant UI | [Permission prompt](/docs/handbook/permission-prompt) |

## Status lifecycle

`Queued` · `Preparing` · `Running` · `WaitingInput` · `WaitingPermission` ·
`Streaming` · `Success` · `Warning` · `Failed` · `Cancelled` · `Detached`

## Safety

- `redact_tool_secrets` on copy/paint paths (host should still pre-redact)
- Egress note paints with warning role when present
- Outcomes are **requests only** — no process spawn/kill

## Keys

Enter expand · `c` cancel · `r` retry · `p` permission · `f` fullscreen · Esc exit zoom · Ctrl+A/C copy

## Example

```rust
use termrock::widgets::{
    ToolCall, ToolCallCard, ToolCallCardState, ToolStatus, ToolRisk,
};

let call = ToolCall::new("t1", "bash", "ran tests")
    .status(ToolStatus::Success)
    .args_summary("cargo test")
    .risk(ToolRisk::Read);
let mut st = ToolCallCardState::new();
// ToolCallCard::new(&call, &system)
//     .tick(frame_tick)
//     .paint(area, buf, &mut st);
let _ = (call, st);
```
