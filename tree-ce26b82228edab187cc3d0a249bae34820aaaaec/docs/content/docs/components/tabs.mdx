## Usage

```rust
use termrock::style::DesignSystem;
use termrock::widgets::{Tab, TabStatus, Tabs, TabsState};

let system = DesignSystem::default();
let tabs = [
    Tab::new("logs", "Logs").status(TabStatus::Running).closable(true),
];
let mut state = TabsState::new().with_selected("logs");
state.set_focused(true);
let _ = Tabs::new(&tabs, &system).gap(1);
```

## State and typed outcomes

The demo owns ephemeral widget state between events. The widget owns painted geometry, focus/selection mechanics, and typed outcomes. The host owns domain effects and decides what an emitted outcome means to the application.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Migrated handbook guidance

# Tabs

**Purpose.** Switch views, documents, or question groups. Each **panel’s state**
is host-owned (map id → panel). Tabs only own strip selection/focus/chrome.


## vs SegmentedControl

SegmentedControl changes mode on **one** surface. Tabs imply **separate
panels**, close actions, dirty/status, and richer overflow.

## Activation

- **Automatic** (default): arrows select  
- **Manual**: arrows focus; Enter/click select  

## Narrow contraction

Expanded → scrolling window → overflow `…` → Select trigger (multi-tab only).

## Outcomes

`SelectionChanged` · `CloseRequested` · `OverflowOpened` · `ReorderRequested`
· `FocusChanged`
