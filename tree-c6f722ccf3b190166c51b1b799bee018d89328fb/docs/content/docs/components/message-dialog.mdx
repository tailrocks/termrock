## Usage

The Code view above and this source excerpt use the exact paint setup registered for `message-dialog/details`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn message_dialog(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let tokens = system.clone().density(termrock::style::Density::default());
    let details = [
        DetailRow {
            id: "state",
            label: "State",
            value: "Ready",
            href: None,
            capability: DetailCapability::None,
            emphasis: false,
            style: None,
        },
        DetailRow {
            id: "reference",
            label: "Reference",
            value: "example-42",
            href: None,
            capability: DetailCapability::Copy,
            emphasis: false,
            style: None,
        },
    ];
    let mut state = DetailTableState::default();
    frame.render_stateful_widget(
        &MessageDialog::new(
            Dialog::new(
                "Result",
                Line::from("The operation completed.").into(),
                &tokens,
            )
            .style(Style::new())
            .emphasis(termrock::widgets::PanelChrome::Focused),
            &details,
            system,
        )
        .label_width(14)
        .wrap(true),
        area,
        &mut state,
    );
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Test recipe

Mount `message-dialog/details`, dispatch only the actions listed above, and assert both the returned outcome and changed Ratatui cells. Passive demos must reject input without trapping page navigation.
