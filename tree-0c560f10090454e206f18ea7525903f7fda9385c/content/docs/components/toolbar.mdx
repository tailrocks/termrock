## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

## Try it

- `←→ choose`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `Enter/Space activate`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `click action`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `resize for overflow`: Press, drag, and release on the visible handle; geometry/value follows the pointer.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted widget owns interaction state, focus chrome, hit geometry, and typed outcomes. The host only forwards backend-neutral events and performs no external effects.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `toolbar/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn toolbar_basic_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    use termrock::widgets::{Toolbar, ToolbarItem, ToolbarState};
    let items = [
        ToolbarItem::action("save", "Save").hint("C-s").priority(90),
        ToolbarItem::action("open", "Open").priority(50),
        ToolbarItem::separator("s1"),
        ToolbarItem::toggle("wrap", "Wrap", true).priority(40),
        ToolbarItem::action("find", "Find").priority(30),
    ];
    let mut state = ToolbarState::horizontal();
    state.set_surface_focused(true);
    state.set_cursor(Some("save"));
    frame.render_stateful_widget(
        &Toolbar::new(&items, system).overflow_id("more"),
        area,
        &mut state,
    );
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Test recipe

Mount `toolbar/basic`, dispatch each listed action, and assert the typed outcome, changed Ratatui cells, persistent follow-up state, pointer hit geometry, and Reset behavior.
