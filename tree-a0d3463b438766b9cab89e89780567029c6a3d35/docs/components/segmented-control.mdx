This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

## Try it

- `←→ change view`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `Home/End`: Move through the real focus/selection model; the next action uses the new target.
- `click segment`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The demo preserves widget state between events. The component owns hit geometry, focus/selection mechanics, and typed outcomes; the host applies domain effects.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `segmented-control/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn segmented_control_basic_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let items = [
        SegmentedItem::new("list", "List").priority(90),
        SegmentedItem::new("grid", "Grid").priority(80),
        SegmentedItem::new("table", "Table").priority(70),
    ];
    let mut state = SegmentedControlState::new(Some("grid"));
    state.set_surface_focused(true);
    let _ = SegmentedControl::new(&items, system)
        .collapse_below(0)
        .paint(area, frame.buffer_mut(), &mut state);
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Test recipe

Mount `segmented-control/basic`, dispatch only the actions listed above, and assert both the returned outcome and changed Ratatui cells. Unsupported input remains ignored without trapping page navigation.
