# 0432: HistoryPicker mutation actions

## Boundary

`HistoryPickerState::handle_key` treats picker mutation and submission
shortcuts as physical key-press actions. A held key must not emit repeated
delete/pin requests or select and close the picker through the query editor.

## Change

- `Press` Ctrl+D emits the existing `Deleted` outcome; Repeat and Release are
  ignored.
- `Press` Ctrl+P emits the existing `PinToggled` outcome; Repeat and Release
  are ignored.
- `Press` Enter, Tab, BackTab, and Ctrl+M submit the selected entry through
  the existing path; Repeat and Release are ignored.
- Escape cancellation, query editing, and cursor/page navigation retain their
  existing lifecycle and repeat behavior.

## Host migration

Hosts routing raw HistoryPicker events must continue passing the complete
`KeyEvent`, including its lifecycle kind. Do not synthesize repeated delete or
pin requests for Repeat or Release events; the state adapter consumes them as
no-ops.
