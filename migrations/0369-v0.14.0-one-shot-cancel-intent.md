# 0369 — v0.14.0 Escape cancellation is one-shot

## Boundary

Escape cancellation is a one-shot action, while text navigation remains
repeatable. A held Escape key must not repeatedly dismiss or change modes in a
host that consumes `UiIntent::Cancel` or a raw widget key event.

## Change

- `default_text_area_intent` maps an accepted Escape press to
  `Some(UiIntent::Cancel)` and maps repeat/release events to `None`.
- `TextAreaState` accepts raw Escape only on press, with no modifier or Shift.
- `PromptComposerState` accepts only a bare Escape press for completion,
  fullscreen, selection-clear, and dismiss transitions.
- Repeatable navigation keeps its existing press/repeat handling.

## Host migration

Treat `None` for repeated or released Escape as ignored input. If a host also
handles raw Escape events, gate dismissal or mode changes on a press and the
surface's supported modifier policy. Do not impose a global press-only gate on
the key adapter: that would disable repeatable navigation. Direct callers of
`TextAreaState::handle_intent(UiIntent::Cancel)` continue to control invocation
frequency explicitly.
