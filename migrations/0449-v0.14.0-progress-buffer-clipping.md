# 0449 — v0.14.0 ProgressBar buffer clipping

## Boundary

`ProgressBar` accepts a caller-provided `Rect` and writes directly to a
ratatui `Buffer`. The render boundary must constrain that rectangle to the
buffer before state projection, layout, truncation, or any cell write.

The canonical Progress component treats clipping as a widget invariant, not
as a caller responsibility. A partially overlapping rectangle paints only its
intersection; a wholly outside rectangle is a no-op. Empty rectangles remain
safe no-ops.

## Canonical evidence

The reference implementation intersects `area` with `*buf.area()` at every
direct render entry point:

- `render_bar` clips before determinate layout and track/percentage painting.
- `Meter::render` clips before value, suffix, and line/block layout.
- `render_indeterminate` clips before sweep geometry and track writes.
- `render_spinner` clips before the spinner glyph and label writes.

The reference `DESIGN.md` progress contract keeps the fixed status suffix,
drops the track below six cells, and requires controls and labels not to be
overlapped. Those rules only hold when geometry is derived from the visible
buffer intersection.

## Root cause

TermRock's public `paint_state` and `paint` methods check only
`area.is_empty()`. They pass raw caller geometry through every downstream
route:

1. `paint_state` projects `ProgressBarState` into a borrowed `ProgressBar`
   and calls `paint`.
2. `paint` dispatches `MultiLine` to `paint_multiline`, or `Compact` and
   `Detailed` to `paint_row`.
3. `paint_multiline` paints title and metadata, and routes its track through
   `paint_kind`.
4. `paint_row` routes through `paint_kind`.
5. `paint_kind` calls `render_determinate` or `render_indeterminate`.
6. The helpers perform direct `set_string`/`set_stringn` writes using the
   unbounded rectangle.

An offset, partially overlapping, or wholly out-of-buffer rectangle can
therefore panic, report invalid buffer parts, or derive geometry from cells
that cannot be painted. The enabling condition is the missing public render
boundary; adding checks inside individual glyph loops would leave other
routes unsafe.

## Change

- Intersect the requested area with `*buffer.area()` at both public paint
  boundaries before state projection, recipe dispatch, layout, or writes.
- Return immediately for an empty intersection.
- Preserve the existing `ProgressBar` and `ProgressBarState` signatures,
  recipes, status suffixes, label/meta behavior, animation, semantics, and
  public `Widget` implementations.
- Keep all render routes covered: state-backed and builder-backed painting;
  compact and detailed rows; multiline title, track, and metadata; and both
  determinate and indeterminate tracks.
- Do not make downstream helpers depend on callers pre-clipping rectangles.

## Test contract

Focused tests must render every route into an offset buffer and exercise:

- determinate compact/detailed rows, including label and metadata;
- indeterminate rows;
- multiline title, track, and metadata;
- `paint_state` for visible state and its recipe variants;
- rectangles that are partially clipped on each edge;
- rectangles wholly outside the buffer and empty rectangles;
- narrow intersections, confirming existing percentage-only and tiny-width
  behavior remains safe; and
- the invariant that cells outside the intersection are unchanged.

Each case must complete without panic and must paint only the requested
intersection. Tests should cover both `ProgressBar::paint` and the `Widget`
delegates so the public boundary cannot regress through an alternate entry
point.

## Visual and API impact

This is a visual safety correction at clipped layouts: visible progress bars
keep their existing Junie geometry, while partial layouts no longer write past
the visible buffer or claim space outside it. Fully outside widgets disappear
without mutation. No public signature or semantic identity changes; callers
may continue passing layout rectangles without manually clipping them.

## Host migration

No host code change is required. Hosts should continue passing the layout
rectangle returned by their normal layout system. Do not add per-call-site
clipping or duplicate buffer-boundary logic; the reusable widget owns this
contract.

No compatibility shim, alias, fallback path, or deprecation period is added.
