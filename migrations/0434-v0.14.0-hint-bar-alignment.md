# 0434: HintBar alignment is honored

## Boundary

`HintBar::alignment` is now a real placement contract. Previously, the value
was stored but the borrowed-hint painter always started at the left inset. The
default remains `CellAlignment::Left`; callers that selected `Center` or
`Right` now get the requested placement.

## Behavior changes

- **Left placement.** The fitted hint block starts at the canonical one-cell
  inset from `area.x`.
- **Centered placement.** The painter measures the hints that fit first, then
  centers that block in the available row. The start is clamped so it never
  crosses the left inset or the space reserved for a right status.
- **Right placement.** The fitted block is placed against the right edge of
  the hint region, preserving the left inset when the row is too narrow and
  never entering the right-status region.
- **Clipping and clamping.** Placement is resolved inside the buffer and area
  intersection. Width uses terminal display columns, not bytes. Hints that do
  not fit are dropped from the right; two cells remain for the canonical `…`
  cut marker when space allows. A right status keeps its edge and wins any
  overlap.

This matches the placement rules of the canonical `keyhint::render_aligned`:
fit before positioning, preserve the continuation marker, keep status at the
right edge, and clamp the hint block to the usable interval. It applies to the
borrowed `HintBar` path. The rich-span `paint_hint_bar` helper now wraps whole
hint groups and substitutes a complete cut marker for an over-wide group, so a
narrow row never splits a key/action pair.

## Local API

Use `CellAlignment` from `termrock::text` and configure the existing
`HintBar` builder. `paint` is the explicit local painter; `Widget::render` is
the equivalent trait entry point.

```rust
use ratatui_core::{
    buffer::Buffer,
    layout::Rect,
    widgets::Widget,
};
use termrock::{
    style::DesignSystem,
    text::CellAlignment,
    widgets::{Hint, HintBar},
};

let hints = [Hint {
    chord: "Enter",
    label: "Open",
    priority: 1,
    visible: true,
}];
let system = DesignSystem::default();
let area = Rect::new(0, 0, 80, 1);
let mut buffer = Buffer::empty(area);

let left = HintBar::new(&hints, &system).alignment(CellAlignment::Left);
left.paint(area, &mut buffer);

let centered = HintBar::new(&hints, &system)
    .alignment(CellAlignment::Center)
    .right("Cell saved");
centered.paint(area, &mut buffer);

let right = HintBar::new(&hints, &system).alignment(CellAlignment::Right);
right.render(area, &mut buffer);
```

`HintBar::right("Cell saved")` remains optional. When present and wide enough
to render, the status is measured before hint placement and retains its
right-edge ownership for every alignment.

## Consumer edits

- Re-bless snapshots and fixture expectations for any bar configured with
  `.alignment(CellAlignment::Center)` or `.alignment(CellAlignment::Right)`;
  those calls no longer render left-aligned.
- Remove caller-side x-offset workarounds. Configure placement through
  `.alignment(...)` so fitting, cut-marker reservation, and status clamping
  share one path.
- Keep `CellAlignment::Left` for the old left-inset layout. No compatibility
  alias or second alignment implementation exists.

## Rollback

No persisted data changes. A caller needing the former layout can explicitly
select `CellAlignment::Left`; restoring the pre-0434 implementation is a
source rollback, not a separate public API path.
