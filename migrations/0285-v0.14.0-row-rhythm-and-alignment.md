# 0285 — Row rhythm and alignment

Separators, header offsets, and hint alignment were decided per widget. Three
key-value widgets used three different separators; the process monitor's header
sat one cell right of its own data; the status bar's dot had space on one side
only; hint rows had two alignment paths and a hardcoded group gap. This gives
each of those one owner.

## Behavior changes

- **`ProcessTable` header alignment.** The header reserved four cells for a
  one-letter status column while rows spend three (mark + status), so every
  column printed one cell right of its data. The header now reserves the mark
  cell explicitly. A regression test pins the `PID` column's right edge to its
  header's.
- **One key-value separator.** `DetailTable` painted `" : "` while
  `KeyValueList` and `KeyValueTable` painted two spaces, and
  `KeyValueList::dense` painted one. All three now read
  `DesignSystem::kv_separator()`, which defaults to the two-cell gutter —
  alignment already carries the pairing. Restore the rule per system with
  `system.with_kv_separator(KvSeparator::Colon)`.
- **Symmetric status-bar separator.** The slot separator painted `· content`;
  it now paints ` · ` with equal space on both sides, and needs four columns
  instead of three before it appears.
- **`Popover` header rule.** A header taller than one row spends its last row
  on a border rule, so a multi-row header reads as a band. Single-row headers
  are unchanged. A dead empty `if` and a branch whose arms were identical are
  gone; the title now contracts with the catalog ellipsis instead of being
  hard-cut.
- **`Select` separator rows** span the full list width. They were capped at 64
  columns, so a wider dropdown drew a rule that stopped in mid-air, and they
  now use the glyph catalog's rule instead of a literal.
- **`KeyboardHelp`** joins hints with the shared separator token, ASCII
  included.

## New surface

```rust
use termrock::{
    style::{Glyph, GlyphSet},
    text::CellAlignment,
    widgets::{HINT_GROUP_JOIN, HINT_SEPARATOR_COLS, HintBar},
};

// `·` is now catalogued, so the ASCII profile answers `|` on its own.
assert_eq!(GlyphSet::Unicode.meta_separator(), "·");
assert_eq!(GlyphSet::Ascii.meta_join(), " | ");
assert_eq!(Glyph::MetaSeparator.resolve(GlyphSet::Ascii).text, "|");

// Footer hints have one alignment path; `render_hint_bar` resolves through it.
let hints = [];
let system = termrock::style::DesignSystem::phosphor();
let bar = HintBar::new(&hints, &system).alignment(CellAlignment::Center);
let _ = (bar, HINT_GROUP_JOIN, HINT_SEPARATOR_COLS);
```

`HintBar` also paints through `text::paint_line_overflow` now, so a hint row
too wide for its area ends in the catalog ellipsis instead of a hard cut.

## Consumer edits

- Pinning `" : "` from a `DetailTable` render: either re-bless the snapshot or
  build the system with `KvSeparator::Colon`.
- Pinning the status bar's separator column: it moved one cell right.
- Matching exhaustively on `Glyph`: add the `MetaSeparator` arm.
- Painting `"   "` between hint groups by hand: use `HINT_GROUP_JOIN`.
