# 0428: QuickOpen one-shot actions

## Boundary

`QuickOpenState::handle_key` treats confirmation, cancellation, result focus
traversal, jump-mode entry, and presentation toggles as physical key-press
actions. A held key must not activate an item, cancel a search, move result or
provider focus, enter jump mode, or toggle presentation repeatedly.

## Change

For the QuickOpen keyboard adapter:

- `Press` Enter activates the selected result; Repeat and Release are ignored.
- `Press` Escape clears the query or cancels an in-flight search/picker;
  Repeat and Release are ignored.
- `Press` Tab, BackTab, and Ctrl+Tab move result/provider focus; Repeat and
  Release are ignored.
- `Press` Ctrl+J enters jump mode and Ctrl+\\ toggles presentation; Repeat and
  Release are ignored.
- Character entry, editing, arrow movement, paging, and Ctrl+P/Ctrl+N
  provider navigation retain their repeatable behavior.

The one-shot gate runs before forwarding keys to `TextInputState`, preventing
its repeatable Enter/Tab/Escape paths from bypassing QuickOpen's action
boundary.

## Host migration

Hosts routing raw QuickOpen events must continue passing the complete
`KeyEvent`, including its lifecycle kind. Do not synthesize a second
activation, cancellation, focus move, jump request, or presentation toggle for
Repeat or Release events; the QuickOpen state adapter consumes them as no-ops.
