# 0382 — v0.14.0 QuickOpen returns borrowed match rows

## Boundary

`filter_quick_open_items` now returns `QuickOpenMatch<'a, Id>` rows borrowing
the caller's `QuickOpenItem` slice. QuickOpen filtering no longer requires
cloning each item or its identifier.

## Change

- Match score and label/detail ranges live on the borrowed match row; the
  original item remains host-owned.
- `QuickOpenRow` lets the widget consume either locally filtered matches or
  raw `QuickOpenItem` rows supplied by an asynchronous host search.
- QuickOpen state and widget types now carry the identifier and row types.

## Consumer migration

Callers that inspect filtered rows should read item fields through
`QuickOpenMatch::item` and match metadata through its range fields. Pass either
the borrowed matches or raw items to `QuickOpenState` and `QuickOpen`; async
search providers can keep supplying host-owned raw rows. No persisted data
changes.

## Rollback

Restore the prior owned-result filter API and remove the borrowed match row
types. Rebuild filtered rows if the host requires an owned result collection.
