# 0304 — The underline scan covers the builder too

Plan 005 retired underline as an interaction cue and left a source scan to keep
it retired. The scan looked for `Modifier::UNDERLINED` and `.underlined()`, so
anything reaching the same modifier through `TextSpan::underline(true)` walked
past it — which is how the focused search match stayed underlined until agent
A caught it by eye.

## Gate change

`design_gate::interaction_underline_is_dead` now also flags
`.underline(true)` outside its whitelist. `markdown.rs` joins the whitelist:
a markdown link is a link, which is the one thing underline still means.

## Behavior change

`Heading` at `HeadingLevel::H1` no longer underlines its text. It already
paints a heavy rule row beneath itself, so the underline was a second cue for
one fact — and the second cue was the one the grammar reserves for links. H1
remains distinct: strong text plus the heavy rule, against H2's light rule and
H3's role-only weight.

## Consumer edits

- Snapshots of an H1 heading lose the `UNDERLINED` modifier on the title row.
  The rule row below it is unchanged.

## Validation

```sh
cargo nextest run -p termrock --all-features --test design_gate interaction_underline
mise run check
```
