# 0380 — v0.14.0 Viewport owns persistent selection state

## Boundary

`Viewport` now keeps interaction and cell-layout state in a caller-owned
`ViewportState`. The `StatefulWidget` state is no longer `DialogScroll`.

## Change

`ViewportState::scroll` carries the two-axis offsets. The same state also owns
selection, drag anchors, cached cell geometry, and append/eviction rebasing.
`Viewport` exposes pointer selection, word selection, copy, Escape clearing,
and `ViewportEvent` results. `LogPaneState` retains one `ViewportState` so
selection and horizontal scrolling survive rebuilt borrowed views.

Viewport content that should reuse cached cell layout must provide a
monotonically changing `content_revision` whenever line text, styles,
alignment, or other layout-affecting content changes. The default uncached
revision rebuilds layout on every call, which is safe for recreated or
mutated borrowed storage but does not provide the cached hot path.

## Consumer migration

Replace `DialogScroll` passed to `Viewport` with `ViewportState`, and access
offsets through `state.scroll`. Route viewport mouse and key events through
`Viewport::on_mouse` and `Viewport::on_key`; handle `ViewportEvent::Copy` in
the host clipboard path. Call `content_revision` for in-place or recreated
model updates when layout reuse is desired; advance it for text, style,
alignment, and layout changes.

The old-revision visual harness remains pinned to its historical
`DialogScroll` API by design; its current-head compile contract uses
`ViewportState`.
