# 0455: Panel surface resolver and removal of the raised/elevation API

## Breaking change

0455 removes Panel's private raised state, the builder method
`.raised(bool)`, and the public `Panel::elevation()` accessor. These were
ambiguous at the Panel boundary: a numeric elevation could disagree with the
variant, overlay ownership, transparency, and the pixels actually painted.
There is no compatibility alias or fallback mode.

Callers must remove `.raised(...)` from Panel construction. Code that inspected
`Panel::elevation()` must inspect `Panel::surface_recipe()` instead; it reports
the resolved surface plane used by the Panel contract. Use `.overlay(true)`
only for a real overlay surface, not as a replacement for an ordinary tonal
flag.

`Card::panel()` no longer depends on the removed Panel state. Cards remain the
canonical filled surface: `SurfaceRecipe::Inset`, `Role::Surface`, the
canonical `2×1` inset, and no box frame.

## Authoritative resolver

One variant-aware resolver drives `Panel::surface_recipe()`,
`Panel::recipe()`, and Panel paint. Focus and danger select chrome; they do not
change the in-flow plane. The effective contract is:

| Variant/state | Surface recipe and paint plane |
| --- | --- |
| Quiet, including the Card adapter | `SurfaceRecipe::Inset` → `Role::Surface` / `surface` (`#111111`); filled, borderless card geometry. |
| Bordered, Interactive, or Selected in flow | `SurfaceRecipe::Canvas` → `Role::Canvas` / `canvas` (`#000000`); the Panel owns the frame and its content inset. |
| Any non-divider overlay | `SurfaceRecipe::Overlay`, `OverlayFocused`, or `OverlayDanger`; `Role::Elevated` / `surface-elevated` (`#18181b`) with a Panel frame forced by `.overlay(true)`. |
| DividerOnly, including when overlay is requested | `SurfaceRecipe::Canvas` metadata with `PanelRecipe.fill == None`; DividerOnly wins, stays transparent, and the Panel leaves the buffer unfilled while painting divider rules only. |

For every non-DividerOnly variant, `.overlay(true)` forces the Panel frame and
uses the elevated overlay recipe. Focus and danger change overlay chrome only;
they do not change the elevated plane. DividerOnly wins over overlay and stays
transparent. A backdrop is owned by the overlay host. Framed in-flow panels
stay on Canvas; they do not become borderless elevated surfaces. Card focus,
selection, and danger chrome do not promote the Card plane.

The reference design in
`/Users/donbeave/terminal-components-claude/DESIGN.md` defines `surface` as
the card plane, `canvas` as the framed in-flow plane, and `surface-elevated`
as the lifted dialog/popup plane. This migration aligns the Panel resolver to
those canonical roles. Historical migration 0442 remains the owner of the
default borderless Panel/Card fill change.

## Consumer migration

1. Delete every Panel `.raised(true)` and `.raised(false)` call. Select
   `PanelVariant::Quiet` for a filled card-like panel, a framed variant for an
   in-flow framed surface, or `.overlay(true)` for an actual overlay.
2. Replace `Panel::elevation()` checks with `Panel::surface_recipe()` checks.
   Match `Inset`, `Canvas`, and the Overlay family; do not infer the final
   plane from a separate elevation value.
3. Keep canonical Cards on `Card`; do not add a fill override or a second
   elevation control around the Card adapter.

## Validation

Tests must prove that the resolver and painted pixels agree for Quiet/Card,
all in-flow framed variants, overlays, and DividerOnly. Include focused and
danger chrome, Card geometry, partial and empty allocations, narrow widths,
out-of-buffer allocations, and Unicode fixtures. Required gates:

```sh
cargo test -p termrock panel --all-features --locked --offline
cargo test -p termrock card --all-features --locked --offline
cargo test -p termrock surface --all-features --locked --offline
cargo fmt --all -- --check
cargo clippy -p termrock --all-targets --all-features --locked --offline -- -D warnings
git diff --check
```

The expected visual roles are exact: Cards and Quiet panels use `#111111`,
in-flow frames use `#000000`, overlays use `#18181b`, and DividerOnly remains
transparent. Rollback is by source revision, not by a runtime compatibility
path.
