# 0335 — KeyEvent phase predicates

**Version:** `v0.14.0`
**Kind:** additive API + input-path refactor

`KeyEvent` now exposes canonical phase predicates so consumers do not repeat
raw `kind` comparisons or accidentally give press, repeat, and release events
different meanings.

## Canonical predicates

```rust
if key.is_press() {
    activate();
}

if key.is_action() {
    move_selection();
}

if key.is_repeat() {
    show_repeat_state();
}

if key.is_release() {
    ignore_release();
}
```

`is_action()` is true for `Press` and `Repeat`. Use `is_press()` for
non-repeatable activation, toggle, and cancel actions. Use `is_release()` when
release-specific handling is required.

The default semantic intent bridges use these predicates as their single phase
vocabulary. Existing event behavior is unchanged.
