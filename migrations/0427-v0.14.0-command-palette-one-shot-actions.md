# 0427: CommandPalette one-shot actions

## Boundary

`CommandPaletteState::handle_key` treats confirmation, cancellation, and
result focus traversal as physical key-press actions. A held key must not
activate a command, submit an argument, clear or close the palette, or move
the result cursor repeatedly through the raw keyboard adapter.

## Change

For the command palette keyboard adapter:

- `Press` Enter activates the selected result or submits its argument;
  Repeat and Release are ignored.
- `Press` Escape clears the query, closes a nested page, cancels argument
  entry, or cancels the palette; Repeat and Release are ignored.
- `Press` Tab and BackTab move result focus; Repeat and Release are ignored.
- Character entry, editing, arrow movement, paging, and history navigation
  retain their repeatable behavior.

The same press-only checks apply in the argument phase before forwarding any
other key to its `TextInputState`. This prevents TextInput's repeatable
Enter/Tab/Escape paths from bypassing the palette action boundary.

## Host migration

Hosts routing raw palette events must continue passing the complete
`KeyEvent`, including its lifecycle kind. Do not synthesize a second
activation, cancellation, or result-focus move for Repeat or Release events;
those are consumed as no-ops by `CommandPaletteState::handle_key`.
