# 0447: DateTimePicker physical one-shot actions

## Boundary

`DateTimePickerState::handle_key` is the raw physical adapter for a picker
that combines a text draft, calendar, and time/day-list views. Lifecycle,
view-transition, open/close, and value-selection actions must not repeat while
a key is held.

## Change

- Non-Press Enter, Tab, BackTab, and Escape events are ignored before draft
  commit/edit, view transition, close, or cancel handling.
- Non-Press calendar-space selection, empty-field open keys, and Alt+Down open
  are ignored before picker state or value mutation.
- Repeatable draft text, calendar/list navigation, and typeahead remain
  supported. Semantic `handle_intent` remains phase-free.

## Host migration

Hosts routing raw `DateTimePickerState` events must continue passing complete
`KeyEvent` values, including lifecycle kind. Do not synthesize repeated
commit, cancel, open/close, view-transition, or calendar-selection actions
from Repeat or Release events. Use `handle_intent` for semantic commands that
are not raw physical keyboard events.
