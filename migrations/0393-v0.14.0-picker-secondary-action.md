# Picker exposes a host-owned secondary action

`PickerState::handle_key` now emits `PickerOutcome::Secondary(id)` when the
selected row receives an unmodified Delete key press. The outcome carries the
selected stable identity and does not mutate the query or selection. Delete
repeats, releases, modified keys, disabled input, and missing, stale,
disabled-row, or non-navigable selections are ignored.

Hosts must handle the new outcome and decide what the secondary action means.
The catalog Tabs picker uses it to close the selected tab, after confirming
that the identity still belongs to the current projection and that at least
one tab will remain. `TablePro` consumes the unsupported action explicitly.

Update exhaustive matches on `PickerOutcome` and add host handling only where
Delete should have a row-level action.
