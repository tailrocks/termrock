# 0478: SplitPane ratio, cell-seam, collapse, and fallback contract

## Boundary

`SplitPane` adopts the canonical `Splitter` arithmetic for its expanded,
feasible path. For a nonzero split axis, the split reserves one divider cell;
therefore `usable = axis_length.saturating_sub(1)`. An expanded split ratio is
globally inclusive **5–95%** of that usable axis. `SplitRatio` stores the bound
as basis points, **500–9500**. The divider is outside the ratio calculation.

The physical seam has a second, ordered constraint: after the stored ratio is
converted to a first-pane cell allocation, layout and interaction clamp that
first cell to the feasible interval
`first_min..=usable - second_min`. The stored ratio is normalized
independently to `500..=9500`. Pane-minimum clamping therefore has precedence
for the physical seam: extreme minimum values may place the painted or
interactive seam outside 5–95% while the stored `SplitRatio` remains within
500–9500 basis points. No single interval simultaneously enforces the
stored-ratio bound and the physical seam minimums.

The zero-usable-axis case is distinct. When `usable == 0` and both physical
minimums are zero, the layout has empty first and second panes and an empty
divider; no divider cell is painted or hit-tested. This covers both a
zero-length split axis and a one-cell split axis. When `usable == 0` but
either minimum is nonzero, the minimums are impossible and the
direction-specific fallback below applies instead, including for a
zero-length split axis.

An empty pane never retains a divider: whenever either pane is empty, the
divider/handle is `Rect::ZERO` and is neither painted nor hit-tested. This
includes `usable == 0` layouts and `usable == 1` layouts when cell allocation
leaves one pane empty, as well as collapsed layouts and impossible-minimum
fallbacks.

The canonical reference calls the one-sided state `Maximized`. Its
`Maximized::First` layout gives the full input area to the first pane and
`Maximized::Second` gives it to the second; the other pane is empty and
`handle()` returns `Rect::ZERO`. TermRock exposes explicit `SplitSide` collapse
rather than a public `Maximized` enum, and its argument names the side to
hide: `collapse(SplitSide::First)` empties the first pane and shows the second;
`collapse(SplitSide::Second)` empties the second and shows the first. Thus the
`SplitSide` names the hidden side, while canonical `Maximized` names the shown
side. The current source gives the same one-sided geometry: the visible pane
gets the full input area, the hidden pane and divider are empty, and rendering
cannot paint or hit-test a collapse handle. Collapse is resolved before
minimum feasibility, so it remains a one-sided state even when the configured
minimums are impossible.

For a pointer drag, the requested coordinate is first clamped to that
physical feasible interval. If the clamp leaves the first-pane allocation at
the already-painted seam, the drag is a physical-seam no-op: it returns
`Ignored`, leaves the stored `SplitRatio` unchanged, and preserves explicit
collapse and other interaction state. A raw pointer coordinate outside the
feasible interval must not force a new normalized stored ratio.

If the pane minimums cannot both fit in the usable axis, there is no feasible
seam. Keyboard and drag interaction is a no-op in that state: the stored
expanded ratio and other interaction state are not mutated. Layout uses the
canonical direction-specific degradation instead:

- **Horizontal:** the second pane occupies the full input area; the first pane
  and divider are empty.
- **Vertical:** the first pane occupies the full input area; the second pane
  and divider are empty.

The impossible-minimum fallback is layout-only. It does not turn an endpoint
ratio into collapse and does not rewrite the stored ratio. Explicit collapse
is checked before minimum resolution and takes precedence. The `usable == 0`,
`0/0` minimum case is an empty layout, not an impossible-minimum fallback;
with a nonzero minimum at `usable == 0`, the direction-specific fallback
applies. There is no separate zero-axis override for that impossible case.

The old contract accepted 0–100%. Endpoint ratios could starve a pane and
were also used by hosts as an accidental collapse mechanism. Collapse is an
explicit state transition and is not represented by an expanded ratio.

Migration `0476` (PasswordInput) and `0477` (PathInput) are separate input API
boundaries. They remain unchanged; this SplitPane record is `0478`.

## Normalization paths

Every path that creates or changes an expanded ratio normalizes to the same
inclusive basis-point range:

- `SplitRatio::from_basis_points` clamps values below `500` to `500` and
  values above `9500` to `9500`.
- `SplitRatio::from_percent` maps percentages below `5` to `5%` and above
  `95` to `95%`.
- `SplitPaneState::new` and `SplitPaneState::set_ratio` retain only the
  normalized ratio supplied by `SplitRatio`.
- Serde deserialization normalizes persisted values before they become state;
  it does not restore `0%`/`100%` endpoint semantics.
- Focused keyboard movement and pointer dragging convert or derive a
  first-pane cell allocation, then clamp the physical allocation to the pane
  minimums. The resulting stored ratio is normalized independently to
  `500..=9500`; these sequential rules are not one shared interval. If
  minima are impossible, neither path mutates the ratio.
- Expanded layout quantizes the stored ratio to cells with floor division:
  `first = floor(usable * basis_points / 10_000)`, followed by physical
  minimum clamping. Pointer dragging clamps the requested first-cell seam,
  then stores the nearest whole-percent ratio represented as basis points
  (`percent * 100`). Keyboard movement stores the smallest whole-percent
  ratio that floors to its target cell. The next layout floors that stored
  ratio again. For example, `usable == 7` and requested first pane `2` stores
  `29%` / `2_900` basis points and lays out as first pane cell `2` on the next
  pass. Arbitrary ratios supplied directly may still use any basis point in
  `500..=9500`; cell-seam interaction is quantized to whole percentages.
- An interaction that is already saturated is a no-op: it returns `Ignored`,
  leaves the stored ratio unchanged, and does not clear explicit collapse
  state. Outward keyboard movement at 500 or 9,500 basis points is saturated.
  For pointer dragging, compare the feasible first-cell allocation before
  deriving a stored ratio; when minima clamping leaves that allocation
  unchanged, the drag is likewise `Ignored` and the stored ratio remains
  unchanged, even if the raw pointer coordinate differs.

Values already inside `500..=9500` are preserved unless a feasible pane
minimum requires a different physical seam. Values outside the global range
are clamped, not rejected and not interpreted as pane collapse.

## Explicit collapse migration

Hosts that used `SplitRatio::from_percent(0)` or `from_percent(100)` to hide a
side must use the state API instead:

```rust
let mut state = SplitPaneState::new(SplitRatio::from_percent(50));
state.collapse(SplitSide::First);  // or SplitSide::Second
// ... later ...
state.expand();
```

`SplitPaneState::collapse` makes the requested side empty while preserving the
configured normalized expanded ratio. `SplitSide::First` hides the first pane
and gives the full input area to the second; `SplitSide::Second` hides the
second and gives it to the first. The current source and canonical maximized
equivalent use no handle (`Rect::ZERO`); `expand` restores that exact ratio.
Do not encode collapse in persisted ratios, keyboard endpoints, drag
coordinates, or a second host-side sentinel. Hosts should consume the
normalized value returned by `ratio()` and `SplitPaneOutcome::RatioChanged`.

## Exact consumer migration

Update consumers of the public SplitPane surface at these boundaries:

1. Replace endpoint construction (`from_percent(0)`/`100` or basis points
   outside `500..=9500`) with a valid expanded ratio plus
   `SplitPaneState::collapse(SplitSide::First|Second)` when a pane must be
   hidden.
2. Restore collapsed panes with `SplitPaneState::expand`, not by assigning an
   endpoint ratio. A saved ratio is therefore the ratio to restore after
   either side expands.
3. State owners that deserialize `SplitRatio` must accept normalized persisted
   values and persist the normalized value on their next save. Do not add a
   compatibility alias or a second ratio scale.
4. Hosts routing keyboard or pointer input through
   `SplitPaneState::handle_key`, `drag_start`, `drag_move`, and `drag_end` need
   no independent global or minimum clamp. Handle `RatioChanged` as the
   authoritative result; treat an impossible-minimum no-op as unchanged
   state.
5. The in-repository SplitPane integration surface is
   `crates/termrock/src/widgets/split_pane.rs`, re-exported by
   `crates/termrock/src/widgets/mod.rs`; its endpoint assertions live in
   `crates/termrock/tests/split_pane.rs`. The catalog and registry entries in
   `crates/termrock-catalog/src/coverage.rs` and
   `crates/termrock/src/registry/inventory.rs` identify the component but do
   not own ratio state. `ResizablePanelGroup` documentation references the
   same affordance; it must not introduce a second interpretation of
   SplitPane's ratio, feasible-seam, collapse, or fallback rules.

## Visual and layout impact

For feasible, expanded layouts, the one-cell divider remains inside the input
rectangle. Layout allocation floors the stored-ratio-to-cell calculation,
then clamps the first-pane cell to the feasible pane-minimum interval,
matching the canonical `Splitter`'s cell allocation. Pointer dragging clamps
the physical seam to that same feasible interval, then derives the nearest
whole-percent stored ratio as basis points. Keyboard movement derives the
smallest whole-percent ratio that floors to its target cell. A subsequent
layout floors the independently normalized stored ratio before applying the
physical pane-minimum clamp. With extreme minimums, the physical seam can
consequently lie outside 5–95% even though the stored ratio remains bounded.
This is cell-seam quantization, not a second ratio scale.

Keyboard interaction at a saturated endpoint, or a keyboard step whose
resolved first-pane cell does not move, is a physical-cell no-op and returns
`Ignored`; it does not mutate the stored ratio or explicit collapse state.
Pointer interaction whose minimum clamp cannot move the already-painted
first-cell allocation is likewise a physical-seam no-op. The stored-ratio
bound remains independent from the physical-minimum clamp described above.

When minimums are impossible and the split axis is nonzero, the divider is
empty and the full-area pane is direction-specific: horizontal uses the
second pane; vertical uses the first pane. This fallback is deterministic,
remains inside the input rectangle, and does not mutate the expanded ratio.
It does not override explicit collapse. At `usable == 0`, `0/0` minimums
produce three empty rectangles with no divider. At `usable == 0` with a
nonzero minimum, the same direction-specific fallback applies, including
when the split axis has zero length.

Collapsed layouts remain visually one-sided by explicit `SplitSide` state and
return to the previous normalized seam after expansion. `SplitSide` identifies
the hidden pane; canonical `Maximized` identifies the shown pane. Both the
current TermRock collapse path and canonical maximized geometry remove the
handle entirely. No new glyph, color, divider thickness, or direction behavior
is introduced by this boundary.

`crates/termrock/tests/split_pane.rs` has these exact focused totals. The
whole-percent interaction quantization, physical-cell keyboard no-op behavior,
and canonical collapsed geometry are covered by a green focused gate:

- `serde`: **27 tests; 27 passed, 0 failed**;
- `--all-features`: **27 tests; 27 passed, 0 failed**.

All three focused runs are green; no focused failure list applies.

Coverage includes:

- constructor and default normalization at basis points `0`, `499`, `500`,
  `9500`, `9501`, and `u16::MAX`, plus percent values below, at, and above
  the `5–95%` bounds;
- serde deserialization normalization for endpoint and out-of-range values;
- horizontal and vertical layout, pane minimums, tiny rectangles, and
  containment inside the input rectangle;
- zero usable-axis `0/0` geometry with empty panes and no divider, plus
  zero-axis impossible-minimum fallback handling;
- canonical direction-specific impossible-minimum fallbacks: horizontal
  assigns the full area to the second pane, while vertical assigns it to the
  first;
- canonical floor-based ratio-to-cell layout allocation, plus pointer drag
  conversion that stores the nearest whole-percent ratio before the next
  floored layout, including cell-seam quantization;
- focused keyboard movement with axis filtering, independently normalized
  `500`/`9500` stored-ratio endpoint bounds, physical-cell movement, and
  physical-cell no-ops when a step cannot change the resolved seam;
- pointer dragging on both axes at expanded endpoints, plus impossible-
  minimum keyboard and drag interactions that return `Ignored` without
  mutating state;
- the saturated no-op contract: outward endpoint movement, keyboard steps
  whose physical cell cannot move, and pointer drags whose minimum clamp leaves
  the resolved first-cell allocation unchanged return `Ignored` without

- collapse and expansion of both sides while preserving the normalized ratio;
- current collapsed geometry and the canonical maximized
  `handle() == Rect::ZERO` rule for one-sided layouts;
- painted-divider focus, hover, drag, `drag_end` release, same-direction hit
