# 0440: Input lifecycle actions

## Boundary

The SearchInput, NumberInput, and PasswordInput raw keyboard adapters treat
submit, cancel, completion, reveal, and clipboard requests as physical
one-shot actions. A held key must not repeat a host-facing outcome or mutate a
draft, reveal latch, history, or editor state through a fallback path.

## Change

- SearchInput filters non-Press Enter, Tab/BackTab, Escape, Ctrl+M, Ctrl+U,
  and clipboard chords before synchronizing or mutating its TextInput. History
  navigation and ordinary text editing remain repeatable.
- NumberInput filters non-Press Enter, Tab/BackTab, Escape, Ctrl+M, and
  clipboard chords before draft synchronization. Arrow/page steppers and
  ordinary numeric editing remain repeatable.
- PasswordInput filters non-Press explicit Alt+R reveal, Enter,
  Tab/BackTab, Escape, Ctrl+M, and clipboard chords. Hold-policy Alt+H keeps
  its Press/Repeat/Release behavior so reveal lasts for the physical key
  duration.
- Release remains inert for these one-shot actions. Hold-policy `Alt+H` is the
  intentional Release-driven exception that hides the reveal latch. Semantic
  `handle_intent` paths remain phase-free; hosts translating physical events
  must preserve the Press gate.

## Host migration

Hosts routing raw input events must continue passing the complete `KeyEvent`,
including lifecycle kind. Do not synthesize repeated submit, cancel,
completion, explicit reveal, or clipboard outcomes for Repeat or Release
events. Hold-policy `Alt+H` remains the intentional Release-driven exception.
