# 0424: Lockup is the reusable brand widget

## Boundary

TermRock adds the public `termrock::widgets::Lockup` widget as the single
reusable representation of application identity. Hosts must replace hand-built
brand glyphs, product-name strings, and ad hoc accent-filled pills with this
widget. The widget is generic: the host supplies the mark; no product string is
compiled into `Lockup`.

## Public API

Construct the normal or compact form from the supplied mark and design system:

```rust
use ratatui_core::widgets::Widget;
use termrock::{
    style::DesignSystem,
    widgets::{Lockup, LockupParts, LockupState},
};

let system = DesignSystem::default();
let lockup = Lockup::new(mark, &system); // one-cell padding on both sides
let compact = Lockup::new(mark, &system).compact(); // no outer padding
let width = lockup.width();
let parts: LockupParts = lockup.paint(area, &mut buffer);

// Widget::render is a convenience for resting-state painting and returns ().
(&lockup).render(area, &mut buffer);

let state = LockupState {
    hovered: true,
    pressed: false,
};
let hovered: LockupParts = lockup.paint_with_state(area, &mut buffer, state);
let pressed: LockupParts = lockup.paint_with_state(
    area,
    &mut buffer,
    LockupState {
        hovered: true,
        pressed: true,
    },
);

lockup.register_semantic(&mut scene, id, area, true);
```

`new` preserves the mark and renders it as ` mark `; chained `compact` renders
the same mark without the padding. Both forms use the same treatment. `width`
returns the display-cell width of the rendered form. `paint` returns
`LockupParts`, whose `content` is the one-row painted region clipped to the
available area. `Widget::render` paints the resting form as a trait convenience
and returns `()`. Use `paint_with_state` when the host supplies hover or pressed
state. Width calculations follow the terminal display width of the supplied
text, including non-ASCII marks.

## Visual and clickable contract

Every form uses the brand treatment:

- background: `accent`;
- foreground: `text_on_accent`;
- text weight: bold.

The lockup is the only brand control that receives the accent fill. Resting
pixels use `accent`; `paint_with_state` uses `accent_hover` for a hovered state
and `accent_pressed` for a pressed state. Pressed state takes precedence when
both flags are set. `register_semantic(scene, id, area, interactive)` registers
the painted one-row `content` region as `Control` when `interactive` is true,
or as non-focusable `Chrome` when it is false. The host owns the action
associated with the semantic ID; painting the lockup must not invent or embed
product behavior.

## Host migration

Import `Lockup` from `termrock::widgets` and pass the application mark at each
identity surface (application bar, menu, capsule, intro/outro, or compact
state). Do not use `▪ Name`, a plain-text product title, or an alternate brand
glyph as a substitute. Chain `.compact()` on `Lockup::new(mark, &system)` only
where the surrounding strip requires the tighter form; compact changes
padding—and therefore the rendered and semantic content width—but not colors,
weight, or semantic behavior.

There is no compatibility alias for old brand renderers. Migrate callers to
the supplied-mark API so the reusable widget remains product-neutral.
