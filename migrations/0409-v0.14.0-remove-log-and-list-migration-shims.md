# 0409 — v0.14.0 remove LogStream and list-row migration shims

## Breaking change

Remote Core iteration 25 commit `16742cc7` removes the line-less
`LogStreamState` scroll entry points and public list/rail migration shims.
`OpsDashboardState::handle_key` now requires the log slice used by
`LogStreamState`. No compatibility shims remain.

## LogStream and OpsDashboard

These line-less methods are removed:

- `LogStreamState::handle_key_scroll(KeyEvent)`
- `LogStreamState::handle_intent_scroll(UiIntent)`
- `LogStreamState::handle_mouse_scroll(MouseEvent)`

Call the canonical methods with the log lines:

```rust
state.handle_key(key, lines);
state.handle_intent(intent, lines);
state.handle_mouse(event, lines);
```

`OpsDashboardState::handle_key` now takes `logs: &[LogLine<'_>]`:

```rust
state.handle_key(key, visible_rows, columns, logs);
```

The `ops-dashboard` registry fixture's `handle_key` wrapper takes and forwards
the same required log slice.

## Other removed public APIs

- `Sparkline::pre_normalized(bool)` — use `.scale(ScaleMode::Fixed {
  min: 0.0, max: 1.0
})` for a fixed unit domain, or choose the appropriate `ScaleMode`.
- `progress_steps_as_list_rows` and its widget re-export — use the canonical
  `ProgressSteps` timeline APIs or a host-owned projection.
- `patterns::project_task_rail_list_rows` — stop importing the former public
  projection; provide `ActivityModel` values to `TaskRail`.
- `FormWizardState::from_count(n)` — use `FormWizardState::new(n)`.

## Documentation cleanup

`EditAction::move_left`/`move_right` and `RadioState` region documentation no
longer labels canonical APIs as legacy; no consumer migration is required.
