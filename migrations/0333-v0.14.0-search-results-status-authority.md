# 0333 — SearchResults status authority

**Version:** `v0.14.0`
**Kind:** breaking API + behavioral

`SearchResultsState` now has one lifecycle authority. The old `LoadState`
mirror could not represent `Stale` or `Cancelled`, allowing consumers to read
contradictory state.

## Removed surface

```rust
state.load
SearchResultsStatus::to_load_state(projected)
```

There is no compatibility field, alias, or conversion shim.

## Canonical replacement

Read and match `state.status` directly:

```rust
match &state.status {
    SearchResultsStatus::Loading { .. } => show_spinner(),
    SearchResultsStatus::Ready { total } => show_results(*total),
    SearchResultsStatus::Stale { generation } => refresh(*generation),
    SearchResultsStatus::Cancelled => show_cancelled(),
    _ => {}
}
```

`SearchResultsStatus` is the complete lifecycle vocabulary: idle, loading,
partial, ready, empty, error, stale, and cancelled.

## Generation and cancellation

Pass the generation returned by `begin_search` to the async host operation and
then to `apply_results`. Older completions become `Stale` unless the current
state is already `Cancelled`; a completion for the cancelled generation is
ignored and cannot restore results.

## Exact consumer edits

Before:

```rust
if matches!(state.load, LoadState::Loading { .. }) {
    show_spinner();
}
```

After:

```rust
if matches!(state.status, SearchResultsStatus::Loading { .. }) {
    show_spinner();
}
```

Remove `LoadState` imports used only for this mirror and delete any conversion
through `to_load_state`.

## Ownership

The host owns search I/O and generation tokens. TermRock owns the lifecycle
status and rejects completions that no longer belong to the active request.

## Validation

```text
cargo fmt --all -- --check
cargo test -p termrock widgets::search_results
```
