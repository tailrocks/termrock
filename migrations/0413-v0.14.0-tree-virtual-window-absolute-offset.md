# 0413: Tree virtual windows use absolute scroll geometry

## Boundary

`TreeState` paints a resident slice while the host owns the full flattened
tree. Scroll state, cursor-follow behavior, and scrollbar geometry must stay
in the full logical index space across virtual-window updates.

## Change

Tree virtual windows now seed `TreeState::offset` from the effective window
origin, translate resident cursor indices to logical indices, and clamp
scrolling against `virtual_total`. The tree keeps the virtualizer synchronized
after programmatic scrolling and clears the offset when the host returns to a
full projection with a zero total.

Empty resident windows preserve their logical origin while the host is still
in virtual mode. Full projections continue to use resident indices.

## Consumer impact

No consumer change is required. Calls to `scroll_by` and
`scroll_to_position` may continue passing the resident count; TreeState uses
its virtual total whenever virtual metadata is active.
