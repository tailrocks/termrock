# 0381 — v0.14.0 Tree absolute virtual-window geometry

## Boundary

`TreeState` keeps virtual scroll geometry in the host collection's logical
coordinate space. A projected `nodes` slice remains resident-only; its window
origin is supplied through `set_virtual_window(window_start, total_len)`.

## Change

- `TreeState::offset()` is the absolute first visible logical row while a
  virtual window is active.
- Selection-follow translates a resident slice index through the window
  origin.
- Programmatic scrolling, scrollbar mapping, and the scrollbar thumb use the
  virtual total and clamp to its legal range.
- Reasserting the same window preserves user scroll. A changed window seeds
  from its new origin, including an empty window at `total_len`.
- Generic viewport updates preserve the collection's virtual-window identity;
  callers explicitly clear it when switching back to a full projection.
- Tree consumes a contiguous resident body projection. Hosts paint sticky rows
  outside that projection rather than mixing them into its origin mapping.

## Consumer impact

Hosts that already project a tree window continue to pass the same two values.
They must treat `offset()` as a logical index and must not apply the window
origin a second time when selecting or rendering the resident slice. Preserve
the active window across ordinary viewport updates; clear it only when the
host returns to a full projection.

## Rollback

Restore the prior Tree widget revision and revert callers that depend on
absolute virtual offsets. No persisted data is changed.
