# 0357: TreeTable focus chrome requires both authorities

## Boundary

TreeTable scene focus and input permission are separate authorities. A table
that is not the focused widget must not paint active cursor chrome merely
because its state still accepts input.

## Change

TreeTable now requires both `TreeTable::focused(true)` and
`TreeTableState::accepts_input` before painting active cursor/selection chrome.
Semantic keyboard and pointer routing remains governed by
`TreeTableState::accepts_input`.

## Consumer impact

No consumer edit is required. Hosts can keep input permission and scene focus
separate; unfocused tables retain their selection without presenting active
focus chrome.
