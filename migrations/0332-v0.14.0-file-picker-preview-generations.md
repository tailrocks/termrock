# 0332 — FilePicker preview generations

`FilePicker` now gives preview requests their own race-safe generation stream.
Rapid selection changes within one directory and navigation to another
directory can no longer let an older async preview replace the current one.

## Removed surface

```rust
state.apply_preview(preview);
```

The ungated `FilePickerState::apply_preview(FilePreview) -> ()` method is
removed. There is no compatibility overload or alias.

## Canonical replacement

Return the generation from the matching `PreviewRequested` outcome:

```rust
match state.handle_key(key) {
    FilePickerOutcome::PreviewRequested { path, generation } => {
        host.preview(path, generation);
    }
    FilePickerOutcome::ListRequested { path, generation } => {
        host.list_dir(path, generation);
    }
    _ => {}
}

// Async preview completion:
if state.apply_preview(generation, preview) {
    // The preview still belongs to the current selection and directory.
}
```

`apply_preview(generation, preview) -> bool` returns `false` and leaves state
unchanged when the result is stale.

## Generation ownership

- `ListRequested::generation` remains the host's token for
  `apply_listing` / `apply_listing_error`.
- `PreviewRequested::generation` is now an independent token for
  `apply_preview`.
- Every selected-file `PreviewRequested` receives a fresh preview generation.
- Every directory listing request invalidates outstanding preview work before
  issuing its listing generation.
- `preview_generation()` exposes the current preview token for state
  inspection and deterministic synchronous setup.

Do not compare or substitute listing and preview generations. They are
separate request domains even when their numeric values happen to match.

## Exact consumer edits

Before:

```rust
FilePickerOutcome::PreviewRequested { path, generation } => {
    let preview = host.preview(path, generation).await;
    state.apply_preview(preview);
}
```

After:

```rust
FilePickerOutcome::PreviewRequested { path, generation } => {
    let preview = host.preview(path, generation).await;
    let _applied = state.apply_preview(generation, preview);
}
```

Cancellation remains host-owned. Hosts may cancel old tasks eagerly, but the
state generation gate is the final authority when completions race.
