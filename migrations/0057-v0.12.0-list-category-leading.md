# 0057 — Category-leading List redesign

## Removed surface

- Treating `ListRowRecipe` as label/trailing/gutter only without secondary,
  hover, loading, or check glyphs.
- Implicit assumption that pointer click always activates (now policy-driven).
- Hardcoded multi-select markers `"[x] "` / `"[ ] "` outside the glyph catalog.
- Missing empty-list paint path (consumer had to special-case zero rows).

## Canonical replacement

| Concept | API |
|---------|-----|
| Visual state | `ListRowVisualState` + `DesignTokens::resolve_list_row` / `DesignSystem::resolve_list_row` |
| Recipe | Expanded `ListRowRecipe` (secondary, shortcut, hover, tint, check glyphs, loading glyph, focus underline) |
| Fluent rows | `ListRow::item` / `separator` + `.leading` / `.secondary` / `.badge` / `.shortcut` / `.trailing` / `.disabled` / `.loading` |
| Paint root | `List::new(&rows, &tokens)` still valid; prefer `List::from_system(&rows, &design)` |
| Empty | `List::empty_message(Line)` |
| Click policy | `ListClickPolicy::{Activate, Select}` via `ListState::set_click_policy` |
| Glyphs | `GlyphSet::{check_on, check_off, loading, selection_gutter}` |

Selection default remains quiet **gutter** via `DesignSystem::phosphor()` /
`SelectionChrome::Gutter`. Focus-visible uses **underline** on the primary label
when the list owns focus and the row is selected (border weight still never
encodes focus).

## Consumer edits

### Prefer fluent rows

```rust
// Before
ListRow {
    id: "build",
    label: Line::from("Build"),
    leading: None,
    secondary: None,
    badge: None,
    shortcut: None,
    trailing: Some(Line::from("ok")),
    role: RowRole::Item,
    enabled: true,
    loading: false,
}

// After
ListRow::item("build", Line::from("Build")).badge(Line::from("ok"))
// or ListRow::item(...).trailing(Line::from("ok"))
```

Struct literals remain valid but must include every field.

### Design system paint root

```rust
let system = DesignSystem::phosphor();
let list = List::from_system(&rows, &system);
// or List::new(&rows, &system.tokens)
```

### Click selects without activate

```rust
let mut state = ListState::new(Some(id));
state.set_click_policy(ListClickPolicy::Select);
// click → Outcome::Changed; Enter still Outcome::Activated
```

### Empty list

```rust
List::new(&[], &tokens).empty_message(Line::from("No results"))
```

### Multi-select glyphs

Checks paint from `GlyphSet` (`☑`/`☐` or `[x]`/`[ ]`). Hit geometry covers the
glyph width, not a fixed 3-cell ASCII box.

### Recipe resolution

```rust
// Still works
tokens.list_row_recipe(selected, focused, enabled);

// Full part×state
tokens.resolve_list_row(ListRowVisualState {
    selected,
    focused,
    hovered,
    enabled,
    loading,
    checked,
});
```

`ListRowRecipe` gained fields (`secondary`, `shortcut`, `hover`, `check_on`, …).
Update any manual construction of the struct (rare).

## Removed concepts

None of the prior public method names were deleted. Behavior changes:

- Click can emit `Changed` instead of `Activated` under `ListClickPolicy::Select`.
- Multi-select chrome uses catalog glyphs (buffer snapshots that assumed `[x]`
  must accept Unicode checks).

## Ownership

Unchanged: consumer owns row projections, filtering, domain effects. List owns
cursor selection, multi-check membership, scroll, hover, painted hit regions,
and typed [`Outcome`] values only.
