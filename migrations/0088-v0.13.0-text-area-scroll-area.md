# 0088 — TextArea viewport via ScrollAreaState

## Mission

Make multi-line input boxes feel **native** (Grok Build / Amp class): dual-axis
viewport, wheel steps, scrollbar chrome, and caret-follow without a second scroll
truth.

## Preserve / migrate / split / delete

| Surface | Fate |
|---------|------|
| `DialogScroll` in `scroll::` | **Preserve** for dialogs/detail tables |
| `TextAreaState` scroll field | **Migrate** `DialogScroll` → `ScrollAreaState` |
| `scroll().scroll_y` / `scroll_x` public fields | **Delete** — use `offset_y()` / `offset_x()` |
| Manual scrollbar paint in TextArea | **Migrate** → `ScrollArea::render_bars` |

## Consumer edits

```rust
// was:
let y = state.scroll().scroll_y;
// now:
let y = state.scroll().offset_y();
let x = state.scroll().offset_x();

// optional host tuning
state.scroll_mut().wheel_steps(3, 4);
state.scroll_mut().chain(ScrollChain::Capture); // default for modal composers
```

PromptComposer selection paint already updated to `offset_y` / `offset_x`.

## Laws

1. One scroll engine for inputs: `ScrollAreaState`.
2. Caret reveal uses quiet offsets (does not fight follow policies).
3. Wheel capture stays on the editor body while `accepts_input`.
4. Paint bars only through DesignSystem scroll roles.

## Validation

```bash
cargo test -p termrock --all-features --lib widgets::text_area
cargo test -p termrock --all-features --lib widgets::prompt_composer
```
