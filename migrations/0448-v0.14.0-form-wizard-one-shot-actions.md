# 0448: FormWizard physical one-shot actions

## Boundary

`FormWizardState::handle_key` is the raw physical adapter for a staged
workflow. Its keyboard actions advance, retreat, skip, retry, save, submit,
or cancel wizard state and must not repeat while a key is held.

## Change

- Non-Press events are ignored before FormWizard lifecycle and phase routing.
- Repeat Enter, Escape, navigation, skip, retry, and save-progress keys no
  longer advance, cancel, submit, or mutate wizard state.
- Semantic `handle_intent` remains the phase-free path; mouse actions remain
  press-only through their existing mouse-kind gate.

## Host migration

Hosts routing raw `FormWizardState` events must continue passing complete
`KeyEvent` values, including lifecycle kind. Do not synthesize repeated wizard
actions from Repeat or Release events. Use `handle_intent` for semantic
commands that are not raw physical keyboard events.
