# 0323 — One modal geometry

**Version:** `v0.14.0`
**Kind:** additive API + behavioral fix

## What changed

Modal placement has one authority:

```rust
use termrock::layout::{ModalSpec, modal_rect};

let area = modal_rect(outer, ModalSpec::new(3, 4, 16).height(1, 3, 6));
```

`ModalSpec` states a *share* of the terminal (`width_num`/`width_den`), the
size the modal would rather not lose (`min_width`, `min_height`), and the
cells left to the terminal (`margin`). `modal_rect` resolves it, centered
horizontally and biased into the upper third — a dialog pinned to the exact
middle covers the row the operator was reading.

## Why it is here

Three patterns hand-rolled the same arithmetic, and two of them were still
wrong:

| Pattern | Before |
|---|---|
| `patterns/agent_workbench.rs` | private `centered_modal(area, w_num, w_den, h_min, w_min)` (fixed in 0322) |
| `patterns/database_workbench.rs` | private `centered_modal(area)`, **panicked** below 26 columns |
| `patterns/git_workbench.rs` | private `centered_modal(area)`, **panicked** below 30 columns |

Each computed `width.clamp(min, area.width - 2)`, and `u16::clamp` panics when
the minimum exceeds the maximum. Migration 0322 fixed the copy the showcase
happened to open; the other two were the same defect waiting for a narrower
terminal. Copies of geometry are how one fix leaves two bugs.

Two further defects fall out of the single implementation:

- **Minimums yield.** A terminal narrower than the modal's minimum is a real
  size, and the modal now contracts into it. The order — raise to the minimum,
  *then* cap by the room — is what makes the cap win instead of asserting an
  impossible range.
- **No overflow.** `area.width * 3 / 5` overflows `u16` above 21 845 columns.
  The share is computed in `u32`.

## Consumer edits

Anything reading the three public workbench helpers is unchanged:

```rust
// Still exactly this, and now panic-free at every size.
let area = termrock::patterns::permission_modal_rect(frame.area());
```

New code that needs its own modal geometry should take the authority rather
than write the arithmetic:

```rust
// Before — the shape that panicked
let width = (area.width * 3 / 5).clamp(24, area.width.saturating_sub(2).max(1));

// After
let rect = modal_rect(area, ModalSpec::new(3, 5, 24).height(1, 2, 8));
```

## The gate

`design_gate.rs` grew the two tests that would have caught this:

- `modal_geometry_never_escapes_its_terminal` walks every public modal helper
  and four `ModalSpec`s across `0..=64 × 0..=24`, asserting the rectangle stays
  inside its area.
- `workbench_overlays_survive_tiny_and_random_geometry` renders a composed
  `render_agent_workbench` frame **with an overlay open** at the documented
  tiny sizes plus 75 seeded random ones.

The existing `flagship_widgets_survive_tiny_and_random_geometry` fuzzes
widgets only and never opens an overlay, which is precisely why three patterns
could carry a panicking modal for as long as they did.
