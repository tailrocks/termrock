# 0317 — Every state paints, and Space works

The state-coverage audit found pressed painting nowhere, hover hard-coded to
`false` in nine collection widgets, row actions always-on, sortable columns
that never said so, and a Space key that could arm a button forever without
ever activating it.

## Behavior changes

**Space activates on ordinary terminals.** `ActivationState` armed on
Space-press and fired on Space-release. Most terminals never report releases,
so on them Space armed the control and nothing else — forever. Activation now
knows which terminal it is on:

```rust
use termrock::input::KeyReleaseReporting;

// Hosts that negotiate the Kitty keyboard protocol:
state.activation.set_release_reporting(KeyReleaseReporting::Reported);

// crossterm hosts can ask:
let reporting = termrock::crossterm::key_release_reporting();
```

The default is `PressOnly`, where Space fires on press. Where releases *are*
reported, the press-arm/release-fire discipline is unchanged.

**Hover reaches the widgets that tracked it and threw it away.** `Select`,
`MultiSelect`, `FilePicker`, `DropdownMenu`, `MenuBar`, `CommandPalette`,
`QuickOpen`, `HistoryPicker` and `DataTable` now assign hover unconditionally
from their own hit regions on `MouseEventKind::Moved` — so a pointer leaving
the list clears it — and pass it to the row recipe. Each emits a
`HoverChanged` outcome (`DataTableOutcome`, `SelectOutcome`,
`MultiSelectOutcome`, `FilePickerOutcome`, `DropdownMenuOutcome`) so a host can
repaint; treating it as a no-op is correct.

**A filled button answers the pointer.** `ControlState::Hovered` on a variant
that already owns its ground (Primary, Success) lifts that ground one step
rather than washing a background that isn't there — hover used to be
pixel-identical to idle. `Pressed` gained its own selection-tint ground instead
of being "hover, but bold".

**Row actions are revealed, not resident** (law P6). `ListRowVisualState`
gains `revealed()`, and `ListRowRecipe` gains `show_actions`: a list row shows
its actions when it is selected, focused or hovered, and otherwise keeps a
faint ellipsis marker so the affordance stays discoverable.

**Sortable columns say so.** A sortable-but-unsorted `Table` header carries a
faint `⇅` (`^v` under ASCII); the direction arrow replaces it once sorted.

**`DataTable` sortability is real.** `sortable: col.sortable || true` forced
every column to advertise sorting and to emit `SortRequested` for columns the
host never marked sortable. It is `col.sortable` now.

**States that existed only in the model now paint.** A read-only `TextArea`
was pixel-identical to an editable one — it reads muted with no caret now, and
read-only stays distinct from disabled. A disabled `InputOtp` row reads
`TextDisabled`. A focused `Collapsible` section trigger takes an accent gutter
and weight instead of resolving to the same `TextStrong` it already had (the
three Accordion recipes inherit the fix). A roving-but-uncommitted tab
brightens its leading edge rather than reversing its label, so the cue no
longer needs a second strip row. A chip's status and its selection compose:
an errored chip that is selected keeps both facts.

**Toasts can be dismissed.** `ToastQueue::handle_key` takes `esc` and drops the
newest toast; `dismiss_top` is the direct call, and `set_focus_paused` is the
documented hook for a host wiring terminal `FocusGained`/`FocusLost` so a
notification does not expire while the window is in the background. The 4s TTL
was already there.

## New surface

- `termrock::input::KeyReleaseReporting`
- `termrock::crossterm::key_release_reporting()`
- `ActivationState::{set_release_reporting, release_reporting}`
- `ListRowVisualState::revealed()`, `ListRowRecipe::show_actions`
- `DataTableState::hovered_row`
- `termrock::style::palette::lift(Color)`
- `ToastQueue::{handle_key, dismiss_top, set_focus_paused}`
- `InputOtpState::is_enabled`

## Breaking changes

- `ListRowRecipe` gained `show_actions`; struct-literal construction must add
  it (builders and `resolve_list_row` are unaffected).
- Five outcome enums gained a `HoverChanged` variant — exhaustive matches over
  them need an arm.
- A `DataTable` host that relied on every column being sortable must mark its
  columns `sortable`.
- Snapshots: hovered primary buttons, pressed buttons, idle list rows with
  actions (now a faint `…`), sortable headers.

## Gate

`design_gate.rs::state_matrix_distinct` renders Button idle / hovered /
pressed / disabled, resolves the row recipe for idle / hovered / selected /
disabled, and resolves every `ControlState` for a button, asserting each pair
differs. A state that stops painting fails it.
