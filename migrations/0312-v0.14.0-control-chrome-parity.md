# 0312 — Control chrome parity

Plan 008 gave the text-input family one field-chrome authority. This closes
its remaining half: the controls that are *not* text fields but were resolving
their own chrome anyway.

## Behavior changes

**`Slider` and `RangeSlider` agree, and neither floods its track.** Each
resolved its own track, fill and thumb styles, and both painted the filled
portion of the track in `Role::Accent` when focused — a focused slider was a
bar of brand green with the thumb lost inside it. One `slider_chrome` answers
for both: the track is `Border`, the fill is `ChartSeries1` because a filled
range is data, and the accent is spent on the one cell the operator is moving.

**`Stepper`'s current step stops wearing a slab.** It painted `Role::Focus`
with `BOLD | REVERSED`, which reads as a selection someone made rather than as
where they are. The step is stated by its glyph and its weight.

**`InputOtp` slots sit in the field well.** Each slot painted bare over the
canvas; they now carry the same `Role::Sunken` ground as every other field, so
an OTP row reads as somewhere to type instead of three loose brackets. The
focused slot keeps its reversed cell.

**`PasswordInput` shows strength as a meter.** The strength row was always
`TextMuted` copy — "fair" told you the level only if you read it. It paints a
four-cell block-ramp meter toned by level (`Danger`, `Warning`, `Success`)
followed by the word, and the reveal toggle takes its glyph from the catalog
instead of hardcoding `o` / `*`.

## New surface

```rust
use termrock::widgets::PasswordStrengthHint;

assert_eq!(PasswordStrengthHint::Strong.meter(false), "▂▄▆█");
assert_eq!(PasswordStrengthHint::Weak.meter(true), "[#---]");
let _ = PasswordStrengthHint::Fair.role(); // Role::Warning
```

## Gate

`design_gate.rs::inputs_share_field_chrome` renders `TextInput`,
`NumberInput`, `SearchInput`, `PasswordInput` and `TokenField` focused and
asserts every one paints the shared well and the shared focus cue. Six widgets
delegating to one substrate should not be able to drift apart again without a
red test.

## Consumer edits

- Snapshots of a focused slider: the track fill is a series color, not the
  accent; the thumb is the accent cell.
- Snapshots of a stepper's current step: no reversed slab.
- Snapshots of an OTP row or a password strength line: new ground and a meter.

## Validation

```sh
cargo nextest run -p termrock --all-features --test design_gate inputs_share_field_chrome
cargo nextest run -p termrock --all-features slider stepper input_otp password
mise run check
```
