# 0334 — SegmentedControl selection authority

**Version:** `v0.14.0`
**Kind:** breaking API + behavioral

`SegmentedControlState` now owns selection through its mutator. Direct writes
could change the selected value without moving the active cursor, leaving
keyboard navigation and the painted selection out of sync.

## Removed surface

```rust
state.selected = Some(id);
```

The `selected` field is private. There is no public alias or compatibility
field.

## Canonical replacement

Read with `selected()` and update with `set_selected`:

```rust
let selected = state.selected().cloned();
state.set_selected(Some(id));
```

Clearing selection also clears the active cursor:

```rust
state.set_selected(None);
```

Keyboard, pointer, and overflow-menu commits use this same path.

## Exact consumer edits

Before:

```rust
state.selected = Some("grid");
```

After:

```rust
state.set_selected(Some("grid"));
```

Replace reads of `state.selected` with `state.selected()`. Keep `cursor` as
the active descendant only; do not use it as a second selection authority.

## Ownership

The host owns the domain value and may control it through `set_selected`.
SegmentedControl owns synchronization between selected value and active cursor.
