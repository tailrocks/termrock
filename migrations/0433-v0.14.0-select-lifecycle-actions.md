# 0433: Select lifecycle actions

## Boundary

`SelectState::handle_key` treats select open, close, and commit triggers as
physical key-press actions. A held key must not repeatedly open a closed
select, close an open select, or commit its highlight.

## Change

- `Press` Enter and Space open a closed select; Repeat and Release are ignored.
- `Press` typeahead opens a closed select and either seeds the searchable query
  or forwards to non-searchable collection typeahead; Repeat and Release are
  ignored at the closed-select boundary.
- `Press` Escape closes an open select, and Enter commits its highlight;
  Repeat and Release are ignored. For non-searchable selects, Press Space
  commits the highlight and Repeat/Release are ignored; searchable Space
  remains repeatable query text.
- Non-Press Ctrl+M is ignored before searchable text-input submission can
  close the select.
- Open-select arrow/j/k navigation and searchable text editing retain their
  repeatable behavior.

## Host migration

Hosts routing raw Select events must continue passing the complete `KeyEvent`,
including its lifecycle kind. Do not synthesize repeated open, close, or commit
outcomes for Repeat or Release events; the state adapter consumes them as
no-ops.
