# 0316 — One token family, one focus vocabulary

Tag and Chip were near-identical paint bodies; keycaps had two renderings that
disagreed on weight and ground; the active-tab cue was an unnamed interim; each
family improvised its focus cue; and the radio ladder's preview rung existed in
the model but was never painted.

## New surface

```rust
use termrock::style::{FocusEmphasis, SurfaceFamily};
use termrock::widgets::{BracketStyle, TabsActiveCue, keycap_text};

// What "the keyboard is here" looks like, per family.
let system = DesignSystem::default()
    .with_focus_emphasis(SurfaceFamily::Cell, FocusEmphasis::Reversed);
assert_eq!(system.focus_emphasis(SurfaceFamily::Row), FocusEmphasis::FocusTint);

// How a tab strip marks its active tab.
Tabs::new(&tabs, &system).active_cue(TabsActiveCue::Connected);
```

- `FocusEmphasis { BrightBorder, SelectionFill, FocusTint, Reversed, BoldKey,
  PillGlyph }` with per-family defaults through `SurfaceFamily`. This names
  what plans 005-008 implemented so a theme can state the vocabulary instead of
  each widget improvising one.
- `BracketStyle { Angle, Square }` — the token family's shape ladder.
- `TabsActiveCue { AccentPill (default), Connected, Marker, Rule }`.
- `keycap_text(chord)` — the single keycap composer.

## Behavior changes

**Tags are angled, chips are squared.** `Tag` painted `[label ×]`, the same
bracket a chip used, so the two read as one control with different contents.
A tag is `⟨label ×⟩` now (`<label x>` under ASCII); a chip keeps `[● label ×]`.
Both go through one paint body, so bracket faintness, remove affordance and
focus cue cannot drift again.

**A focused token brightens its bracket**, not its whole label (audit D18) —
the selection pip stays free to state membership.

**Keycaps agree.** `ShortcutHint`'s keycap form used a plain `HintKey` label
with no weight and no raised ground; it delegates to `Kbd` now, so every keycap
in the library has the same ground and weight.

**Tabs.** The interim active cue is named `AccentPill` and is the default.
`Connected` puts the active tab on the body's ground, `Marker` uses a chevron
plus weight for colourless terminals, and `Rule` draws the opt-in accent rule.
`docs/design/termrock-design-language.md` §5.2 carries the errata.

**Radio groups paint the middle rung.** `○ → ◎ → ●`: the option under a roving
cursor previews with `◎` (`(-)` under ASCII) instead of looking identical to a
committed choice.

**Comfortable lists breathe.** Under `Density::Comfortable`, a group header
opens with one blank canvas row so sections read as sections. Compact and
Dashboard densities are unchanged.

## Consumer edits

- Snapshots containing a `Tag`: brackets are `⟨ ⟩`.
- Snapshots of a `ShortcutHint` keycap: bold label on a raised ground.
- Snapshots of a Comfortable list with group headers: one extra blank row
  before each header after the first.
- A host that asserted a radio cursor row equals the selected row must now
  distinguish `◎` from `●`.

## Gates

- `design_gate.rs::one_chip_recipe` — no second bracket-composing paint body in
  `tag_chip.rs` or `kbd.rs`.
- `design_gate.rs::bold_budget_per_row` — a row recipe never returns bold
  secondary, trailing or shortcut styles, at any density or state.
