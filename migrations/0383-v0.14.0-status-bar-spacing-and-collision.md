# 0383 — StatusBar spacing and collision-safe contraction

## Boundary

`StatusBar` uses plane spacing for persistent items and groups. It paints a
one-cell outer edge and three blank cells between retained items or groups;
structural `·` and `│` separators are not part of the geometry. A transient
sentence owns the right edge of the free span and never paints through a
persistent right slot. This is a visual and layout change. The public slot,
state, semantic, hit-region, and `mode_fade` APIs remain available.

## Canonical evidence

- `migrations/0110-v0.13.0-status-bar.md` requires priority contraction while
  retaining one strongest persistent survivor.
- `migrations/0298-v0.14.0-status-in-the-glyph.md` keeps slot words neutral on
  `Role::StatusBar`; semantic tone belongs to the glyph or rail.
- `docs/design/component-anatomy-spec.md` requires left, center, and right
  groups, priority dropping, and a single highest-priority item at tiny sizes.

## Exact geometry and behavior

- Fill the requested row with the elevated status-bar plane.
- Use one plane cell at each outer edge whenever the persistent budget can
  represent both edges. Retained items and groups have three blank plane cells
  between them. These cells never contain separator glyphs.
- Allocate left items left-to-right, right items right-to-left, and center
  items centered in the remaining span. Spacing is budgeted before priority
  admission, so it cannot consume a retained item's content width.
- Drop the lowest-priority item first; equal priorities drop center, then
  right, then left. Preserve the globally strongest or essential persistent
  item in left-only, center-only, and right-only layouts, truncating it with
  the shared grapheme-safe `…` when necessary.
- Build a transient label from its optional glyph, one space, and its text.
  Place it at `collision_right - width - 1`, where `collision_right` is the
  nearest retained right slot or the row's right edge. Omit it when the free
  span cannot hold it. It remains non-interactive.
- Keep slot labels neutral over the elevated plane. Typed semantic status tone
  is painted on the glyph cell only. A custom glyph is clipped to one display
  cell so wide graphemes cannot overwrite neighboring content.

## Compatibility impact

Frames and tests that expect zero outer padding, separator glyphs, old narrow
survivors, colored semantic labels, or transient overlap must be updated. The
public `StatusBar`, `StatusSlot`, `StatusBarState`, semantic, and hit-region
interfaces remain source-compatible; callers must not add manual separators or
padding.

## Validation

Focused tests cover same-side and cross-group spacing, left/center/right narrow
priority survivors, one-cell boundaries, grapheme-safe truncation, transient
collision placement, elevated hover fill, neutral labels with semantic glyph
tone, and wide custom glyph clipping. Run:

```sh
cargo test -p termrock status_bar --all-features --locked --offline
cargo fmt --all -- --check
cargo clippy -p termrock --all-targets --all-features --locked --offline -- -D warnings
git diff --check
```
