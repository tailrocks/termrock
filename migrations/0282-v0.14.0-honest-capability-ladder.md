# 0282 — Honest capability ladder: quantizer, projections, glyph de-collision

TermRock's degraded-terminal projections told the truth about the palette and
lied about everything else. This boundary makes the ladder honest: ANSI-16 keeps
hue, 256-color keeps elevation, monochrome keeps structure, projections downgrade
the chrome color can no longer carry, and the glyph catalog stops giving one
character to six meanings.

Nothing changes on a truecolor terminal with the Unicode glyph set except the
glyph reassignments listed below.

## What changed

### 1. ANSI-16 quantization matches hue, not RGB distance

`quantize_color(_, ColorCapability::Ansi16)` previously required "the other
channels are dark" before naming a primary, so every mixed hue fell through to
`Color::White`: phosphor accent `(0,255,65)`, danger `(255,94,122)`, warning
`(255,216,94)`, and success `(61,220,90)` all painted white. Color stopped
carrying meaning on exactly the terminals where it was the last cue standing.

The mapping now selects a hue sector from the chroma-normalized channels, then
picks the bright or dim half by peak channel:

| Source | Before | After |
|--------|--------|-------|
| `(0,255,65)` accent | `White` | `LightGreen` |
| `(255,94,122)` danger | `White` | `LightRed` |
| `(255,216,94)` warning | `White` | `LightYellow` |
| `(0,180,180)` info | `Cyan` | `Cyan` |
| `(61,220,90)` success | `White` | `LightGreen` |
| `(80,80,80)` border | `Gray` | `DarkGray` |

Two thresholds are deliberate and worth knowing when authoring a theme:

- Channel spread ≤ 24 is treated as neutral and takes the gray ladder
  (`Black` / `DarkGray` / `Gray` / `White` by level).
- A peak channel below 64 also takes the gray ladder regardless of hue: ANSI
  `Green` is `(0,205,0)`, so painting a `(20,51,26)` selection tint with it would
  turn a whisper into a shout.

`Color::Indexed` inputs now round-trip through RGB, so an indexed source lands on
the same ANSI-16 name its truecolor equivalent would.

> Not a nearest-neighbor search. Plan 003 specified luminance-weighted nearest
> RGB; that metric answers `DarkGray` for danger `(255,94,122)` (a pastel sits
> closer to mid-gray than to its own primary in RGB space) and fails the plan's
> own acceptance table. Hue-sector matching is what keeps meaning.

### 2. 256-color keeps the elevation ladder

`rgb_to_xterm256` only used the 232-255 gray ramp for *exactly* equal channels.
The phosphor surfaces are a near-neutral green wash, so `Canvas` `(10,12,10)`
through `Elevated` `(30,38,32)` all floored to cube index 16 (pure black) and
every panel, dialog, and well rendered on one flat plane.

Colors whose channel spread is ≤ 12 now take the gray ramp with nearest-step
rounding:

| Role | Before | After |
|------|--------|-------|
| `Canvas` | 16 | 232 |
| `Sunken` | 16 | 233 |
| `Surface` | 16 | 233 |
| `Raised` | 16 | 234 |
| `Elevated` | 16 | 235 |

Exact grays round to the nearest ramp step instead of flooring, so mid grays
shift by at most one step.

> **Known ceiling:** the ramp steps by 10 while the phosphor ladder steps by ~5,
> so `Sunken` and `Surface` share index 233 — a sunken well is invisible at 256
> colors. There is no dark neutral between 8 and 18 in the xterm palette, so this
> cannot be fixed in the quantizer; widening the ladder in the palette is the
> only lever. Recorded as a follow-up against plan 002.

### 3. Monochrome substitutes REVERSED for fills

Monochrome maps every color to `Color::Reset`, which used to delete filled
styles outright: selection, focused actions, and filled badges vanished into the
canvas. A style that *had* a background now gains `Modifier::REVERSED`.

```rust
let mono = RolePalette::tailrocks_phosphor().quantized(ColorCapability::Monochrome);
assert!(mono.style(Role::Selection).add_modifier.contains(Modifier::REVERSED));
assert!(!mono.style(Role::Text).add_modifier.contains(Modifier::REVERSED));
```

Consumers that add their own `REVERSED` on top of a quantized selection style
now double-invert back to normal. Drop the manual modifier.

### 4. Projections downgrade chrome, not just color

`CapabilityBoundary::project_system` and
`CapabilityPreviewHost::projected_tokens` used to replace the palette and leave
everything else, so a projected-to-monochrome system still claimed
`SelectionChrome::Fill` and the Unicode glyph set. Both now:

- record the projected `capability` on the returned `DesignSystem`;
- force `GlyphSet::Ascii` under `ColorCapability::Monochrome`;
- force `SelectionChrome::Gutter` when the capability is monochrome or the glyph
  set is ASCII.

This mirrors `DesignSystem::no_color()`. If your host projected a system and then
set `selection`/`glyphs` itself, apply those overrides *after* the projection.

### 5. Glyph catalog: one glyph, one concept

ASCII `>` previously meant selection, disclosure, chevron, arrow, folder, play,
and prompt at once; `◉` meant busy, connection, token, and active status at once.
Encodings changed:

| Glyph | Before (unicode / ascii / enhanced) | After |
|-------|-------------------------------------|-------|
| `SelectionGutter` | `▌` / `>` / `▌` | `▌` / `*` / `▌` |
| `Bullet` | `•` / `*` / `•` | `•` / `-` / `•` |
| `SelectionMark` | `▣` / `#` / `▣` | `▮` / `#` / `▮` |
| `Info` | `i` / `i` / `ℹ` | `·` / `i` / `ℹ` |
| `Busy` | `◉` / `o` / `◉` | `◐` / `o` / `◐` |
| `Connection` | `◉` / `o` / `◉` | `◍` / `=` / `◍` |
| `Token` | `◉` / `#` / `◉` | `◧` / `%` / `◧` |
| `StatusDotHollow` | `○` / `o` / `○` | `○` / `.` / `○` |
| `Loading` | `…` / `...` / `…` | `◔` / `:` / `◔` |
| `File` | `·` / `.` / `📄` | `▫` / `.` / `📄` |
| `Folder` | `▸` / `>` / `📁` | `▪` / `/` / `📁` |
| `FolderOpen` | `▾` / `v` / `📂` | `▨` / `\` / `📂` |
| `FocusDiamond` | `◇` / `+` / `◇` | `◊` / `>` / `◊` |
| `DisabledMark` | `⊘` / `x` / `⊘` | `⊘` / `~` / `⊘` |

`Glyph::Loading`'s ASCII width drops from 3 columns to 1 — layouts that reserved
three cells for it now have two spare.

`◇` is free for the new `Glyph::NowEdge` (timeline live edge / checkpoint), and
`▸`/`▾` mean disclosure only.

New catalog entries:

- `Glyph::NowEdge` — live edge / checkpoint marker.
- `Glyph::Mask` — one masked-character glyph (`●`, ASCII `*`) replacing the
  three-way `*` / `●` / `•` split across `TextInput`, `PasswordInput`, `InputOtp`.
- `Glyph::SliderThumb` / `SliderFill` / `SliderRail` / `SliderTick`.
- `Glyph::DividerVertical` / `DividerVerticalActive` / `DividerVerticalHint` and
  the three horizontal counterparts.
- `LEFT_BLOCK_RAMP` (`▏▎▍▌▋▊▉`) for sub-cell meters and bar tops.
- `SHADE_RAMP` (`░▒▓`) for colorless hatching and soft fills.

`GLYPH_CONTEXTS` publishes the surfaces whose glyphs must stay distinguishable
(collection row, status strip, slider track); a test asserts no two members of a
context share an encoding in any `GlyphSet`. Mutually exclusive states of one
element (a divider that is idle *or* focused) are exempt by construction.

Widget paint sites still holding local literals (`slider.rs`, `split_pane.rs`,
`resizable_panel_group.rs`, `charts.rs`, `multi_select.rs`, `menu_bar.rs`, the
input masks) are rewired by the widget-facing plans; this boundary only makes the
catalog able to serve them.

## Ownership and rollback

Quantization and the glyph catalog remain TermRock's; hosts still choose the
capability and glyph set. Rollback is source-only — restore the previous revision;
no persisted state is involved.
