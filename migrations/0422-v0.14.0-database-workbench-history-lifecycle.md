# 0422: DatabaseWorkbench preserves the HistoryPicker lifecycle

## Boundary

`DatabaseWorkbench` treats history as a composed `HistoryPickerState` child.
The host owns the outer overlay flag and focus gates; the picker owns its query,
draft stash, cursor, and cancellation outcome. Opening, cancelling, selecting,
and reopening must keep those two lifecycles synchronized.

## Change

When opening history, the host captures the current query draft and opens the
child through `HistoryPickerState::open(Some(query_draft))`. Setting only the
host's `history_open` flag is insufficient: the child must be opened for its
query and input state to be initialized, and the draft must be available for
cancel restoration.

While the overlay is open, route the raw key event to
`HistoryPickerState::handle_key`. Do not maintain a second host-level Escape
handler. The outer host rejects non-Press events with `Ignored` before overlay
routing, so Repeat and Release events cannot mutate the picker or dismiss the
overlay.

A Press Escape is handled by the picker as `Cancelled`: it closes the child,
then the host clears `history_open`, restores the stashed draft from
`HistoryPickerState::take_draft()`, and reapplies its focus gates. A selected
history entry closes the picker and replaces the query editor text with the
entry value; the cancelled draft is not restored on selection.

Every open action must call `HistoryPickerState::open` again. Reopening starts
the picker with a fresh empty query and active input state while stashing the
current query draft, rather than reusing stale picker query/state from the
previous overlay session.

## Consumer impact

Hosts must synchronize their outer open flag with the child outcome. Handle
`Cancelled` by restoring `take_draft()`, handle `Selected` by applying its
value to the query, and keep non-Press outer host events inert. Consumers that
previously dismissed history directly on raw Escape or reopened by toggling
only a host flag must migrate to the child lifecycle above.
