# 0032 — Fail-safe ApprovalCard interaction

## Removed surface

- `ApprovalCardState::selected: usize` is no longer public.
- `ApprovalCardState::handle_key` no longer returns
  `Option<ApprovalDecision>`.
- Escape no longer aliases cancellation to `ApprovalDecision::Deny`.
- `ApprovalCardState::new()` no longer selects `AllowOnce`.

No deprecated alias or compatibility facade remains.

## Canonical replacement

`ApprovalCardState` now stores a semantic `ApprovalDecision`, defaults to
`ApprovalDecision::Deny`, and exposes:

- `selected()` and `set_selected(...)`
- `with_selected(...)` for an explicit initial decision
- `handle_key(...) -> ApprovalCardOutcome`
- `handle_mouse(...) -> ApprovalCardOutcome`
- `decision_regions` containing the latest painted semantic hit geometry

`ApprovalCardOutcome` separates selection movement, confirmation, cancellation,
and ignored input. Press and Repeat may navigate. Confirmation remains
Press-only so held Enter cannot emit repeated approvals.

## Exact consumer edits

Before:

```rust
let mut state = ApprovalCardState::new();
state.selected = 3;

if let Some(decision) = state.handle_key(key) {
    apply_permission(decision);
}
```

After:

```rust
let mut state = ApprovalCardState::with_selected(ApprovalDecision::Deny);

match state.handle_key(key) {
    ApprovalCardOutcome::Confirmed(decision) => apply_permission(decision),
    ApprovalCardOutcome::Cancelled => close_without_decision(),
    ApprovalCardOutcome::SelectionChanged => request_redraw(),
    ApprovalCardOutcome::Ignored => {}
}
```

Forward mouse events after rendering when pointer interaction is enabled:

```rust
match state.handle_mouse(mouse) {
    ApprovalCardOutcome::Confirmed(decision) => apply_permission(decision),
    ApprovalCardOutcome::SelectionChanged => request_redraw(),
    ApprovalCardOutcome::Cancelled | ApprovalCardOutcome::Ignored => {}
}
```

Replace numeric selection checks with semantic identity:

```rust
if state.selected() == ApprovalDecision::Deny {
    // render or announce the safe selection
}
```

## Removed concepts

- Numeric decision identity at the public boundary
- Implicit approval caused by untouched Enter
- Cancellation represented as a denial decision
- Keyboard-only interaction geometry

## Ownership changes

TermRock owns safe selection defaults, navigation, confirmation de-bouncing,
responsive decision chrome, and painted hit regions. Consumers still own all
permission policy, persistence, executor effects, wording, and the meaning of
closing without a decision. `ApprovalCardOutcome` is a message only and never
executes policy.
