# 0338 — Bounded runner event draining

**Version:** `v0.14.0`  
**Kind:** behavioral

The synchronous runner still drains immediately ready backend events in FIFO
order, but it now applies at most 64 events before advancing to the next frame
cycle. A continuously ready input producer can no longer prevent a new
`FrameTick`, redraw, animation wakeup, or model deadline from being observed.

Events left in the backend queue are handled by the following frame cycle. All
events in one bounded batch continue to share the frame tick sampled before the
batch, and `ControlFlow::Break` still exits immediately.
