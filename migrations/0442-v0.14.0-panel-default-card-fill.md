# 0442 — v0.14.0 Panel default card fill

## Boundary

`Panel`'s default borderless presentation is a card, not a transparent hole in
the caller's buffer. The canonical panel fills its allocation with the
ordinary `surface` plane, then places title and body content inside the
design-system card inset. TermRock defaults `Panel::new` to
`PanelVariant::Quiet` with `raised = false`, but its old paint path treated
that ordinary state as `SurfaceFill::Transparent` and left the allocation
untouched.

`raised(false)` is not a transparency opt-out. The corrected paint boundary
selects `SurfaceFill::Transparent` only for `PanelVariant::DividerOnly` when
`raised == false`; ordinary Quiet panels remain filled.

This migration makes the default panel a filled card while retaining explicit
surface and frame variants. No source compatibility layer is introduced.

## Canonical evidence

The reference implementation at
`/Users/donbeave/terminal-components-claude/src/widgets/panel.rs` defines the
card as the default panel form. `Panel::card` resolves its background to
`Theme::surface`, intersects the requested area with the buffer, and fills the
whole card rectangle before painting the title row and `2×1` inner inset.
`Panel::framed` is the explicit alternative: it fills with `Theme::canvas`,
then paints a rounded border and frame inset.

The reference `DESIGN.md` Panel section describes the card as a “filled
surface” and the default container. Its token contract maps `card` to
`colors.surface` and `spacing.card-inset`; the canonical palette is
`surface: #111111`, with `card-inset: 2`.

TermRock already carries the matching lower-level contract:

- `SurfaceRecipe::Inset` resolves to `Role::Surface` and the card inset.
- `SurfaceFill::Auto` keeps that recipe-owned fill.
- `SurfaceFill::Transparent` explicitly means “never paint background.”
- `Card::panel()` already opts into the filled card path with `.raised(true)`;
  its focused test asserts the `Role::Surface` background and no outer border.

## Root cause

The `Panel` paint path treated `raised` as both a visual opt-in and the fill
gate. In the borderless branch, `Panel::paint` selected `Auto` only when
`self.raised` was true and selected `Transparent` otherwise. That made the
default `Quiet` variant semantically mean “do not fill,” even though `Quiet`
only owns border/chrome policy and the selected `Inset` recipe already
describes the ordinary card plane.

The enabling condition was the paint-time transparent override applied to every
non-raised borderless panel. It is not a missing palette token, a layout
problem, or a caller omission. Fix the default/explicit fill contract at the
Panel boundary; do not add per-call background stamping in hosts.

## Exact default and explicit fill behavior

| Construction | Fill contract | Chrome contract |
| --- | --- | --- |
| `Panel::new(&system)` | Filled borderless card; `SurfaceFill::Auto` through `SurfaceRecipe::Inset`, resolving to `Role::Surface`; preserve the `2×1` card inset. | Quiet/card title, body, footer, and focus semantics unchanged. |
| `Panel::quiet(&system)` | Same filled card default. “Quiet” means no box border, not transparent. | No full border; existing quiet header/footer behavior remains. |
| `.raised(true)` | Explicit filled card path; keep the existing `Role::Surface` card plane and do not create a nested box. | Existing card/focus behavior remains. |
| `.raised(false)` | Does not disable the ordinary fill for `Quiet`, `Bordered`, `Interactive`, or `Selected`; those variants remain recipe-driven. | `raised` controls the card/elevation recipe, not a general transparency mode. |
| `PanelVariant::DividerOnly` with `raised == false` | Explicit transparent divider region; use `SurfaceFill::Transparent` and leave existing buffer backgrounds untouched. | Existing divider-only chrome remains. Setting `.raised(true)` opts that variant back into a filled surface. |
| `PanelVariant::Bordered`, `Interactive`, or `Selected` | Keep each variant's existing recipe-owned fill and border behavior. | No variant is silently converted into a second card. |
| `.overlay(true)` or a framed/bordered panel | Keep overlay/elevated and canvas/frame ownership as currently defined. | Overlay/frame boundaries remain explicit. |

The fill covers the clipped outer allocation, including cells behind empty
title/body space. Content geometry remains owned by `Panel::layout`; the
change does not add padding, alter hit regions, or move semantic regions.
Card geometry always keeps the canonical `2×1` inset; tiny rectangles use
saturating dimensions and may therefore return an empty body rather than
silently falling back to a full-area body.
Monochrome and reduced-color projections continue to follow the
`SurfaceFill::Auto` capability policy rather than relying on hue alone.

## Validation

Add or update focused Panel/Card tests to prove the contract:

- default `Panel::new` and `Panel::quiet` stamp every cell in the clipped
  borderless allocation with the `Role::Surface` background and retain the
  card inset;
- `.raised(true)` remains filled and borderless; ordinary `.raised(false)` does
  not suppress the default fill, while `DividerOnly` with `raised == false`
  leaves a sentinel background unchanged;
- titles, footer/body rectangles, focus gutter, semantic regions, and
  `PanelVariant::Bordered`/overlay behavior do not change;
- partially clipped and empty allocations remain safe; the fill never writes
  outside the buffer;
- `Card::new` keeps its existing filled-surface/no-box behavior.

## Visual breaking impact

Every caller that paints a default or quiet `Panel` over a non-empty buffer
will now see the panel's surface plane in cells that were previously
transparent. Background content behind empty body/title space is intentionally
covered. Screens and goldens may change in panel regions, especially stacked
panels, in-app panels, narrow panels, and composited backgrounds.

Callers that intentionally compose a transparent divider over an existing
background must select the explicit `PanelVariant::DividerOnly` behavior with
`raised == false`. Callers that want the canonical card need no new padding,
fill call, or constructor; the default does that work.

The existing `.raised(true)` paint behavior remains in this slice: its
borderless card path still resolves to the current `Inset`/`Role::Surface`
underlay. Changing `Role::Elevated` semantics or the public `elevation()`
contract is a separate migration, not an implicit consequence of the default
fill fix.

## Compatibility policy

There is no compatibility shim, legacy-default flag, alias constructor,
caller-side fill helper, or dual rendering path. `Quiet` is not retained as a
second transparent default, and `.raised(false)` is not a hidden legacy mode.
Consumers must update visual expectations and use the explicit existing
`DividerOnly` transparency only when that composition is genuinely intended.
A temporary rollback, if required for an older golden baseline, is a
source-revision rollback.
