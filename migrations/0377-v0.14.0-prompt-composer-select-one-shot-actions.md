# 0377 — v0.14.0 PromptComposer and Select host actions are one-shot

## Boundary

Raw host actions are accepted once per physical press. With
`submit_on_enter` enabled, a held bare Enter in `PromptComposerState` submits
on its press and does not add a newline on repeat. When that policy is disabled,
bare Enter remains text editing and repeated Enter can insert newlines. When a
composer chip owns focus, bare Enter activates it and bare Escape clears chip
focus before generic composer intents. Modified Enter remains the composer
newline chord even when a chip has focus.

`SelectState` Enter activation and Escape dismissal are Press-only. Space
activation is also Press-only for non-searchable Select lists; a searchable
Select routes Space through its search field. Repeat and Release do not perform
the listed host actions. Text insertion, search input, and list navigation
remain repeatable.

## Host migration

No public API changed. Hosts may continue routing raw key events through the
same methods. Treat ignored Repeat and Release events as inert input. Hosts
that call `handle_intent` or activation methods directly continue to control
their invocation frequency explicitly.
