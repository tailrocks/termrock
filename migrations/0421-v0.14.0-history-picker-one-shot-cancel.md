# 0421: HistoryPicker Escape cancellation is one-shot

## Boundary

`HistoryPickerState::handle_key` treats Escape as a one-shot raw-key action.
Cancellation is decided before picker reconciliation or text-input processing,
so held or released Escape cannot mutate or close a live picker.

## Change

For a live picker, `KeyCode::Esc` has this contract:

- `Press` closes the picker and returns `HistoryPickerOutcome::Cancelled`.
- `Repeat` and `Release` return `HistoryPickerOutcome::Ignored` before
  reconciliation or `TextInputState` handling. The picker stays open and its
  draft remains unchanged.

This gate applies only to Escape cancellation. Down, Up, PageUp, PageDown,
Ctrl+Home, Ctrl+End, and supported Ctrl+J/K navigation remain repeatable picker
navigation. Do not replace
the Escape gate with global press-only admission.

## Host migration

Hosts handling raw picker events must treat `Ignored` as a no-op and must not
assume that every Escape phase cancels. Route raw Escape through
`HistoryPickerState::handle_key`, or gate cancellation on
`KeyEvent::is_press()` before invoking host-side dismissal logic.

Direct `HistoryPickerState::handle_intent(UiIntent::Cancel | UiIntent::Close,
...)` calls are deliberately phase-free. They bypass raw event phase
information, so direct callers must enforce the one-shot event policy
themselves. Preserve the picker draft and open state when handling ignored
Repeat or Release events.
