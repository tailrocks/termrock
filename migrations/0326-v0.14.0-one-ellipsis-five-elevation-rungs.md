# 0326 — One ellipsis and five visible elevation rungs

**Version:** `v0.14.0`
**Kind:** breaking (duplicate text helpers removed) + behavioral

Final verification of plans 003 and 020 found two remaining parallel paths.

## Ellipsis comes from the glyph catalog

Removed:

```rust
termrock::widgets::ascii_ellipsis()
termrock::widgets::BREADCRUMBS_ELLIPSIS
termrock::widgets::BREADCRUMBS_ELLIPSIS_ASCII
```

Use the active design system instead:

```rust
let ellipsis = system.glyphs.ellipsis();
```

For an explicit low-capability preview, project the system first:

```rust
let ascii = system.ascii();
let ellipsis = ascii.glyphs.ellipsis();
```

The removed helpers encoded a second Unicode/ASCII choice beside
`GlyphSet`. That allowed breadcrumbs, text truncation, tabs, and other
surfaces to disagree after a capability projection.

## Indexed-256 elevation preserves hierarchy

`RolePalette::quantized(ColorCapability::Indexed256)` now resolves the five
surface roles as one ordered ladder:

```text
Canvas < Sunken < Surface < Raised < Elevated
```

Nearest-colour rounding remains the first pass. When adjacent neutral roles
collide on the xterm gray ramp, the higher role advances one ramp step. This
closes the documented plan-003 deviation where `Sunken` and `Surface` both
became index 233, erasing input troughs on 256-colour terminals.

Custom palettes should not depend on two semantic elevation roles collapsing
to one indexed colour. The role order is now the contract.

## Long dropdown menus keep the cursor visible

`DropdownMenu` now projects its existing `CollectionState` into the painted
viewport. Moving beyond the last visible row scrolls the menu, paints the
shared continuation edges and scrollbar, and exposes hit regions only for
rows that were painted. No consumer edit is required.

Previously the cursor could move below the panel while paint remained on the
first rows. The model accepted input but gave no visible response.

## Picker titles state count and filter

`FilePicker` and `HistoryPicker` now use `PanelTitleSpec` for their count and
active filter. `FilePickerState::filter_text()` exposes the host-owned filter
for inspection. Existing setters and outcomes are unchanged.

This removes the last picker-specific plain-title path; overlays now use the
same title grammar as lists, workbenches, and dashboards.

## Streaming Markdown exposes its paint projection

`StreamingMarkdown::with_blocks` lets hosts inspect the exact block projection
used by paint without returning values that borrow temporary parser buffers.
`StreamingMarkdown::measure_height` measures that same projection directly.

Use these APIs instead of reparsing streamed text in a host layout pass. Open
fences remain marked incomplete, and their row map now has a test proving it
matches measured height at narrow and wide widths.

## File review actions follow file-tree focus

When `DiffReviewState` is focused on its file tree with no multi-selection,
approve/reject now targets the focused file as `DiffReviewUnitKind::File`.
Previously the fallback always targeted the current hunk, so an operator could
approve a hunk in another pane while looking at a file row. Existing typed
`ApproveRequested` and `RejectRequested` outcomes remain canonical; no
parallel file-only outcome was added.
