# 0417: Text-area Escape cancel is one-shot

## Boundary

`default_text_area_intent` separates one-shot cancellation from repeatable
text-area navigation. A held Escape key must not dispatch repeated
`UiIntent::Cancel` values to a host that may dismiss or change modes.

## Change

For an otherwise accepted Escape event, `Press` maps to
`Some(UiIntent::Cancel)`. `Repeat` and `Release` map to `None`.

This gate applies only to the cancel action. Home, End, PageUp, PageDown, and
unmodified Left/Right continue to map on both `Press` and `Repeat`, preserving
held-key navigation. Releases remain unmapped.

The same boundary is enforced in the raw handlers for `TextAreaState` and
`PromptComposerState`: their Escape-only completion, fullscreen, selection,
edit-finish, and dismiss branches accept only the event phase and modifier
policy above. A raw Repeat, Release, Control+Escape, or Alt+Escape cannot peel
one of those surfaces.

## Host migration

Hosts that dispatch the result of `default_text_area_intent` must treat
`None` for repeated or released Escape as ignored input. Remove any host-side
assumption that every Escape phase produces `UiIntent::Cancel`; if a host also
handles raw Escape events, gate its dismiss or mode transition on
`KeyEvent::is_press()` and the surface's supported modifier policy.

Do not change the adapter's initial `is_insert()` admission to a global
press-only gate: doing so would disable repeatable navigation. Direct callers
of `TextAreaState::handle_intent(UiIntent::Cancel)` remain unchanged and own
their invocation frequency explicitly.
