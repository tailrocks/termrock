# 0431: Picker one-shot actions

## Boundary

`PickerState::handle_key` treats picker activation, cancellation, scope
handoff, secondary actions, and query clearing as physical key-press actions.
A held key must not activate or cancel a picker repeatedly, change host scope,
emit a secondary action, or clear the query after the initial press.

## Change

For the Picker keyboard adapter:

- `Press` Escape, Enter, Alt+Enter, Tab, and Delete perform their existing
  actions; Repeat and Release are ignored.
- `Press` Ctrl+U clears a searchable query; Repeat and Release are ignored.
- Query editing, arrow/page navigation, and Ctrl+n/p/j/k list navigation retain
  their repeatable behavior.

## Host migration

Hosts routing raw Picker events must continue passing the complete `KeyEvent`,
including its lifecycle kind. Do not synthesize a second activation,
cancellation, scope handoff, secondary action, or query clear for Repeat or
Release events; the state adapter consumes those events as no-ops.
