# 0397: Tree loading status removes interaction eligibility

## Boundary

`TreeNode::with_status(TreeNodeStatus::Loading)` can leave `enabled` set to
`true`, even though loading rows must not accept tree interaction.

## Change

`TreeNode::is_interactive()` now centralizes tree eligibility as
`enabled && !status.skips_navigation()`. Tree navigation, activation,
selection/check handling, pointer hit regions, focus/hover visual state, and
composed-row output use that predicate. A loading node is therefore skipped
even when a host applies its status after construction.

## Consumer impact

No consumer change is required. Hosts may continue to use
`with_status(TreeNodeStatus::Loading)`; the row remains visible with loading
status chrome but is not navigable, activatable, selectable, or hittable until
its status becomes interactive.
