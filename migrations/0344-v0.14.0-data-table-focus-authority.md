# 0344: DataTable focus chrome requires both authorities

## Boundary

`DataTable` separates scene focus from permission to receive keyboard and
pointer input. Rendering must not infer one authority from the other.

## Change

Active row and cell focus chrome now paints only when both
`DataTable::focused(true)` and `DataTableState::accepts_input` are true.
Input handling remains governed by `accepts_input`; scene focus remains host
owned by the widget builder.

## Consumer impact

Consumers that want active focus chrome must pass both authorities. Consumers
that intentionally render a focused-looking but input-disabled surface must
choose that presentation outside the DataTable focus contract.
