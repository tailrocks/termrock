# 0337 — Toast pause freezes timed presence

**Version:** `v0.14.0`
**Kind:** breaking API + behavioral

Pausing a `ToastQueue` now freezes each live toast's timed presence. Resuming
shifts the `Presence` phase origin by the exact paused duration, so a toast
cannot expire while terminal focus is lost and does not lose TTL on focus
return.

## Breaking API

The pause timestamp is supplied by the host frame that changes focus:

```rust
queue.set_focus_paused(tick, true);
queue.set_focus_paused(tick, false);
```

`ToastQueue::set_paused` and `ToastState::set_paused` likewise take
`FrameTick` before the pause flag. Update hosts to pass the current tick; there
is no compatibility overload.

## Presence contract

`Presence` owns the pause clock. Pending show delays, visible TTLs, and exit
transitions all stop while paused; resuming moves their phase origins forward.
`next_deadline` returns `None` during the pause and resumes with the shifted
deadline. Persistent and hidden presences remain unchanged.
