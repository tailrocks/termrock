# 0371 — v0.14.0 DatabaseWorkbench preserves HistoryPicker state

## Boundary

`DatabaseWorkbench` composes `HistoryPickerState` with its own overlay flag and
focus gates. Opening, cancelling, selecting, and reopening history now keep
the host and child lifecycles synchronized.

## Change

- Every history-open action opens the picker with the current query draft.
- While history is open, key events route through the picker.
- A Press Escape closes the picker and restores the saved query draft.
- A selected history item replaces the query and discards the saved draft.
- Repeat and release events are inert at the workbench input boundary.

## Host migration

No host API changed. Hosts using this pattern should restore
`HistoryPickerState::take_draft()` on `Cancelled`, apply the selected value on
`Selected`, and keep the host open flag synchronized with picker state.
