# 0279 — Visual cascade completion

Plan 010 completes the v0.13 visual-richness cascade and makes its paint
authorities executable policy.

## Consumer changes

- `Callout`, `ImageSurface`, `FullscreenViewer`, and `PreviewCard` now obtain
  border geometry from `Surface`. Theme `BorderShape` and ASCII glyph policy
  therefore apply consistently; remove consumer overrides that compensated for
  their former hand-drawn square borders.
- Prompt queue, paste-chip, submit-history, and citation previews now interpret
  width limits as terminal display columns. Wide Unicode is truncated through
  `text::truncate_cols` without splitting glyphs or exceeding its cell budget.

## Series summary and opt-outs

| Surface | v0.13 default | Explicit opt-out |
|---|---|---|
| Canvas/panels | Obsidian surface ladder and density padding | `DesignSystem::terminal_native()` or explicit density |
| Borders | Theme-owned square single lines | `BorderShape::Rounded`; ASCII capability maps both to `+` |
| Selection | gutter + deep tint + strong text | choose another `SelectionChrome` explicitly |
| Controls | semantic button/input recipes | supply documented style override points |
| Overlays | backdrop + elevated fill | host placement remains caller-owned |
| Motion | deterministic status motion | `Motion::Reduced` |
| Agent blocks | semantic actor rails | select neutral actor roles |
| Data/forms | shared row and FieldRow recipes | project composed values through public row parts |

## New invariant

Repository policy tests reject widget production sources that erase recipe
backgrounds with `bg = None` or embed box-corner literals instead of using
`Surface`. Lookbook tests render representative Surface, List, and Button
stories across every built-in preset, truecolor, 256-color, ANSI16,
monochrome/ASCII, and explicit no-color projections.

`ansi_text` still clears parsed foreground/background under `NO_COLOR`; that
is capability sanitation, not widget paint, and remains required.
