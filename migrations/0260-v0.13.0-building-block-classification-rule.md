# 0260 — Building-block vs example-composite agent rule and standard

## Mission

Make the widgets/patterns package boundary a **permanent agent rule** and
in-repo design standard—not only a one-time rehome. Agents must classify every
new UI surface before implementing it.

## Surfaces

| Artifact | Role |
|----------|------|
| `Agents.md` / `AGENTS.md` | Mandatory *Building block vs example composite* section |
| `docs/design/building-block-vs-example-composite.md` | Classification SoT + checklist |
| `docs/scripts/check-building-block-boundary.ts` | Structural gate (forbidden widgets exports, inverted deps, catalog path) |
| `widgets/mod.rs` module docs | Points agents at the standard |

## Placement law (unchanged homes)

- **Building blocks** → `termrock::widgets`
- **Example composites** → `termrock::patterns` only
- **Dependency** → patterns may use widgets; widgets must not use patterns

## Consumer impact

No type renames beyond 0257–0259. Documentation and agent checklist only, plus
the boundary check script.

## Validation

```bash
rtk bun run docs/scripts/check-building-block-boundary.ts
rtk cargo test -p termrock --lib patterns::connection_manager
rtk cargo check -p termrock
```
