## Usage

```rust
use termrock::widgets::{
    example_plan_document, PlanReview, PlanReviewOutcome, PlanReviewState,
};

let mut state = PlanReviewState::new();
state.open(example_plan_document());
PlanReview::new(&system).paint(area, buf, &mut state);

match state.handle_key(key) {
    PlanReviewOutcome::Approved => {}
    PlanReviewOutcome::RevisionRequested { feedback } => { let _ = feedback; }
    PlanReviewOutcome::Cancelled => {}
    _ => {}
}
```

## Try it

- `Enter open action` or `click trigger` opens a real ChoiceDialog.
- `S toggle sidebar region` changes visible chrome.
- `↑↓/wheel select row` changes persistent selection.
- `/ filter` focuses a real TextInput; type or paste, then apply with Enter.

Accepted actions update the same mounted Rust value. The status line shows the latest outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted Rust demo owns deterministic sample state. The component/pattern owns its reusable paint and interaction contracts; the consuming host owns domain policy and every external effect.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Migrated handbook guidance

# PlanReview

Interactive review for agent-generated plans. Host owns execution policy;
outcomes are **requests only**. Approve is never the initial focus.
The plan-gold rail and title establish document identity; task fields and
decision chips reuse the shared composition vocabulary.

## Domain

- `PlanDocument` — body, sections, tasks, risks, assumptions, files, refs, risk, previous
- `PlanComment` + `PlanCommentAnchor` — line/range/section/task/file/orphan

## Actions (safe focus)

Abandon · Revise · Feedback · Approve… · Approve

Default: `RequestRevision` (low/medium) or `Abandon` (high/critical). Enter
confirms focus only. Bare `a` moves focus — does not grant.
