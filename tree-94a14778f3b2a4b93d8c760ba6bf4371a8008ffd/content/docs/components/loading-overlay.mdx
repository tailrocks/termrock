## Usage

```rust
use termrock::style::{DesignSystem, Motion};
use termrock::runtime::FrameTick;
use termrock::widgets::{BusyBoundary, BusyBoundaryState, BusyMode, BusyRoute};

let system = DesignSystem::default();
let mut busy = BusyBoundaryState::new();
let _ = busy.begin(BusyMode::Cancellable, "Syncing workspace");
busy.set_unavailable(Some("Edits paused until sync finishes"));
busy.set_expected_ms(Some(2_000));

// paint content, then:
BusyBoundary::paint(pane, buf, &mut busy, &system, tick, Motion::Full);

match busy.route_key(key) {
    BusyRoute::Cancel => { /* abort */ }
    BusyRoute::Blocked => {}
    BusyRoute::Deliver => { /* normal */ }
    BusyRoute::Outside => {}
}
```

## State and typed outcomes

The widget owns deterministic paint and layout. The host owns all surrounding state and effects; this demo intentionally exposes no fake cursor, click, or keyboard behavior.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
