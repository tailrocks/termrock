# 0267 — Tree tone tiers and pinned horizontal scroll

`TreeNode` now carries the product-neutral `ToneTier` semantic projection and
`TreeState` owns horizontal label scrolling. Disclosure, indentation, and
selection/check chrome remain pinned while long labels scroll by display
columns. Existing hover wash continues through the shared list-row recipe.

## Required consumer edit

External `TreeNode` struct literals must add the new field. Constructors already
default it to `Primary`.

```rust
// Before
TreeNode {
    status: TreeNodeStatus::Ready,
    parent: None,
    // remaining fields
}

// After
TreeNode {
    status: TreeNodeStatus::Ready,
    tone: ToneTier::Primary,
    parent: None,
    // remaining fields
}
```

Prefer constructors and semantic builders for new code:

```rust
let node = TreeNode::new(id, Line::from(label), depth)
    .tone(ToneTier::Live);
state.set_h_offset(8);
state.scroll_horizontal(2);
```

No compatibility field or parallel renderer remains. `Tree` is the canonical
single-column data hierarchy; `TreeNavigation` remains route-oriented and
`TreeTable` remains multi-column.

Validate with `cargo nextest run -p termrock --test tree`, `mise run check`,
and `mise run gate`.
