## Usage

The Code view above and this source excerpt use the exact paint setup registered for `drawer/sheet`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn drawer_sheet_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let mut state = termrock::widgets::DrawerState::sheet();
    state.open();
    state.set_header_rows(1);
    termrock::widgets::Sheet::new("Sheet", system)
        .footer(Some("drag handle"))
        .paint(area, frame.buffer_mut(), &mut state);
    let body = state.body_area();
    if !body.is_empty() {
        frame.buffer_mut().set_stringn(
            body.x,
            body.y,
            "bottom sheet content",
            usize::from(body.width),
            system.style(termrock::style::Role::TextMuted),
        );
    }
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
