# 0302 — Overlay affordances restored, and the neon-fill gate goes live

Three overlays computed an affordance and threw it away — the code that built
it was there, the paint was not. One design gate that had been waiting on the
004–007 sweeps is now active.

## Behavior changes

- **`FilePicker` has a footer again.** It built its hint line and dropped it
  with a `let _ = hint;` and a comment about avoiding overwrite. The footer row
  is now reserved before the body claims the space, so the hints have somewhere
  to go: `N selected · enter open · space multi · esc close`. The list and
  preview lose one row when the picker is taller than two rows.
- **`AlertDialog` says what to type.** A type-to-confirm dialog painted the
  typed text and a check mark but never the required phrase, so the operator
  had to guess it. The prompt row reads `type <phrase> to confirm` above the
  input.
- **`Combobox` escalates a suggestion-source error into field validation.**
  The escalation was computed and discarded with `let _ = validation;` because
  the borrowed message would not outlive the field paint; the message is owned
  locally now and reaches the field. Its open/closed chevron is painted in the
  right-hand cell when the status glyph has not taken it.

## Gate

`design_gate.rs::no_widget_paints_selection_fill_by_default` is no longer
`#[ignore]`d. It renders a list with a selected row and asserts no cell carries
the `Role::Selection` fill — selection fill is chrome a host opts into, never
what a collection does by default. It passes against the 004–007 row grammar.

The whole gate file now runs with nothing skipped.

## Consumer edits

- A host that laid out around `FilePicker`'s full body height gets one fewer
  body row when the picker is taller than two rows.
- Snapshots of an `AlertDialog` type-to-confirm body gain a prompt row.
