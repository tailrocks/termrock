# 0258 — Widgets/patterns boundary fixes (queue model + ops/resource state)

## Mission

Close residual leaks after 0257:

1. **PromptComposer** must not depend on `patterns`. Neutral queue identity types
   live in `widgets::prompt_queue_model` (`PromptQueueItem`, `PromptQueueRef`,
   `PromptQueueStatus`, `AgentBusyState`, alias `QueuedPrompt`). The
   `patterns::PromptQueue` management recipe re-exports the model and owns the
   full UI state. Projection: `patterns::project_prompt_queue_from_items`.
2. **OpsDashboardState / ResourceBrowserState** (and outcomes) move from
   `widgets::blocks` to `patterns` (`ops_dashboard`, `resource_browser`).
   `widgets::BlockChrome` remains a tiny generic chrome marker.

## Consumer edits

```rust
// Queue item model (composer + host FIFO)
use termrock::widgets::{PromptQueueItem, PromptQueueRef, PromptQueueStatus, QueuedPrompt};
// Management recipe
use termrock::patterns::{PromptQueue, PromptQueueState, project_prompt_queue_from_items};

// Ops / resource browser state machines
use termrock::patterns::{OpsDashboardState, OpsRegion, ResourceBrowserState};
use termrock::widgets::BlockChrome; // still widgets
```
