## The five directions (and TermRock translation)

### 1. Browser operating system — Displace, gucduck, Cyan Banister

Pages become applications; navigation becomes window management; projects
become files. Works only when the OS metaphor has *internal logic* (case
studies → Viewer, articles → Notes, images → Photos, settings control
theme/sound/motion). Common failure: draggable windows with no meaningful
responsibility.

**TermRock translation:** this is the overlay/window + semantic-scene kernel.
TermRock's focus authority + overlay family already provide the "windows with
responsibilities" primitive. The lesson: every overlay/panel must carry a
**semantic role** (viewer / inspector / dialog / palette), never a generic
floating box. Maps to `Role::BorderFocused` single-owner rule — one window owns
interaction at a time, exactly like the OS metaphor.

### 2. Command-native — ZUI_OS, Vlad Burca, Sat Naing

CLI is primary navigation: `help`, `about`, `open project-name`,
`theme light`. Modern form requires autocomplete, command suggestions, history,
**clickable output**, keyboard shortcuts, visible `help`. Vlad Burca's
autocomplete + visual project output solve discoverability.

**TermRock translation:** command palette + `KeyboardHelp` + intent routing.
The key insight is **clickable output** and **typed-as-enhancement-not-
requirement** — every command has a non-typed path. TermRock intents already
model this (an intent is reachable by key *and* mouse *and* palette). The
command-native direction validates making `KeyboardHelp` a first-class widget,
not an afterthought.

### 3. ASCII as living graphical material — Aino, Artefakt, RCK, Dragonfly Redux

> "The most promising direction for a site that should feel **modern rather
> than nostalgic**."

ASCII responds to pointer velocity, scroll, live video, audio, image luminance,
particle sims, loading states, network data. The site does not pretend to be an
old terminal — terminal primitives become a contemporary rendering medium.

**TermRock translation:** this is **the phosphor identity's strongest defense.**
TermRock's glyph ladder (`○→◎→●`, shape-before-color), MotionChannel
(Work/Wait/Stream/Live), and block-glyph catalog (`▏▎▍▌▋▊▉`, `░▒▓`) are exactly
"ASCII as rendering medium." The audit's F3 (`MotionChannel` + `shimmer_cells`)
and F5 (glyph catalog gaps) findings are not polish — they are this direction's
prerequisite. A TermRock UI that animates glyph density, breathes, or shimmers
on stream is executing direction 3. This is where TermRock looks *modern*, not
retro.

### 4. Industrial control room — Terminal Industries, Studio Dialect

Telemetry, coordinates, timestamps, progress indicators, maps, technical
diagrams, operational language, monospaced metadata, dense-but-structured
dashboards. "Best for a serious developer tool, infrastructure platform, AI
system, logistics company, or technical framework. Operational without forcing
visitors to type commands."

**TermRock translation:** **this is TermRock's native home.** Status bars,
`DataTable`, `Panel`, telemetry rows, progress/gauge — direction 4 maps 1:1 to
TermRock's panel + status + table primitives. The "control-room aesthetic that
works for enterprise without becoming retro or playful" is precisely the
non-cyberpunk credibility TermRock targets. Reinforces that TermRock must
nail: dense readable tables, status semantics, restrained motion (Work/Wait
only, no decoration).

### 5. Optional terminal layer — Viacheslav Novoseltsev, Trey Hollinger

Polished conventional UI first; a shortcut (`T`) flips to terminal/ASCII/raw/
debug/low-bandwidth mode. Strongest originality-vs-usability balance. The
terminal becomes a *discovered capability*, not an unavoidable gimmick.

**TermRock translation:** **density ladder + contraction + accessibility.**
TermRock's capability/quantize ladder and density modes (Comfortable → Compact
→ Dense) are the TUI form of this. A user runs Comfortable by default and
"discovers" Dense/debug mode. Low-bandwidth mode (Trey Hollinger) maps to
TermRock's contraction path (narrow-terminal, colorless cues). The lesson: the
high-information-density path must be *optional*, with a clean low-density
default — never force density on the user.

## What the best examples share

### The terminal affects behavior, not just visuals

> "Projects become files. Pages become processes. Categories become
> directories. Navigation becomes commands. Loading becomes a boot sequence.
> Errors become meaningful system states."

**TermRock translation:** loading/empty/error are **first-class semantic
states**, not afterthoughts. This directly validates the audit's F8/F9
(`DangerChrome`, `LoadingMode`) and the law's 7 message states. A TermRock
widget that cannot render a meaningful empty/loading/error state is incomplete
— because in direction-4/5 thinking, those states *are* the product.

### They avoid the green-on-black cliché

Contemporary palettes cited: warm cream + charcoal, orange + black, red +
graphite, pastel lavender + blue, stark black + white, neutral editorial.

**TermRock translation — the phosphor question, settled again.** This is the
second independent source (after `terminal-aesthetics-landscape-2026-08.md` §S2)
flagging green-on-black as a cliché. TermRock's response is unchanged and now
double-confirmed:

- **Phosphor stays the default** (loved, ships with Tailrocks) — but as *one
  deliberate, distinctive theme*, never the only one.
- **Full re-themability is mandatory** (already CLAUDE.md law).
- **Ship ecosystem + editorial palettes as first-class**: Catppuccin, Tokyo
  Night, Gruvbox (from landscape doc) **plus** the editorial ones this source
  surfaces — warm cream/charcoal, orange/black, red/graphite, neutral. A
  consumer picking Lumena's "expensive, contemporary, not-cyberpunk" look must
  get a coherent TermRock Role mapping without hand-rolling it.
- The accent-budget rule (≤2 bright accents/viewport) is *why* phosphor can
  stay single-hue without becoming the cliché — restraint is the difference
  between "distinctive" and "hacker skin."

### They mix monospace with expressive typography

Mono for commands/metadata/telemetry; modern grotesk for nav/body; distinctive
display face for large statements; oversized numbers/symbols as composition.

**TermRock translation — the TUI typography problem.** A TUI cannot freely mix
font families. But the *hierarchy* the rule wants is achievable through what a
terminal *can* vary:

- **Glyph weight/brightness** for hierarchy where web uses font-weight (bright
  phosphor for "display," dim for "body metadata").
- **Block-glyph density** (`█▓▒░`) for visual weight contrast.
- **Unicode width discipline** (full-width CJK / box-drawing) for compositional
  oversized elements.
- **Reserved accent glyphs** (the few bright cells) as the "display face"
  equivalent — spend the accent budget on hierarchy, not decoration.

This is a real design principle TermRock should make explicit: **typographic
hierarchy in TUI is encoded in brightness, glyph-weight, and accent spend, not
font family.** Worth recording in the design-language SoT.

### They provide escape routes

Skip-boot, visible suggested commands, autocomplete, clickable output,
conventional nav alongside, `⌘K` palette, normal+console mode, simplified
mobile.

**TermRock translation:** the capability/density ladder must always offer a
*lower*-complexity rung. No TermRock UI should lock a user into its densest
mode. Contraction (narrow terminal), colorless cues (accessibility), and a
discoverable lower-density default are the escape routes. This is also an
accessibility requirement, not just a UX preference.

## The composite "Operator Environment" vision

The source proposes combining Displace (structure) + Aino (experimentation) +
Terminal Industries (maturity) + Terminal.shop (authenticity) into an
"Operator Environment" rather than a retro terminal: modern editorial layout +
reactive ASCII field + status bar (version/status/location/time) + `⌘K`
embedded terminal where typing is enhancement + project-as-filebrowser + near-
black/warm-white/one-accent palette + scanline/glitch reserved for transitions.

**TermRock relevance:** TermRock is the *component layer* that would build such
an environment. The composite validates TermRock's whole primitive set —
status bar, panel, command palette, filebrowser/list, ASCII motion, single-
accent theming, density toggle — as the correct inventory. No exotic primitive
is needed; the "wow" comes from executing the existing set at this quality bar.

## Cross-surface implications (per contributor rules)

1. **Typographic-hierarchy principle** (brightness/glyph-weight/accent-spend,
   not font family) should be added to the design-language SoT — it is missing
   and this is the second source demanding it.
2. **Editorial palette set** (cream/charcoal, orange/black, red/graphite,
   neutral) joins the ecosystem palette set (Catppuccin/Tokyo Night/Gruvbox)
   as required first-class themes. Both sources now agree phosphor cannot
   stand alone.
3. **Empty/loading/error as first-class semantic states** — re-flag any widget
   in the audit missing these as a P0, since two sources treat them as core
   product, not polish.
4. **Density ladder must offer a low-complexity default rung** — accessibility
   + this source's "escape routes" both require it.

## Limitations

- The landscape is ChatGPT-sourced, not independently re-verified against each
  live site. Award recognition (Awwwards/CSSDA/FWA) is taken on the source's
  attribution. The *design principles* extracted are the valuable, portable
  part; individual project claims are secondary.
- No live site was visually inspected in this pass (vision tool could not reach
  them reliably; prior tweet screenshots also failed). Principles are taken
  from the source's stated descriptions.

## Open questions

1. Does TermRock commit to a **neutral/editorial first-class theme** (Lumena/
   cream-charcoal style) alongside phosphor + ecosystem palettes? Two sources
   now say terminal aesthetics must survive without green-on-black.
2. Should the design-language SoT add an explicit **TUI typographic-hierarchy**
   section (brightness / glyph-weight / accent-spend / block-density)? This
   source and basic terminal physics both demand it; it appears absent.
3. Is a **command-palette widget** (`⌘K`-style, fuzzy, every-action-reachable)
   a first-class building block TermRock should ship? Direction 2 + 5 both
   treat it as load-bearing for discoverability.
