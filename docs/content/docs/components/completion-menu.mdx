## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

## Try it

- `↑↓ select`: Move through the real focus/selection model; the next action uses the new target.
- `Enter/Tab commit`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `Esc dismiss`: Open the transient state first, then cancel it; focus and the underlying state are preserved.
- `click candidate`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted widget owns interaction state, focus chrome, hit geometry, and typed outcomes. The host only forwards backend-neutral events and performs no external effects.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `completion-menu/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn completion_menu_basic(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let panel_tokens = system.clone().density(Density::default());
    frame.render_widget(Panel::new(&panel_tokens).title("Editor"), area);
    let candidates = [
        CompletionCandidate::new("select", "SELECT")
            .kind("keyword")
            .kind_glyph("⌘")
            .group("Keywords")
            .documentation("Select rows from a relation."),
        CompletionCandidate::new("from", "FROM")
            .kind("keyword")
            .group("Keywords"),
        CompletionCandidate::new("users", "users")
            .kind("table")
            .detail("public")
            .group("Tables"),
        CompletionCandidate::new("orders", "orders")
            .kind("table")
            .group("Tables"),
        CompletionCandidate::new("where", "WHERE")
            .kind("keyword")
            .group("Keywords"),
    ];
    let anchor = Rect::new(area.x.saturating_add(4), area.y.saturating_add(2), 1, 1);
    let mut state = CompletionMenuState::new(Some("select"));
    state.set_show_docs(true);
    frame.render_stateful_widget(
        &CompletionMenu::new(&candidates, system, area, anchor).preferred_size(
            CompletionMenuSize {
                width: 48,
                height: 8,
            },
        ),
        area,
        &mut state,
    );
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
