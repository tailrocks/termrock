## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

## Try it

- `↑↓ select`: Move through the real focus/selection model; the next action uses the new target.
- `←→ collapse/expand`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `Enter activate`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `/ filter`: Focus the editable field, then type or paste Unicode text; the draft remains visible.
- `click row`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

The mounted widget owns interaction state, focus chrome, hit geometry, and typed outcomes. The host only forwards backend-neutral events and performs no external effects.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `tree-navigation/project`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn tree_navigation_project_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let nodes = example_project_tree();
    let mut state = TreeNavigationState::new(Some("main"));
    state.set_focused(true);
    state.reconcile_route(&nodes);
    state.focus_route(&nodes);
    TreeNavigation::new(&nodes, system)
        .ascii(true)
        .paint(area, frame.buffer_mut(), &mut state);
}
```

## Migrated handbook guidance

# TreeNavigation

**Purpose.** Project explorers, schema browsers, settings trees, documentation
outlines. **Not** the multi-select data [`Tree`](/docs/components/tree) widget.


## Route ≠ focus

- `route()` — active destination (survives filter when still in projection)
- `focus()` — keyboard cursor
- Enter on routeable leaf → `RouteChanged`

## Arrows

- **←** collapse or parent  
- **→** expand / lazy load / first child  
- **↑/↓** move focus  

## Lazy children

`LazyLoadRequested { id, generation }` → host loads → `apply_lazy_result` + new
projection → `reconcile_route` keeps selection when possible.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
