## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

<TerminalPreview story="mode-ribbon/basic" interactive caption="ModeRibbon · Mode ribbon — live shared Rust state" />

## Try it

- `←→ change mode`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `Enter request mode`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted widget owns interaction state, focus chrome, hit geometry, and typed outcomes. The host only forwards backend-neutral events and performs no external effects.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `mode-ribbon/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn mode_ribbon_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let tokens = system.clone().density(Density::default());
    let modes = [
        WorkbenchMode {
            id: "plan",
            label: "Plan",
            active: true,
            enabled: true,
        },
        WorkbenchMode {
            id: "build",
            label: "Build",
            active: false,
            enabled: true,
        },
    ];
    Widget::render(ModeRibbon::new(&modes, &tokens), area, frame.buffer_mut());
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Test recipe

Mount `mode-ribbon/basic`, dispatch each listed action, and assert the typed outcome, changed Ratatui cells, persistent follow-up state, pointer hit geometry, and Reset behavior.
