## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

<TerminalPreview story="diagnostic/list" interactive caption="DiagnosticView · Diagnostic list — live shared Rust state" />

## Try it

- `↑↓ move`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `Enter expand`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `wheel scroll`: Scroll over the preview; its own viewport moves while the docs page stays put.
- `click diagnostic`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `C copy`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted widget owns interaction state, focus chrome, hit geometry, and typed outcomes. The host only forwards backend-neutral events and performs no external effects.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `diagnostic/list`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn diagnostic_list(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let labels = [SourceLabel::primary(SourceRange::line_span(2, 5, 12)).label("expected `i32`")];
    let items = [
        Diagnostic::new("d1", DiagnosticSeverity::Error, "mismatched types")
            .code("E0308")
            .source("rustc")
            .file("src/main.rs")
            .labels(&labels),
        Diagnostic::new("d2", DiagnosticSeverity::Warning, "unused variable: `y`")
            .code("unused_variables")
            .source("rustc")
            .file("src/main.rs"),
        Diagnostic::new(
            "d3",
            DiagnosticSeverity::Info,
            "build finished with warnings",
        )
        .source("cargo"),
    ];
    let mut state = DiagnosticState::new();
    DiagnosticView::new(&items, system)
        .recipe(DiagnosticRecipe::List)
        .title("Problems")
        .render(area, frame.buffer_mut(), &mut state);
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Test recipe

Mount `diagnostic/list`, dispatch each listed action, and assert the typed outcome, changed Ratatui cells, persistent follow-up state, pointer hit geometry, and Reset behavior.
