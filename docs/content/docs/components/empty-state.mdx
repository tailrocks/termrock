## Live terminal (Ghostty-class)

This preview mounts one persistent Rust component instance. Use the listed keyboard and pointer actions; each accepted action updates the same state and reports its typed outcome.

<TerminalPreview story="empty-state/basic" interactive caption="EmptyState · Empty state — persistent Rust preview; available actions appear below" />

## Usage

```rust
use termrock::style::DesignSystem;
use termrock::widgets::{EmptyState, EmptyKind, EmptyAction, example_empty_search};

let system = DesignSystem::default();
EmptyState::new("No results", &system)
    .kind(EmptyKind::NoResults)
    .explanation("Try another query")
    .primary(EmptyAction::with_shortcut("Clear filters", "esc"))
    .paint(area, buf);
// or: example_empty_search(&system)
```

## Try it

- Use the actions shown beside the terminal; mouse, keyboard, paste, drag, and resize are forwarded only when the component supports them.
- Confirm the visual state and typed outcome, then use **Reset** to mount a fresh instance.

Accepted actions update the same mounted Rust value. The status line shows the latest outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted widget owns interaction state, focus chrome, hit geometry, and typed outcomes. The host only forwards backend-neutral events and performs no external effects.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Test recipe

Mount `empty-state/basic`, dispatch each listed action, and assert the typed outcome, changed Ratatui cells, persistent follow-up state, pointer hit geometry, and Reset behavior.
