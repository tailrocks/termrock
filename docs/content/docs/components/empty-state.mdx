## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

<TerminalPreview story="empty-state/basic" interactive caption="EmptyState · Empty state — live shared Rust state" />

## Try it

- `Tab choose action`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `Enter/Space activate`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `1/2 shortcut`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `click action`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted widget owns interaction state, focus chrome, hit geometry, and typed outcomes. The host only forwards backend-neutral events and performs no external effects.

The Code view above and this source excerpt use the exact paint setup registered for `empty-state/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust

// Exact paint setup used by the shared catalog story.

```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Test recipe

Mount `empty-state/basic`, dispatch each listed action, and assert the typed outcome, changed Ratatui cells, persistent follow-up state, pointer hit geometry, and Reset behavior.
