## Usage

```rust
use termrock::style::DesignSystem;
use termrock::widgets::{
    ErrorState, ErrorKind, Recovery, RecoveryAction, RetrySafety,
    ErrorStateState, example_error_network,
};

let system = DesignSystem::default();
let err = ErrorState::new("Request failed", &system)
    .kind(ErrorKind::Network)
    .explanation("Could not reach the API")
    .technical("timeout after 30s")
    .source("jobs-service")
    .recovery(
        Recovery::none()
            .with_retry(RecoveryAction::with_shortcut("Retry", "r"))
            .with_retry_safety(RetrySafety::Safe)
            .with_copy_diagnostics(true)
            .with_work_preserved(true, Some("Draft retained")),
    );

let mut state = ErrorStateState::new(); // technical collapsed
err.paint_with_state(area, buf, &mut state);
// ErrorView is a type alias for ErrorState
```

## Try it

- No actions. This component is passive in this demo; the page remains navigable.

Accepted actions update the same mounted Rust value. The status line shows the latest outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The widget owns deterministic paint and layout. The host owns all surrounding state and effects; this demo intentionally exposes no fake cursor, click, or keyboard behavior.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Test recipe

Mount `error-view/basic`, dispatch only the actions listed above, and assert both the returned outcome and changed Ratatui cells. Passive demos must reject input without trapping page navigation.
