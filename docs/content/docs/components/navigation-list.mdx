## Usage

The Code view above and this source excerpt use the exact paint setup registered for `navigation-list/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn navigation_list_basic_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let items = [
        NavItem::new("a", "Inbox").badge("3"),
        NavItem::new("b", "Starred"),
        NavItem::new("c", "Archive"),
    ];
    let mut state = NavigationListState::new(Some("a"));
    state.set_focused(true);
    // focus moved to b, route still a
    let _ = state.handle_key(
        termrock::input::KeyEvent::new(
            termrock::input::KeyCode::Down,
            termrock::input::KeyModifiers::NONE,
        ),
        &items,
    );
    NavigationList::new(&items, system)
        .ascii(true)
        .paint(area, frame.buffer_mut(), &mut state);
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
