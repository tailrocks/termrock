## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

## Try it

- `↑↓ move`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `Enter select`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `/ filter`: Focus the editable field, then type or paste Unicode text; the draft remains visible.
- `F follow`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `wheel scroll`: Scroll over the preview; its own viewport moves while the docs page stays put.
- `click event`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted widget owns interaction state, focus chrome, hit geometry, and typed outcomes. The host only forwards backend-neutral events and performs no external effects.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `timeline/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn timeline(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let events = [
        TimelineEvent::with_id("a", "12:01", "Started deploy")
            .status(TimelineStatus::Success)
            .actor("ci")
            .relative("1h ago")
            .duration("12s"),
        TimelineEvent::with_id("b", "12:02", "Running tests")
            .status(TimelineStatus::Running)
            .active()
            .actor("ci")
            .correlation("trace-9"),
        TimelineEvent::with_id("c", "12:03", "Open PR")
            .status(TimelineStatus::Pending)
            .actor("bot"),
    ];
    let mut state = TimelineState::new();
    state.following = false;
    state.cursor = 1;
    frame.render_stateful_widget(
        Timeline::with_events(&events, system).focused(true),
        area,
        &mut state,
    );
}
```

## Migrated handbook guidance

# Timeline

**Purpose.** Present time-ordered events with status, actor, and optional
grouping. Supports live streaming while preserving reading position when the
user scrolls up.


## Recipes

| Recipe | Use |
|--------|-----|
| `Detailed` (default) | Full rows: time · actor · status · text |
| `Rail` | Compact side-panel markers |
| `GroupedDay` | Day/session headers |

## Live stream

- `TimelineState::following` defaults **true** (stick to newest).
- Moving up / wheel-up **pauses** follow.
- `f` or End re-follows; call `on_append(len)` after host appends.

## Example

```rust
use termrock::widgets::{
    Timeline, TimelineEvent, TimelineState, TimelineStatus, TimelineRecipe,
};

let events = [
    TimelineEvent::with_id("a", "12:01", "Deploy")
        .status(TimelineStatus::Success)
        .actor("ci"),
    TimelineEvent::with_id("b", "12:02", "Tests")
        .status(TimelineStatus::Running)
        .active(),
];
let mut state = TimelineState::new();
// Timeline::with_events(&events, &system).recipe(TimelineRecipe::Rail)
```

## Checkpoint mode (Timeline)

`TimelineState::set_checkpoint_mode(true)`: Enter → `RestoreRequested`, `c` →
`CompareRequested` on checkpoint rows.

For full session restore/rewind UX (boundaries, preview, draft preserved), use
[CheckpointTimeline](/docs/components/checkpoint-timeline) (migration `0229`).
