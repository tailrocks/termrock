## State and typed outcomes

`AlertDialogState` owns safe focus, action hit regions, and typed outcomes. The demo closes on the outcome and reports it; destructive external effects remain host-owned and are intentionally absent.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `alert-dialog/delete`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn alert_dialog_delete_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let mut state = AlertDialogState::new(
        AlertKind::Delete,
        AlertScope::example_delete(),
        "delete",
        "keep",
    );
    AlertDialog::new(system).paint(area, frame.buffer_mut(), &mut state);
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
