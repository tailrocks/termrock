## Usage

```rust
use termrock::style::DesignSystem;
use termrock::widgets::{CommandPalette, CommandPaletteState, example_command_catalog};

let system = DesignSystem::default();
let catalog = example_command_catalog();
let mut state = CommandPaletteState::new(None);
state.set_focused(true);
let visible = state.refilter(&catalog);
CommandPalette::new("Commands", &visible, &system).paint(area, buf, &mut state);
```

## State and typed outcomes

The demo owns ephemeral widget state between events. The widget owns painted geometry, focus/selection mechanics, and typed outcomes. The host owns domain effects and decides what an emitted outcome means to the application.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Migrated handbook guidance

# Command palette

**Purpose.** Let users jump to any command by typing a query. TermRock paints
the modal, filter field chrome, and result list; **you** own the command catalog
and what happens on activation.


## When to use / when not

| Use CommandPalette | Prefer |
|--------------------|--------|
| Global command jump | — |
| File/symbol pickers | Picker |
| Agent slash commands only | PromptComposer slash menu |
| Settings forms | Form |

## Focus law

| Concern | Owner |
|---------|--------|
| Overlay open/Esc peel | OverlayStack |
| Surface focus / accepts input | Host (`focused` + `set_accepts_input`) |
| Result cursor | Picker/list inside `CommandPaletteState` |
| Filter / ranking | Consumer projection |

## Outcomes

- `Ignored`
- `QueryChanged` — rebuild filtered rows
- `CursorMoved` — result highlight changed
- `Activated(Id)`
- `Cancelled` — Esc with empty query

## Intents

Results use list intents (j/k, page, Enter, Esc). Query typing stays on
TextInput path. Two-stage Esc: clear query, then cancel.

## Non-color

- Empty: `∅` / `[ ]` + message
- Panel: Focused vs Normal border roles
- Footer: muted keymap hint

## Responsive

| Geometry | Behavior |
|----------|----------|
| height ≥ 8, width ≥ 28 | Footer hint |
| narrow (&lt; 28) | Drop footer; short placeholder |
| Overlay narrow | Fullscreen promote via OverlayPolicy |

## Basic example

```rust
use ratatui_core::{layout::Rect, text::Line};
use termrock::{
    style::DesignSystem,
    widgets::{CommandPalette, CommandPaletteSize, ListRow, place_command_palette},
};

let system = DesignSystem::default();
let rows = [ListRow::item("quit", Line::from("Quit"))];
let palette = CommandPalette::new("Commands", &rows, &system);
let rect = place_command_palette(Rect::new(0, 0, 80, 24), CommandPaletteSize::default());
assert!(rect.width > 0);
let _ = palette;
```

## Interactive example

```rust
use ratatui_core::text::Line;
use termrock::{
    input::{KeyCode, KeyEvent, KeyModifiers},
    style::DesignSystem,
    widgets::{
        CommandPalette, CommandPaletteOutcome, CommandPaletteState, ListRow,
    },
};

let system = DesignSystem::default();
let rows = [ListRow::item("quit", Line::from("Quit"))];
let mut state = CommandPaletteState::new(Some("quit"));
state.set_accepts_input(true);
let outcome = CommandPalette::handle_key(
    &mut state,
    KeyEvent::new(KeyCode::Enter, KeyModifiers::NONE),
    &rows,
);
assert!(matches!(outcome, CommandPaletteOutcome::Activated("quit")));
let _ = CommandPalette::new("Commands", &rows, &system);
```
