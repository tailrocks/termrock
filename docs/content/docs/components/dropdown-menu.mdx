## Live terminal (Ghostty-class)

Open the menu from its trigger. The same `DropdownMenuState` then handles row navigation, submenu disclosure, activation, and dismissal.

## Usage

```rust
use ratatui_core::layout::Rect;
use termrock::style::DesignSystem;
use termrock::widgets::{
    DropdownMenu, DropdownMenuState, MenuNode, open_dropdown_menu_overlay, measure_menu_panel,
};

let system = DesignSystem::default();
let nodes = vec![
    MenuNode::command("open", "Open").shortcut("C-o"),
    MenuNode::submenu("more", "More", vec![MenuNode::command("a", "A")]),
];
let mut state = DropdownMenuState::new();
let bounds = Rect::new(0, 0, 80, 24);
let _ = state.open_from_keyboard(&nodes, bounds);
// stack: open_dropdown_menu_overlay(...); paint: DropdownMenu::new(&nodes, &system).paint(...)
```

## Try it

- `Enter open menu` or click **Actions**.
- Once open, use `↑↓`, `←→`, Enter, Escape, or click a row.

Accepted actions update the same mounted Rust value. The status line shows the latest outcome; **Reset** creates a fresh instance.

## State and typed outcomes

`DropdownMenuState` owns its cascade, cursor, typeahead, and hit geometry. The host owns the command effect and opener-focus restoration after the typed outcome closes the menu.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
