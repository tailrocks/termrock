This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

## Try it

- `←→ change tab`: Move through the real focus/selection model; the next action uses the new target.
- `Home/End`: Move through the real focus/selection model; the next action uses the new target.
- `click tab`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The demo owns ephemeral widget state between events. The widget owns painted geometry, focus/selection mechanics, and typed outcomes. The host owns domain effects and decides what an emitted outcome means to the application.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `tabs/status`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn tabs(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let items = [
        Tab {
            id: "overview",
            label: "Overview",
            glyph: Some(Span::styled("●", system.style(Role::Success))),
            badge: None,
            status: TabStatus::Success,
            active: true,
            enabled: true,
            closable: false,
        },
        Tab {
            id: "details",
            label: "Details",
            glyph: None,
            badge: Some("2"),
            status: TabStatus::None,
            active: false,
            enabled: true,
            closable: false,
        },
        Tab {
            id: "logs",
            label: "Logs",
            glyph: None,
            badge: None,
            status: TabStatus::Running,
            active: false,
            enabled: true,
            closable: false,
        },
    ];
    let mut state = TabsState::new().with_selected("overview");
    state.set_focused(true);
    frame.render_stateful_widget(&Tabs::new(&items, system).gap(1), area, &mut state);
}
```

## Migrated handbook guidance

# Tabs

**Purpose.** Switch views, documents, or question groups. Each **panel’s state**
is host-owned (map id → panel). Tabs only own strip selection/focus/chrome.


## vs SegmentedControl

SegmentedControl changes mode on **one** surface. Tabs imply **separate
panels**, close actions, dirty/status, and richer overflow.

## Activation

- **Automatic** (default): arrows select  
- **Manual**: arrows focus; Enter/click select  

## Narrow contraction

Expanded → scrolling window → overflow `…` → Select trigger (multi-tab only).

## Outcomes

`SelectionChanged` · `CloseRequested` · `OverflowOpened` · `ReorderRequested`
· `FocusChanged`

## Related

SegmentedControl · CollectionState · migration `0152`

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Test recipe

Mount `tabs/status`, dispatch each listed action, and assert the typed outcome, changed Ratatui cells, persistent follow-up state, pointer hit geometry, and Reset behavior.
