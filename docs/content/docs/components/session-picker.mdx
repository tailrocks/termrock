## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

<TerminalPreview story="session-picker/basic" interactive caption="SessionPicker · Session picker — live shared Rust state" />

## Try it

- `↑↓ select`: Move through the real focus/selection model; the next action uses the new target.
- `/ search`: Focus the editable field, then type or paste Unicode text; the draft remains visible.
- `Enter resume`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `D delete dialog`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `Esc cancel`: Open the transient state first, then cancel it; focus and the underlying state are preserved.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `session-picker/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn session_picker_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    use termrock::patterns::{SessionPicker, SessionPickerState, example_sessions};
    let mut state = SessionPickerState::new();
    state.set_sessions(example_sessions());
    state.focused = true;
    frame.render_stateful_widget(&SessionPicker::new(system), area, &mut state);
}
```
