## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

<TerminalPreview story="integration-status/list" interactive caption="IntegrationStatus · IntegrationStatus list — live shared Rust state" />

## Try it

- `↑↓ select`: Move through the real focus/selection model; the next action uses the new target.
- `Enter inspect`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `R reconnect`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `Tab details`: Move through the real focus/selection model; the next action uses the new target.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `integration-status/list`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn integration_status_list_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    use termrock::patterns::{
        IntegrationStatus, IntegrationStatusPresentation, IntegrationStatusState,
        example_integrations,
    };
    let mut state = IntegrationStatusState::new();
    state.set_entries(example_integrations());
    state.presentation = IntegrationStatusPresentation::CompactList;
    state.focused = true;
    frame.render_stateful_widget(&IntegrationStatus::new(system), area, &mut state);
}
```

## Safety

- Third-party provenance always labeled
- Egress capabilities call out **may send data outside workspace**
- Outcomes never auto-grant permissions

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
