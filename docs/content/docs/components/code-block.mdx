## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

## Try it

- `↑↓ move line`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `wheel scroll`: Scroll over the preview; its own viewport moves while the docs page stays put.
- `click line`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `Enter activate`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `C copy`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted widget owns interaction state, focus chrome, hit geometry, and typed outcomes. The host only forwards backend-neutral events and performs no external effects.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `code-block/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn code_block(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    use termrock::widgets::RoleTokenSyntax;
    let lines = ["fn main() {", "    println!(\"hi\");", "}"];
    let hi = RoleTokenSyntax::rust(system);
    let mut state = CodeBlockState::new();
    let _ = CodeBlock::new(&lines, system)
        .language("rust")
        .path("src/main.rs")
        .line_numbers(true)
        .highlighter(&hi)
        .paint(area, frame.buffer_mut(), &mut state);
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
