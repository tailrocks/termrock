## Live terminal (Ghostty-class)

This preview owns a persistent `TextInputState`. Type or paste Unicode, move the caret, and click to place it; Reset clears the draft.

<TerminalPreview story="text-input/basic" interactive caption="TextInput · Type, paste, move, and place the real caret" />

## Usage

```rust
use termrock::{style::DesignSystem, widgets::{EditAction, TextInput, TextInputState, Validation}};

let system = DesignSystem::default();
let input = TextInput::new("Filter", &system)
    .placeholder("type to filter")
    .validation(Validation::Valid);
let mut state = TextInputState::new("").with_max_graphemes(80);
let changed = state.apply(EditAction::Insert('a'));
```

## Try it

- `type Unicode`: insert browser text through the backend-neutral key event.
- `paste`: dispatch `Event::Paste` into the same Rust state.
- `←→ move caret`: move by grapheme, not byte.
- `click place caret`: use widget hit geometry to reposition the caret.

Accepted actions update the same mounted Rust value. The status line shows the latest outcome; **Reset** creates a fresh instance.

## State and typed outcomes

`TextInputState` owns the draft, grapheme-safe caret, selection, and validation. The host owns submission effects. The browser paints only the caret emitted by the Rust widget buffer.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
