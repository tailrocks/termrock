## Anatomy

`root` · `header` · `body` · `footer` · optional `disclosure`

## Variants

| Variant | Border | Notes |
|---------|--------|-------|
| Bordered | box | default |
| Quiet | none | transparent fill |
| DividerOnly | top/bottom rules | ASCII fallback via GlyphSet |
| Interactive | box | panel-level focus + Activate |
| Selected | box | selection chrome — **not** focus |

Focus uses `PanelChrome::Focused` → `Role::BorderFocused` (never border weight).

## Usage

```rust
use termrock::{style::{DesignSystem, PanelChrome}, widgets::{Panel, PanelBody, PanelVariant}};

let system = DesignSystem::default();
let body = Panel::new(&system)
    .title("Inbox")
    .variant(PanelVariant::Bordered)
    .emphasis(PanelChrome::Focused)
    .body(PanelBody::Empty)
    .body_title("No messages")
    .paint(area, buf, None);
```

## Keyboard (when focusable)

| Intent | Keys (default maps) | Outcome |
|--------|---------------------|---------|
| Activate | Enter | `Activated` (interactive) or toggle (collapsible) |
| Toggle | Space | `ToggleCollapsed` |
| Expand / Collapse | Right/Left (list map) | expand/collapse |

## Mouse

- Click header/disclosure → toggle collapse
- Click hit region (interactive) → Activate

## Common mistakes

- Using selected chrome as focus — keep focus on `BorderFocused`
- Nesting Panels for padding — use Surface/padding, one Panel per region
- Painting children outside `body` / `clip`
