This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

- `Enter/Space toggle`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `← collapse`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `→ expand`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `click header/body`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The demo owns only ephemeral focus state. `Panel` owns border geometry and semantic focused/unfocused chrome; the host owns routing and any effect caused by activation.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `panel/focused`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn panel(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let panel_tokens = system.clone().density(Density::default());
    frame.render_widget(
        Panel::new(&panel_tokens)
            .title("Summary")
            .emphasis(PanelChrome::Focused),
        area,
    );
    if area.width > 2 && area.height > 2 {
        frame.render_widget(
            Paragraph::new("State   Ready\nMode    Interactive"),
            Rect::new(area.x + 1, area.y + 1, area.width - 2, area.height - 2),
        );
    }
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
