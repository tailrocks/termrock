## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

## Try it

- `Tab panes`: Move through the real focus/selection model; the next action uses the new target.
- `↑↓ select`: Move through the real focus/selection model; the next action uses the new target.
- `Enter inspect`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `A approve`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `R reject`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `plan-review/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn plan_review_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    use termrock::patterns::{PlanReview, PlanReviewState, example_plan_document};
    let mut state = PlanReviewState::new();
    state.open(example_plan_document());
    state.focused = true;
    frame.render_stateful_widget(&PlanReview::new(system), area, &mut state);
}
```

## Migrated handbook guidance

# PlanReview

Interactive review for agent-generated plans. Host owns execution policy;
outcomes are **requests only**. Approve is never the initial focus.
The plan-gold rail and title establish document identity; task fields and
decision chips reuse the shared composition vocabulary.


## When to use / when not

| Use PlanReview | Prefer |
|----------------|--------|
| Approve/revise agent plan before work | — |
| Single tool/shell trust gate | [PermissionPrompt](/docs/components/permission-prompt) |
| Patch/hunk accept | [DiffReview](/docs/components/diff-review) |
| Multi-question interview | [QuestionFlow](/docs/components/question-flow) |
| Live pipeline progress | [ProgressSteps](/docs/components/progress-steps) (if present) |

## Domain

- `PlanDocument` — body, sections, tasks, risks, assumptions, files, refs, risk, previous
- `PlanComment` + `PlanCommentAnchor` — line/range/section/task/file/orphan
- `remap_plan_comments` / `update_plan` — preserve stable anchors across revisions

## Actions (safe focus)

Abandon · Revise · Feedback · Approve… · Approve

Default: `RequestRevision` (low/medium) or `Abandon` (high/critical). Enter
confirms focus only. Bare `a` moves focus — does not grant.

## Common mistakes
