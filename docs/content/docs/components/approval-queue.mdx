## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

<TerminalPreview story="approval-queue/basic" interactive caption="ApprovalQueue · ApprovalQueue — live shared Rust state" />

## Try it

- `↑↓ select`: Move through the real focus/selection model; the next action uses the new target.
- `Enter inspect`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `A approve`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `D deny`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `Esc cancel`: Open the transient state first, then cancel it; focus and the underlying state are preserved.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `approval-queue/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn approval_queue_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    use termrock::patterns::{
        ApprovalQueue, ApprovalQueuePresentation, ApprovalQueueState, example_approval_queue,
    };
    let mut state = ApprovalQueueState::new();
    state.set_items(example_approval_queue());
    state.presentation = ApprovalQueuePresentation::Full;
    state.focused = true;
    frame.render_stateful_widget(&ApprovalQueue::new(system), area, &mut state);
}
```

Multi-type human-decision inbox. High-risk items **only Open** into
