## Usage

```rust
use termrock::style::DesignSystem;
use termrock::runtime::FrameTick;
use termrock::widgets::{
    Anchor, Severity, Toast, ToastLifetime, ToastQueue, ToastSpec, ToastStack, TOAST_DEFAULT_TTL,
};
use std::time::Duration;
use termrock::runtime::Instant;

let system = DesignSystem::default();
let toast = Toast::new(&system, "Saved", Severity::Success).anchor(Anchor::TopRight);
let tick = FrameTick::manual(Instant::now(), Duration::ZERO, Duration::ZERO);
let mut queue = ToastQueue::new();
let _ = queue.push(tick, ToastSpec::message("s", "Saved").severity(Severity::Success));
ToastStack::new(&system).paint(area, buf, &mut queue);
// missed: queue.drain_missed() → NotificationCenter
let _ = (toast, TOAST_DEFAULT_TTL, ToastLifetime::default_ttl());
```

## State and typed outcomes

The demo owns ephemeral widget state between events. The widget owns painted geometry, focus/selection mechanics, and typed outcomes. The host owns domain effects and decides what an emitted outcome means to the application.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
