## Try it

- `Space/Enter toggle`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `click toggle`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `move pointer to hover`: Move the pointer over the target; hover chrome changes without activation.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `toggle/pressed`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn toggle_pressed_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let mut off = ToggleState::new();
    let mut on = ToggleState::with_value(ToggleValue::Pressed);
    on.set_focused(true);
    let row = Layout::horizontal([Constraint::Length(14), Constraint::Length(14)]).split(area);
    let _ = Toggle::new("Bold", system).paint(row[0], frame.buffer_mut(), &mut off);
    let _ = Toggle::new("Bold", system).paint(row[1], frame.buffer_mut(), &mut on);
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
