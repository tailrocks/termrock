## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

## Try it

- `↑↓ select row`: Move through the real focus/selection model; the next action uses the new target.
- `Enter copy/open`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted widget owns interaction state, focus chrome, hit geometry, and typed outcomes. The host only forwards backend-neutral events and performs no external effects.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `detail-table/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn detail_table(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let _tokens = system.clone().density(termrock::style::Density::default());
    let rows = [
        DetailRow {
            id: "state",
            label: "State",
            value: "Ready",
            href: None,
            capability: DetailCapability::Copy,
            emphasis: true,
            style: None,
        },
        DetailRow {
            id: "link",
            label: "Reference",
            value: "https://example.invalid",
            href: Some("https://example.invalid"),
            capability: DetailCapability::CopyAndLink,
            emphasis: false,
            style: None,
        },
        DetailRow {
            id: "region",
            label: "Region",
            value: "ap-southeast-1",
            href: None,
            capability: DetailCapability::None,
            emphasis: false,
            style: None,
        },
        DetailRow {
            id: "updated",
            label: "Updated",
            value: "moments ago",
            href: None,
            capability: DetailCapability::None,
            emphasis: false,
            style: None,
        },
        DetailRow {
            id: "owner",
            label: "Owner",
            value: "platform / runtime",
            href: None,
            capability: DetailCapability::Copy,
            emphasis: false,
            style: None,
        },
    ];
    let table = DetailTable::new(&rows, system).label_width(14).wrap(true);
    let measured = table.measure();
    if area.height > 0 {
        frame.buffer_mut().set_stringn(
            area.x,
            area.y,
            format!("NATURAL EXTENT  {} × {}", measured.0, measured.1),
            usize::from(area.width),
            system.style(Role::TextMuted),
        );
    }
    let table_area = Rect::new(
        area.x,
        area.y.saturating_add(2),
        area.width.min(measured.0),
        area.height.saturating_sub(2).min(measured.1),
    );
    let mut state = DetailTableState::default();
    state.selected = Some("link");
    frame.render_stateful_widget(&table, table_area, &mut state);
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
