## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

## Try it

- `↑↓ choose step`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `Enter activate/retry`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `click step`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `Esc blur`: Open the transient state first, then cancel it; focus and the underlying state are preserved.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted widget owns interaction state, focus chrome, hit geometry, and typed outcomes. The host only forwards backend-neutral events and performs no external effects.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `progress-steps/pipeline`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn progress_steps_pipeline_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let steps = example_build_pipeline();
    let mut state = ProgressStepsState::new();
    ProgressSteps::new(&steps, system)
        .title("Build pipeline")
        .paint(area, frame.buffer_mut(), &mut state);
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Test recipe

Mount `progress-steps/pipeline`, dispatch each listed action, and assert the typed outcome, changed Ratatui cells, persistent follow-up state, pointer hit geometry, and Reset behavior.
