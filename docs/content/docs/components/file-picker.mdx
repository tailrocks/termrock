Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `file-picker/unix`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn file_picker_unix_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let mut state = FilePickerState::new("/home/u/proj")
        .with_mode(FilePickerMode::OpenFile)
        .with_preview(true)
        .with_path_style(PathStyle::Unix);
    state.set_focused(true);
    file_picker_seed(&mut state, "/home/u/proj", file_picker_unix_entries());
    let _ = state.apply_preview(
        state.preview_generation(),
        FilePreview::text(
            "README.md",
            [
                "# proj".into(),
                "".into(),
                "Hello from Unix FS host.".into(),
            ],
        ),
    );
    FilePicker::new(system)
        .title("Open file")
        .ascii(true)
        .paint(area, frame.buffer_mut(), &mut state);
}
```

## Migrated handbook guidance

# FilePicker

**Purpose.** Reusable open/save browser for files and directories. Built from
PathInput, CollectionState list focus, Selection multi-check, and optional
OverlayStack dialogs. TermRock never calls the filesystem.


## Ownership

| Concern | Owner |
|---------|--------|
| List / preview I/O, cancel, permissions | Host |
| Entry projection (kind, hidden, size, mtime labels) | Host |
| Hidden filter, name filter, sort, multi, crumbs | FilePicker |
| Path field typing | Embedded PathInput |
| Modal place / dismiss | OverlayStack helpers |

## Host loop

```rust
match state.handle_key(key) {
    FilePickerOutcome::ListRequested { path, generation } => {
        host.cancel_list();
        host.list_dir(path, generation); // async
    }
    FilePickerOutcome::PreviewRequested { path, generation } => {
        host.preview(path, generation);
    }
    FilePickerOutcome::Confirmed { paths } => host.accept(paths),
    FilePickerOutcome::Cancelled => host.close_picker(),
    FilePickerOutcome::FilterChanged => {
        // e.g. Ctrl+H hidden — re-list if host omitted hidden rows
        let _ = state.request_list(state.cwd().to_owned());
    }
    _ => {}
}

// when list returns:
if state.apply_listing(generation, cwd, entries, None) {
    // applied
}
// stale generation → false, ignored

// when preview returns:
if state.apply_preview(generation, preview) {
    // applied
}
// stale preview generation → false, ignored
```

Listing and preview requests use independent generation sequences. Every
`PreviewRequested` carries a fresh preview generation. Starting any directory
listing invalidates outstanding preview work, so a late result from the prior
selection or directory cannot replace the current preview.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not apply preview data without returning the exact generation from the
  matching `PreviewRequested` outcome.
- Do not infer an action from visual styling; handle the widget's typed outcome.
