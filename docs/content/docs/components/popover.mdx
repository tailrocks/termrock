## Live terminal (Ghostty-class)

Open the anchored surface from its trigger, then dismiss it with Escape or its real Close button.

<TerminalPreview story="popover/basic" interactive caption="Popover · Popover basic — persistent Rust preview; available actions appear below" />

## Usage

```rust
use ratatui_core::layout::Rect;
use termrock::interaction::{OverlaySize, OverlayStack};
use termrock::style::DesignSystem;
use termrock::widgets::{
    Popover, PopoverState, open_popover_overlay, POPOVER_OVERLAY_ID,
};

let system = DesignSystem::default();
let mut stack = OverlayStack::<&str>::new();
let bounds = Rect::new(0, 0, 80, 24);
let anchor = Rect::new(10, 5, 8, 1);
let size = OverlaySize::menu(28, 10);
let mut state = PopoverState::new();
let _ = state.open_on_stack(&mut stack, bounds, anchor, size, Some("trigger"));
// Paint: Popover::new("Settings", &system).paint(entry.rect, buf, &mut state);
// Host fills state.slots().body. Dismiss via stack → opener focus restored.
```

## Try it

- `Enter open popover` or click **Open details**.
- Once open, press Escape or click **Close**.

Accepted actions update the same mounted Rust value. The status line shows the latest outcome; **Reset** creates a fresh instance.

## State and typed outcomes

`PopoverState` owns open/focus/presentation state and slot geometry. Overlay placement and opener focus remain host-owned; the demo reports the close reason without external effects.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Test recipe

Mount `popover/basic`, dispatch only the actions listed above, and assert both the returned outcome and changed Ratatui cells. Passive demos must reject input without trapping page navigation.
