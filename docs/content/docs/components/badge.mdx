## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

<TerminalPreview story="badge/basic" interactive caption="Badge · Badge variants — live shared Rust state" />

## Try it

- `hover`: Move the pointer over the target; hover chrome changes without activation.
- `click toggle`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `Enter toggle`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted widget owns interaction state, focus chrome, hit geometry, and typed outcomes. The host only forwards backend-neutral events and performs no external effects.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `badge/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn badge_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    use termrock::widgets::Badge;
    let chunks = Layout::vertical([
        Constraint::Length(1),
        Constraint::Length(1),
        Constraint::Length(1),
        Constraint::Length(1),
        Constraint::Length(1),
        Constraint::Length(1),
        Constraint::Length(1),
    ])
    .split(area);
    let _ = Badge::new("meta", system)
        .neutral()
        .paint(chunks[0], frame.buffer_mut(), None);
    let _ = Badge::new("info", system)
        .info()
        .paint(chunks[1], frame.buffer_mut(), None);
    let _ = Badge::new("ok", system)
        .success()
        .paint(chunks[2], frame.buffer_mut(), None);
    let _ = Badge::new("warn", system)
        .warning()
        .paint(chunks[3], frame.buffer_mut(), None);
    let _ = Badge::new("fail", system)
        .destructive()
        .paint(chunks[4], frame.buffer_mut(), None);
    let _ = Badge::new("tag", system)
        .outline()
        .paint(chunks[5], frame.buffer_mut(), None);
    let _ = Badge::count(150, system).paint(chunks[6], frame.buffer_mut(), None);
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Test recipe
