## Try it

- `↑↓ move`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `Enter details`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `/ filter`: Focus the editable field, then type or paste Unicode text; the draft remains visible.
- `F follow`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `wheel scroll`: Scroll over the preview; its own viewport moves while the docs page stays put.
- `click event`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted widget owns interaction state, focus chrome, hit geometry, and typed outcomes. The host only forwards backend-neutral events and performs no external effects.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `event-stream/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn event_stream_basic(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let events = event_stream_sample();
    let mut state = EventStreamState::new();
    state.set_following(false);
    state.cursor = 2;
    state.on_append(events.len() as u16, area.height.saturating_sub(1));
    EventStream::with_events(&events, system)
        .focused(true)
        .render(area, frame.buffer_mut(), &mut state);
}
```

## Migrated handbook guidance

# EventStream

**Purpose.** Structured event consoles (k8s events, agent activity, observability)
where rows are **typed**, not freeform log lines. Distinct from
[LogStream](/docs/components/log-stream) (text+level) and
[Timeline](/docs/components/timeline) (presentation recipes).


## When to use

| Use EventStream | Prefer |
|-----------------|--------|
| Kubernetes / cloud events | — |
| Agent tool/activity stream | — |
| Burst-prone high-rate feeds | — |
| Plain application logs | LogStream |
| Deploy/history narrative | Timeline |

## Live + unread

- Follow tail by default (`ScrollAreaState` authority).
- Scroll/move up **detaches**; chip shows `↓ N new`.
- Host calls `on_append(total, viewport)` after each project.
- `report_backpressure(dropped, batched)` for drop/batch chrome.

## Example

```rust
use termrock::widgets::{EventStream, EventStreamState, StreamEvent, EventSeverity};

let events = [
    StreamEvent::with_id("e1", "Warning", "12:01", "FailedMount")
        .severity(EventSeverity::Warn)
        .source("kubelet")
        .fields("vol=cfg")
        .detail("MountVolume.SetUp failed…")
        .batch_count(3),
];
let mut state = EventStreamState::new();
state.on_append(1, 20);
// EventStream::with_events(&events, &system).render(area, buf, &mut state);
```

## Pluggable summary / detail

- `summary` — one-line host-formatted row body.
- `fields` — optional `k=v` chrome (dropped when narrow).
- `detail` — inspector body when selected (`i` / Enter).
