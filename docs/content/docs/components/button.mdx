- `click press/release`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The demo owns ephemeral widget state between events. The widget owns painted geometry, focus/selection mechanics, and typed outcomes. The host owns domain effects and decides what an emitted outcome means to the application.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `button/activation`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn button_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let mut state = ButtonState::new();
    state.activation.set_accepts_input(true);
    Button::new("Save", system)
        .variant(termrock::widgets::ButtonVariant::Primary)
        .leading("✓")
        .render(area, frame.buffer_mut(), &mut state);
}
```

## Migrated handbook guidance

# Button

**Purpose.** Domain-neutral control that signals one activation. Effects stay
consumer-owned (`ActivationOutcome`). Multi-id toolbars still use `ActionBar`.


## When to use / when not

| Use Button | Prefer |
|------------|--------|
| One labeled or icon action | — |
| Dialog / form footer CTA | — |
| Several stable-ID actions | [ActionBar](/docs/components/dialog) / Action |
| Navigation | Tabs / List |

## Focus law

| Concern | Owner |
|---------|--------|
| Surface input | `ActivationState::set_accepts_input` (host/scene) |
| Pressed / armed | ActivationState (pointer Down / Space) |
| Default dialog focus | Host — **never** default-focus Destructive (`is_safe_default_focus`) |

## Variants

`Primary` · `Secondary` · `Quiet` · `Outline` · `Destructive` · `Link` ·
`Success` · `Command`

## Sizes

`Compact` · `Normal` (pad only; always 1 row).

## Activation

- `default_button_intent` → Enter/Space map to `UiIntent::Activate`
- Enter: activate on **Press** (once; Repeat ignored)
- Space: **arm** on Press, activate on **Release**
- Pointer: Down arms, Up inside hit activates; drag-off cancels
- Loading and disabled never activate (distinct paint)
- `set_pending_confirmation(true)` → first Activate is `ConfirmRequired`

## Non-color

- Colorless: strong text for primary/danger/success; outline uses `[ ]`
- Loading: `…` / `...` prefix (not same as disabled dim alone)
- Icon-only without a11y name paints danger mark (refuse silent control)

## Responsive

| Width | Behavior |
|-------|----------|
| full_width | Fill area |
| narrow (&lt; 12) | Drop trailing then leading glyphs |
| tiny (&lt; 6) | Label start only |

## Basic example

```rust
use termrock::{
    style::DesignSystem,
    widgets::{Button, ButtonState, ButtonVariant},
};

let system = DesignSystem::default();
let button = Button::new("Save", &system).variant(ButtonVariant::Primary);
let mut state = ButtonState::new();
state.activation.set_accepts_input(true);
let _ = (button, &mut state);
```

## Interactive example

```rust
use termrock::{
    input::{KeyCode, KeyEvent, KeyModifiers},
    style::DesignSystem,
    widgets::{ActivationOutcome, Button, ButtonState, ButtonVariant},
};

let system = DesignSystem::default();
let _button = Button::new("Save", &system).variant(ButtonVariant::Primary);
let mut state = ButtonState::new();
state.activation.set_accepts_input(true);
let out = state.handle_key(KeyEvent::new(KeyCode::Enter, KeyModifiers::NONE));
assert!(matches!(out, ActivationOutcome::Activated));
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
