## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

<TerminalPreview story="search-input/basic" interactive caption="SearchInput · Search input — live shared Rust state" />

## Try it

- `type or paste query`: Focus the editable field, then type or paste Unicode text; the draft remains visible.
- `←→ move caret`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `Esc clear`: Open the transient state first, then cancel it; focus and the underlying state are preserved.
- `click clear`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted widget owns interaction state, focus chrome, hit geometry, and typed outcomes. The host only forwards backend-neutral events and performs no external effects.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `search-input/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn search_input_basic_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let mut state = SearchInputState::new().with_query("table");
    state.set_focused(true);
    let _ = SearchInput::new(system)
        .placeholder("Search…")
        .status(SearchStatus::Results { count: 12 })
        .ascii(true)
        .paint(area, frame.buffer_mut(), &mut state);
}
```

## Migrated handbook guidance

# SearchInput

**Purpose.** Query chrome for tables, logs, quick-open, palettes, and
inspectors. TermRock owns typing, clear, history, metadata strip, and debounce
*signals*. Hosts own filtering, scoring, and async search.


## Debounce (no async inside)

```rust
// after handle_key / insert_str
match state.poll(frame_tick) {
    SearchInputOutcome::DebouncedQuery { query } => host.search(query),
    _ => {}
}
```

`Duration::ZERO` debounce + `flush_debounce()` for immediate apply.

## Escape

1. Non-empty → clear → `Cleared`
2. Empty → `Cancelled` (dismiss)

## Status projection

Host sets `SearchStatus::{Idle,Searching,Results{count},NoResults,Error}` after
its own search completes. Never computed by scanning domain data inside the widget.

## Metadata before query

Leading icon + active `SearchFilterChip`s paint **left of** the editable query
so filter context contracts first under narrow widths.

## Example

```rust
use termrock::style::DesignSystem;
use termrock::widgets::{SearchFilterChip, SearchInput, SearchInputState, SearchStatus};

let system = DesignSystem::default();
let mut state = SearchInputState::new();
state.set_focused(true);
let chips = [SearchFilterChip::new("ext", "rs")];
let _ = SearchInput::new(&system)
    .filters(&chips)
    .status(SearchStatus::Results { count: 4 });
```
