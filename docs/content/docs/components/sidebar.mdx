- `↑↓ select`: Move through the real focus/selection model; the next action uses the new target.
- `Enter activate`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `[ toggle rail`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `click route`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `wheel`: Scroll over the preview; its own viewport moves while the docs page stays put.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

`SidebarState` owns presentation and navigation focus/route state. The host performs actual navigation and opens drawer/palette surfaces from typed outcomes.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `sidebar/settings`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn sidebar_settings_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let items = example_settings_nav();
    let mut state = SidebarState::new(Some("profile"));
    state.set_focused(true);
    Sidebar::new(&items, system)
        .ascii(true)
        .show_panel(true)
        .title("Settings")
        .paint(area, frame.buffer_mut(), &mut state);
}
```

## Migrated handbook guidance

# Sidebar & NavigationList

**Purpose.** AppShell start-dock navigation. **Route** (active destination) is
separate from **focus** (keyboard cursor). Host owns real routing and expansion
projection.


## NavigationList

Core list: sections, groups, badges, status, filter (`/`), expand hooks,
contextual actions, optional `command` ids for semantic commands.

## Sidebar

Chrome around NavigationList: panel title, rail toggle (`[`), width auto-rail,
drawer/palette outcomes for narrow shells.

- `example_settings_nav`
- `example_database_nav`

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Test recipe

Mount `sidebar/settings`, dispatch each listed action, and assert the typed outcome, changed Ratatui cells, persistent follow-up state, pointer hit geometry, and Reset behavior.
