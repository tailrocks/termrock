## Live terminal (Ghostty-class)

Navigate routes, activate one, and toggle expanded/rail presentation. Route and keyboard focus remain distinct.

<TerminalPreview story="sidebar/settings" interactive caption="Sidebar · Sidebar settings — persistent Rust preview; available actions appear below" />

## Usage

```rust
use termrock::style::DesignSystem;
use termrock::widgets::{Sidebar, SidebarState, example_settings_nav};

let system = DesignSystem::default();
let items = example_settings_nav();
let mut state = SidebarState::new(Some("profile"));
state.set_focused(true);
let _ = Sidebar::new(&items, &system).title("Settings").show_panel(true);
```

## Try it

- `↑↓`, wheel, or click moves focus; Enter activates the focused route.
- `[` toggles expanded and rail presentation without changing route identity.

Accepted actions update the same mounted Rust value. The status line shows the latest outcome; **Reset** creates a fresh instance.

## State and typed outcomes

`SidebarState` owns presentation and navigation focus/route state. The host performs actual navigation and opens drawer/palette surfaces from typed outcomes.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Migrated handbook guidance

# Sidebar & NavigationList

**Purpose.** AppShell start-dock navigation. **Route** (active destination) is
separate from **focus** (keyboard cursor). Host owns real routing and expansion
projection.


## NavigationList

Core list: sections, groups, badges, status, filter (`/`), expand hooks,
contextual actions, optional `command` ids for semantic commands.

## Sidebar

Chrome around NavigationList: panel title, rail toggle (`[`), width auto-rail,
drawer/palette outcomes for narrow shells.
