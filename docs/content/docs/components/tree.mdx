## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

<TerminalPreview story="tree/navigation" interactive caption="Tree · Tree navigation — live shared Rust state" />

## Try it

- `↑↓ select`: Move through the real focus/selection model; the next action uses the new target.
- `←→ collapse/expand`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `click row`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

`TreeState` owns selection and expansion. The host owns domain loading and effects; the demo uses deterministic in-memory nodes only.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `tree/navigation`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn tree(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let tokens = system.clone().density(termrock::style::Density::default());
    let nodes = tree_nodes();
    let mut state = TreeState::new(Some("workspace"));
    state.enable_multi_select();
    state.selection_mut().unwrap().toggle(&"notes");
    frame.render_stateful_widget(&Tree::new(&nodes, &tokens), area, &mut state);
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
