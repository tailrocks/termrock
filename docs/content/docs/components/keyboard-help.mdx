## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

<TerminalPreview story="keyboard-help/footer" interactive caption="KeyboardHelp · KeyboardHelp footer — live shared Rust state" />

## Try it

- `? open help`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `type to filter`: Focus the editable field, then type or paste Unicode text; the draft remains visible.
- `↑↓ navigate`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `wheel scroll`: Scroll over the preview; its own viewport moves while the docs page stays put.
- `Esc close`: Open the transient state first, then cancel it; focus and the underlying state are preserved.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted widget owns interaction state, focus chrome, hit geometry, and typed outcomes. The host only forwards backend-neutral events and performs no external effects.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `keyboard-help/footer`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn keyboard_help_footer(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let entries = example_help_entries(system);
    let mut state = KeyboardHelpState::new();
    KeyboardHelp::new(&entries, system).paint(area, frame.buffer_mut(), &mut state);
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
