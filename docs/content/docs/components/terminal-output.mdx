## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

## Try it

- `↑↓ move`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `wheel scroll`: Scroll over the preview; its own viewport moves while the docs page stays put.
- `F follow`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `C cancel`: Open the transient state first, then cancel it; focus and the underlying state are preserved.
- `Y copy command`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `click stream filter`: Focus the editable field, then type or paste Unicode text; the draft remains visible.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted widget owns interaction state, focus chrome, hit geometry, and typed outcomes. The host only forwards backend-neutral events and performs no external effects.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `terminal-output/running`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn terminal_output_running(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let meta = TerminalCommandMeta::new("cargo test -p termrock --lib")
        .cwd("/Users/dev/termrock")
        .status(TerminalRunStatus::Running)
        .duration_ms(3400)
        .pid(4242);
    let lines = terminal_output_sample_lines();
    let mut state = TerminalOutputState::new();
    state.on_append(lines.len() as u16, area.height.saturating_sub(4));
    TerminalOutput::new(&meta, &lines, system)
        .title("build")
        .render(area, frame.buffer_mut(), &mut state);
}
```

## Migrated handbook guidance

# TerminalOutput

Presents one projected command run: metadata chrome, streaming stdout/stderr,
follow/pause, and typed control **requests**. TermRock never spawns or kills
processes.


## When to use / when not

| Use TerminalOutput | Prefer |
|--------------------|--------|
| Agent/build command panes | — |
| Compact tool summary only | [ToolCard](/docs/components/tool-card) |
| Multi-source logs | [LogStream](/docs/components/log-stream) |
| Owned append buffer | [LogPane](/docs/components/log-pane) |

## Safety

- No `Command::new`, no PTY in this widget
- Outcomes: `CancelRequested`, `RetryRequested`, `DetachProcessRequested`, `Copy*`, …
- Host owns process policy and secrets redaction (helpers assist display only)

## Follow / scroll

`ScrollAreaState` is sole follow authority. Scrolling away detaches; chip or `f`
re-follows. `on_append` updates unread while pinned.
