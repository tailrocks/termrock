## Live terminal (Ghostty-class)

Drive the multi-step flow with its real navigation state. Domain fields are represented by deterministic host-owned content inside the wizard body slot.

## Usage

```rust
use termrock::style::DesignSystem;
use termrock::widgets::{FormWizard, FormWizardState, WizardStep};

let system = DesignSystem::default();
let mut state = FormWizardState::with_steps([
    WizardStep::new("account", "Account"),
    WizardStep::new("confirm", "Confirm"),
]);
state.set_focused(true);
let _ = FormWizard::new(&system).title("Setup");
```

## Try it

- Enter/Right advances, Left goes back, and `S` skips an optional step.
- Escape cancels; nav buttons and step hits accept pointer input.

Accepted actions update the same mounted Rust value. The status line shows the latest outcome; **Reset** creates a fresh instance.

## State and typed outcomes

`FormWizardState` owns step chrome, gates, review, failure, and progress outcomes. The host owns field values, validation messages, persistence, and submission effects.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Ownership

| Concern | Owner |
|---------|--------|
| Step titles, optional flags, progress ids | WizardStep / state |
| Field values, validation messages | Host Form / fields |
| Submit / async I/O / persistence | Host via outcomes |
| Side effects | **Never** in TermRock |

## Host loop

```rust
match state.handle_key(key) {
    FormWizardOutcome::StepChanged { .. } => {
        let _ = state.request_focus_field();
    }
    FormWizardOutcome::AsyncCheckRequested { generation, .. } => {
        host.validate_async(generation);
    }
    FormWizardOutcome::SubmitRequested => host.submit(),
    FormWizardOutcome::ProgressSaved { progress } => host.save(progress),
    FormWizardOutcome::Cancelled => host.close(),
    _ => {}
}
// resume:
state.restore_progress(&saved);
```
