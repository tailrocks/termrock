This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

## Try it

- `Enter/→ next`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `← back`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `S skip optional`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `Esc cancel`: Open the transient state first, then cancel it; focus and the underlying state are preserved.
- `click nav`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

`FormWizardState` owns step chrome, gates, review, failure, and progress outcomes. The host owns field values, validation messages, persistence, and submission effects.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `blocks/form-wizard`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn form_wizard_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let mut state = FormWizardState::with_steps([
        WizardStep::new("account", "Account"),
        WizardStep::new("region", "Region").optional(true),
        WizardStep::new("confirm", "Confirm"),
    ]);
    state.set_focused(true);
    FormWizard::new(system).title("Connect").ascii(true).paint(
        area,
        frame.buffer_mut(),
        &mut state,
    );
}
```

## Migrated handbook guidance

# FormWizard

**Purpose.** Setup, onboarding, connections, migrations — multi-step chrome
with validation gates. Domain values stay in the host; paint fields into
`body_area()` after wizard chrome.


## Ownership

| Concern | Owner |
|---------|--------|
| Step titles, optional flags, progress ids | WizardStep / state |
| Field values, validation messages | Host Form / fields |
| Submit / async I/O / persistence | Host via outcomes |
| Side effects | **Never** in TermRock |

## Host loop

```rust
match state.handle_key(key) {
    FormWizardOutcome::StepChanged { .. } => {
        let _ = state.request_focus_field();
    }
    FormWizardOutcome::AsyncCheckRequested { generation, .. } => {
        host.validate_async(generation);
    }
    FormWizardOutcome::SubmitRequested => host.submit(),
    FormWizardOutcome::ProgressSaved { progress } => host.save(progress),
    FormWizardOutcome::Cancelled => host.close(),
    _ => {}
}
// resume:
state.restore_progress(&saved);
```
