## Usage

```rust
use termrock::layout::{
    Stack, Inline, FlexSize, Align, Justify, OverflowPolicy, direction_for_width,
};

let layout = Stack::new().gap(1).layout(area, &[
    FlexSize::Fixed(2),
    FlexSize::fill(),
    FlexSize::Fixed(1),
]);
let body = layout.get(1).unwrap();

let chips = Inline::new().wrap(true).gap(1).layout(area, &[
    FlexSize::Fixed(6),
    FlexSize::Fixed(6),
]);

// Responsive: stack when narrow, inline when wide
let layout = Stack::new()
    .responsive(area.width, 60)
    .gap(1)
    .layout(area, &[FlexSize::fill(), FlexSize::fill()]);

// Clip tail under pressure
let tight = Stack::new()
    .overflow(OverflowPolicy::ClipTail)
    .layout(area, &[FlexSize::Fixed(3), FlexSize::Fixed(3), FlexSize::Fixed(3)]);

// Intrinsic cross-axis size (non-stretch)
let row = Inline::new()
    .align(Align::Center)
    .layout_with_cross(area, &[FlexSize::Fixed(8)], &[1]);
```

## State and typed outcomes

The widget owns deterministic paint and layout. The host owns all surrounding state and effects; this demo intentionally exposes no fake cursor, click, or keyboard behavior.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
