## Live terminal (Ghostty-class)

Move the real roving cursor, activate an enabled row, or close and reopen the menu. Disabled rows are skipped.

<TerminalPreview story="menu/roving" interactive caption="Menu · Menu — persistent Rust preview; available actions appear below" />

## Usage

```rust
use termrock::style::DesignSystem;
use termrock::widgets::{Menu, MenuItem, MenuState};

let system = DesignSystem::default();
let items = [MenuItem::new("a", "Open")];
let mut state = MenuState::new();
Menu::new(&items, &system).render(area, buf, &mut state);
```

## Try it

- `↑↓`, wheel, or click moves the menu-local cursor.
- Enter activates; Escape closes. Use the shown trigger to reopen it.

Accepted actions update the same mounted Rust value. The status line shows the latest outcome; **Reset** creates a fresh instance.

## State and typed outcomes

`MenuState` owns open state, cursor, and hit rows. Scene focus and the effect behind `Activated(id)` remain host-owned.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Test recipe

Mount `menu/roving`, dispatch only the actions listed above, and assert both the returned outcome and changed Ratatui cells. Passive demos must reject input without trapping page navigation.
