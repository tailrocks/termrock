## Workflow

- `Enter expand/collapse`: invoke the focused public state-machine action and inspect its typed request.
- `wheel/↑↓ scroll`: move the pattern-owned viewport without scrolling the documentation page.
- `S stop request`: invoke the focused public state-machine action and inspect its typed request.
- `F full view`: forward this normalized action to the mounted public pattern state.

Accepted actions update the same persistent pattern instance in web docs and native Lookbook. Typed requests appear in the status line; the fixtures never authenticate, connect, execute, persist, or mutate external state.

## Ownership

TermRock owns composition, focus geometry, responsive layout, and reusable state transitions. The consuming application owns records, commands, persistence, secrets, authorization, and side effects.

## Migrated handbook guidance

# TerminalRunCard

Agent-card specialization of shell runs over the `TerminalOutput` substrate:
proposed vs executed command, edited approval, provenance, env redaction,
stdout/stderr, exit/signal, follow/scroll, and typed control requests.
Compact runs are one semantic status line; expanded runs continue the
tool-actor rail. Pass `.tick(frame_tick)` for deterministic running presence.


## When to use / when not

| Use TerminalRunCard | Prefer |
|---------------------|--------|
| Shell tools in agent transcript | — |
| Full command workbench pane | [TerminalOutput](/docs/components/terminal-output) |
| Non-shell tool calls | [ToolCallCard](/docs/interaction-notes) |
| Multi-source logs | [LogStream](/docs/components/log-stream) |

## Phases

`Proposed` · `EditedApproval` · `Executed` — always keep proposed text when it
differs from executed.

## Safety

- No process/PTY in TermRock
- Outcomes request stop/detach/retry/permission/copy/fullscreen only
- Env/command copy paths redaction-assisted; host pre-redacts

## Keys

Enter expand · `c` stop · `r` retry · `d` detach · `p` permission · `f`/Shift+F fullscreen · `y` copy command · scroll detaches follow
