# DataTable

**Purpose.** Show multi-column data at scale without allocating or painting the
entire universe. TermRock owns chrome (header, selection, load states); you own
query, sort, filter, and `project(start..end)`.

Today’s handbook covers **`DataTable` + `data_view` kits** and the mature
`Table` widget. Prefer `VirtualWindow` for 10k–1M logical rows.

## When to use / when not

| Use DataTable / Table | Prefer |
|----------------------|--------|
| Relational grids, query results | — |
| Sort/filter chrome outcomes | Consumer executes sort |
| Simple vertical navigation | [List](/docs/handbook/list) |
| Hierarchy | Tree / TreeTable |
| Key/value object detail | DetailTable / ObjectInspector |

## Basic example

```rust
use termrock::widgets::{VirtualWindow, data_view_bench};

// Logical 1M rows — never allocate 1M cells in TermRock.
let mut window = VirtualWindow::new(data_view_bench::ROWS_1M, 40);
let (start, end) = window.visible_range();
assert!(end - start <= 40);
// consumer: project only [start, end)
let _ = window.scroll_by(100);
```

## Interactive example

```rust
use ratatui_core::text::Line;
use termrock::{
    input::{KeyCode, KeyEvent, KeyModifiers},
    style::DesignTokens,
    widgets::{CellAlignment, Column, ColumnWidth, Table, TableRow, TableState},
};

let tokens = DesignTokens::default();
let columns = [Column::new("name", Line::from("Name"), ColumnWidth::Min(12))];
let cells = [Line::from("alpha")];
let rows = [TableRow::new("r1", &cells)];
let table = Table::new(&columns, &rows, &tokens);
let mut state: TableState<&str, &str> = TableState::new(Some("r1"));
let _ = (
    table,
    state.handle_key(&rows, KeyEvent::new(KeyCode::Down, KeyModifiers::NONE)),
    CellAlignment::Left,
);
```

## Anatomy

`toolbar?` · **sticky header** · body viewport · footer (count / load) ·
selection gutter · optional expand detail  

Pinned columns stay outside horizontal scroll when using column kits.

## Public API

| API | Why |
|-----|-----|
| `VirtualWindow` | O(1) visible range over 1M logical rows |
| `DataTableState::set_logical_rows` | Universe size without row alloc |
| `DataTableOutcome::SelectAllRequested` | Never invent unloaded ids |
| `ColumnModel::contract_to_budget` | Responsive drop of low-priority columns |
| `Table` | Mature interactive grid when rows are resident |

## State ownership

| TermRock | Consumer |
|----------|----------|
| Window offset, focus, selection chrome | Dataset, sort, filter execution |
| LoadState paint | Fetch / stream / error messages |
| | Clipboard write for Copy payloads |

## Typed outcomes

`DataTableOutcome` / table `Outcome`: sort/filter **requests**, activate,
toggle, copy, expand — effects stay outside.

## Variants

- Load: Idle / Loading / Partial / Ready / Empty / Error.  
- Selection: row / multi / cell (kits).  
- Density: Compact vs Comfortable.

## Sizes

Min ~ header + 2 body rows. Wide terminals enable more columns; narrow contracts
by priority.

## Density

Compact reduces pad; still one body line per row for virtualization.

## Keyboard

Arrows, Page, Home/End, Space multi-toggle, Enter activate, `s` sort request,
`/` filter request, `c` copy, Shift+expand (DataTable shell).

## Mouse

Header sort clicks, row select, wheel scroll (breaks follow if used in streams).

## Focus

Table is a pane target; cell/row focus separate from selection set.

## Responsive

`contract_to_budget` drops low priority first; primary id columns pin high
priority. Story: `data-table/narrow-priority`.

## Accessibility / colorless

Selection gutter glyphs; sort `▲`/`^`; load/error text not color-only.

## Unicode

Stories: `data-table/cjk`, `data-table/combining`. Measure with display cols.

## Composition

Ops dashboards, ResourceBrowser, agent DiffReview neighbors, Workbench panes.

## Theming

`Role::TextStrong` header, `Role::Selection` / `Focus`, `Role::Danger` errors.

## Custom recipe

```rust
// Project only the window — never build Vec of logical_len in the widget.
use termrock::widgets::VirtualWindow;
let w = VirtualWindow::new(1_000_000, 40);
let (a, b) = w.visible_range();
assert!(b - a <= 40);
```

## Common mistakes

- Materializing all rows for paint.  
- Select-all that scans unloaded pages.  
- Re-sorting inside the widget on every key.

## Complete application example

```text
query → total_count → state.window.logical_len = total
each frame: project(visible_range) → DataTable/Table::render
on SortRequested → re-query → reset window offset carefully
on SelectAllRequested → select only projected ids
```


## Cursor vs scene focus (0068)

Use `cursor_row` / `CursorMoved` for in-table navigation. Host owns surface focus via `focused(bool)` + `accepts_input`.
