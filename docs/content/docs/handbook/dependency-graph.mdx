# DependencyGraph

Terminal-constrained dependency viewer. Host projects nodes and directed edges;
TermRock applies a **deterministic layered layout** (or falls back to tree/list
when the canvas is unreadable) and emits selection/detail outcomes.

## When to use / when not

| Use DependencyGraph | Prefer |
|---------------------|--------|
| Package / service / schema / task deps | — |
| Pure hierarchy without edges | [Tree](/docs/handbook/tree) / [TreeTable](/docs/handbook/tree-table) |
| Catalog browser | [SchemaBrowser](/docs/handbook/schema-browser) |

## Ownership

| Concern | Owner |
|---------|--------|
| Resolve packages / build graph | Host |
| Layout, pan, view mode, filter | `DependencyGraphState` |
| Details side panel | Host via `DetailsRequested` |

## Readability fallback

Graph view is **not** a general drawing engine. Auto-fallback to **Tree** when:

- width ≤ 40, or  
- node count > 48, or  
- `force_tree`

Host may still force List via `preferred_view`.

## Layout honesty

Layered placement is deterministic topological layering — good enough for
moderate DAGs and service maps, not for dense cyclic graphs. Cycles get residual
layer assignment by id order.
