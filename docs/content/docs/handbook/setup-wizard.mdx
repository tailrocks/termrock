# SetupWizard

Source-owned onboarding block (migration `0238`). Composes **FormWizard** +
**Stepper** with step-kind body paint. Domain values and auth stay host-owned.

## Live terminal (Ghostty-class)

One focused interactive surface — the same TermRock paint path as the lookbook
and [Components](/docs/components) pages. **Not SVG.** Focus the frame; use keys
or click to step multi-state packs when available.

<TerminalPreview story="setup-wizard/welcome" interactive caption="SetupWizard · setup-wizard/welcome — Ghostty truecolor focus surface" />

## When to use

| Use SetupWizard | Prefer |
|-----------------|--------|
| First-run product setup | Single-step Form / Dialog |
| Multi-phase onboarding with resume | FormWizard alone for generic multi-step |
| Inline setup in a pane | Fullscreen app root mode |

## Step kinds

Welcome · Capability · Account · Connection · Choices · Validation · Permission · Theme · Summary · Recovery · Custom

## Modes

- **Fullscreen** — root first-run with small safe margin  
- **Inline** — fill host pane  

## Laws

| Law | Detail |
|-----|--------|
| Safe cancel | Esc → confirm strip; never one-shot leave |
| Resume | `WizardProgress` chrome only |
| Keyboard-only | Enter/n next · p back · s skip · Ctrl+S save progress |
| No marketing splash | One-line welcome detail |

## Minimal host loop

```rust
use termrock::patterns::{
    SetupWizardState, SetupWizardSurfaces, example_setup_steps,
    example_capability_lines, render_setup_wizard,
};
use termrock::widgets::BUILTIN_THEME_PRESETS;

let mut state = SetupWizardState::from_steps(example_setup_steps())
    .with_title("First run");

render_setup_wizard(buf, area, SetupWizardSurfaces {
    system: &system,
    state: &mut state,
    fieldsets: &fieldsets_for_step,
    capabilities: &example_capability_lines(),
    summary_lines: &summary,
    welcome_title: "Setup",
    welcome_detail: "Configure once. Keyboard-first.",
    theme_presets: BUILTIN_THEME_PRESETS,
    theme_paint: Some(&system),
    permission: None,
});
```
