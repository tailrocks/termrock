## Try it

- `type or paste secret`: Focus the editable field, then type or paste Unicode text; the draft remains visible.
- `Alt+R reveal/mask`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `click reveal`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `Enter submit`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

`PasswordInputState` owns masked draft, caret, reveal policy, and clipboard gates. The host owns authentication/submission and must never log the secret. Demo outcomes are redacted.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `password-input/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn password_input_basic_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let mut state = PasswordInputState::with_secret("hunter2");
    state.set_focused(true);
    let _ = PasswordInput::new("Password", system)
        .placeholder("Enter secret…")
        .ascii(true)
        .paint(area, frame.buffer_mut(), &mut state);
}
```

## Migrated handbook guidance

# PasswordInput

**Purpose.** Credential and token fields that must not leak through paint (when
masked), `Debug`, semantic scene, or outcome payloads.


## When to use / when not

| Use PasswordInput | Prefer |
|-------------------|--------|
| Passwords, API tokens, recovery codes | — |
| Non-secret masked demo only | `TextInput::secret` paint mask |
| Multi-line secrets | avoid — use single-line tokens or host file |

## Security contract

| Channel | Behavior |
|---------|----------|
| Paint | Mask graphemes unless reveal policy shows plaintext |
| `Debug` | Redacted (`filled`, policies only) |
| Semantic scene | Labels like `password masked` — never value |
| Outcomes | No secret strings; `Submitted` is a signal |
| Clipboard | Default paste-only; copy never embeds secret |
| Drop | `secure_clear` overwrites buffer + undo snapshots |

## Policies

### Reveal

- `Never` (default)
- `Explicit` — Alt+R or reveal glyph
- `Hold` — Alt+H press/release

### Clipboard

- `DenyAll`
- `PasteOnly` (default)
- `AllowHostCopy` — `ClipboardCopyAllowed`; host may call `secret()` carefully

## Example

```rust
use termrock::{
    style::DesignSystem,
    widgets::{
        ClipboardPolicy, PasswordInput, PasswordInputOutcome, PasswordInputState,
        PasswordStrengthHint, RevealPolicy,
    },
};

let system = DesignSystem::default();
let mut state = PasswordInputState::new()
    .with_reveal_policy(RevealPolicy::Explicit)
    .with_clipboard_policy(ClipboardPolicy::PasteOnly);
state.set_focused(true);
match state.handle_key(/* … */) {
    PasswordInputOutcome::Submitted => {
        let secret = state.take_secret();
        // authenticate; never log secret
        let _ = secret;
    }
    _ => {}
}
let _ = PasswordInput::new("Password", &system)
    .strength(PasswordStrengthHint::Weak);
```
