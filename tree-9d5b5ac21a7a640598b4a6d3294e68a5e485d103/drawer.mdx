## Usage

The Code view above and this source excerpt use the exact paint setup registered for `drawer/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn drawer_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let mut state = termrock::widgets::DrawerState::new();
    state.open();
    state.set_header_rows(1);
    state.set_footer_rows(1);
    Drawer::new("Inspector", system)
        .footer(Some("esc · [ ] resize"))
        .paint(area, frame.buffer_mut(), &mut state);
    let body = state.body_area();
    if !body.is_empty() {
        frame.buffer_mut().set_stringn(
            body.x,
            body.y,
            "filters · details",
            usize::from(body.width),
            system.style(termrock::style::Role::Text),
        );
    }
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
