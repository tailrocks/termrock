## Usage

The Code view above and this source excerpt use the exact paint setup registered for `button-group/dialog`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn button_group_dialog_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let items = [
        ButtonGroupItem::new("cancel", "Cancel"),
        ButtonGroupItem::destructive("delete", "Delete"),
        ButtonGroupItem::primary("save", "Save").leading("✓"),
    ];
    let mut state = ButtonGroupState::new();
    state.set_surface_focused(true);
    state.cursor = Some("save");
    let _ =
        ButtonGroup::new(&items, system)
            .separated()
            .paint(area, frame.buffer_mut(), &mut state);
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
