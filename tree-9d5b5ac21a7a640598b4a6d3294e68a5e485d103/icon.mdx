## Usage

The Code view above and this source excerpt use the exact paint setup registered for `icon/browser`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn icon_browser_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    use termrock::style::{Glyph, GlyphGroup, Role};
    use termrock::widgets::Icon;
    let mut y = area.y;
    for group in GlyphGroup::ALL {
        if y >= area.bottom() {
            break;
        }
        frame.buffer_mut().set_stringn(
            area.x,
            y,
            group.id(),
            usize::from(area.width),
            system.style(Role::TextMuted),
        );
        y = y.saturating_add(1);
        let mut x = area.x;
        for g in Glyph::in_group(group) {
            if y >= area.bottom() {
                break;
            }
            let w = 4u16;
            if x.saturating_add(w) > area.right() {
                x = area.x;
                y = y.saturating_add(1);
                if y >= area.bottom() {
                    break;
                }
            }
            let _ = Icon::new(g, system).min_width(w).paint(
                Rect {
                    x,
                    y,
                    width: w,
                    height: 1,
                },
                frame.buffer_mut(),
            );
            x = x.saturating_add(w);
        }
        y = y.saturating_add(1);
    }
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
