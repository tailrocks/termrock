# 0295 — Underline means "link", and nothing else

`Modifier::UNDERLINED` was doing the work of nine different cues — focus,
selection, hover, current item, sort, severity, match highlight, syntax class,
button affordance — across 44 widget files, while `Role::Link` itself was not
underlined in any color palette. Underline meant everything except the one
thing a reader expects it to mean.

The binding grammar is `docs/design/termrock-design-language.md` §5.9: a border,
a gutter, or a glyph — never an underline. Underline survives only in content
passthrough, in monochrome links, and as an explicit cursor fallback.

## What replaced what

| Old cue | Now |
|---------|-----|
| Focused button (Outline / Quiet / Secondary / IconButton) | bold label; the recipe's border already moved |
| Pressed button, latched icon button | `REVERSED` (the press is when it goes solid) |
| Focused field label (text, number, search, select, combobox, multi-select, token, path, slider) | bold label; the field's own border carries focus |
| Focused checkbox / radio / switch / toggle / segmented label | `Role::Focus` + bold (mono adds `REVERSED` for segmented) |
| Hovered control label | `Role::TextStrong` (no rule), or the `HoverTint` wash where a rect exists |
| Cell cursor (`table`, `data_table`, `tree_table`) | `REVERSED` on the one cell |
| OTP slot cursor | `REVERSED` slot |
| Current page / crumb / step / viewer chrome | bold (`REVERSED` for the viewer title, which owns keys) |
| Selected row wash (`markdown`, `key_value_list`) | `Role::SelectionTint` bg + `▌` gutter, each cell keeping its own foreground |
| Match highlight (`text`) | accent foreground + bold |
| Code search highlight | `HoverTint` ground + bold |
| Word diff | the diff tints plus bold |
| Mono severity (`identity`, `keyboard_help`) | `REVERSED` / `Role::Warning` + bold |
| Markdown emphasis | `ITALIC` only |
| Inline code span | `Role::Info` tone (still no filled background) |
| "Today" in the date picker | `Role::Accent` (a fact about the date, not a selection) |
| Mono `SyntaxString` | `ITALIC` |

`markdown::underline_row` is now `markdown::select_row` (private).

## `LinkStyle` replaces `LinkVariant::Underline`

Links get an explicit policy instead of a shape variant that meant paint:

```rust
// Before
Link::url("docs", "https://example.com", &system).variant(LinkVariant::Underline);
// After — the default is color + the `↗` external cue, no underline
Link::url("docs", "https://example.com", &system);
// Classic web link:
Link::url("docs", "https://example.com", &system).link_style(LinkStyle::AlwaysUnderline);
// Underline only under the pointer / keyboard:
Link::url("docs", "https://example.com", &system).link_style(LinkStyle::UnderlineOnHover);
```

`LinkVariant` keeps only its shape arms (`Plain` — now the default — and
`Bracketed`); `LinkVariant::Underline` is removed. Focus no longer underlines a
link (bold already carried it). **Monochrome always underlines**, whatever the
policy says: without color there is nothing else that marks a link.
`Citation` renders with `LinkStyle::AlwaysUnderline`.

## The code tokenizer returns kinds, not styled guesses

`TokenSyntax` used to encode "this is a string" as green-plus-underline, and
`RoleTokenSyntax` decoded that back by sniffing modifiers — so changing the
paint silently changed the classification.

```rust
// New: the classification is the fact
pub enum CodeTokenKind { Plain, Comment, String, Number, Keyword, Function }
impl CodeTokenKind { pub const fn role(self) -> Role; }

let tokens = TokenSyntax::rust().tokens_for_line(line); // Vec<(&str, CodeTokenKind)>
```

`SyntaxHighlighter::highlight_line` is unchanged for both types; `TokenSyntax`
maps kinds to palette-free fallback colors, `RoleTokenSyntax` maps them through
`syntax_role_style`. Hosts that matched on the old sentinel styles should match
on `CodeTokenKind` instead.

## Sanctioned survivors

A source-scan gate, `design_gate::interaction_underline_is_dead`, fails the
build if underline reappears outside this whitelist:

| File | Why |
|------|-----|
| `link.rs` | the link affordance itself (`LinkStyle`) |
| `citation.rs` | a citation is a link |
| `key_value_list.rs` | `href` values are links |
| `primitives.rs` | `ButtonVariant::Link` renders as a link |
| `code_block.rs` | diagnostic spans — squiggle substitute (§5.9) |
| `text.rs` | `TextSpan::underline` is author-set content, not a state |

Outside `widgets/`: `ansi_text` (SGR-4 / OSC-8 passthrough) and the `Link` /
`LinkHover` entries of the ANSI and high-contrast palettes.

## Deferred

Markdown emphasis now emits `ITALIC` with no fallback: TermRock has no
capability flag for "terminal cannot render italics" yet, so the underline
fallback was dropped rather than guessed. Adding that flag is follow-up work.
