# 0243 — FileManager composition block

## Mission

Complete **file-management composition**: breadcrumbs, file tree/list, preview,
quick open, search, multi-select, operation queue, status bar, and
confirm/conflict dialogs. Responsive multi-pane → single-pane/drawer. Copy,
move, delete, rename, and new as **typed requests**. **Filesystem I/O stays
application-owned**.

Research: Yazi, ranger, lf, broot, desktop file managers (interaction and paint
performance references only — not a clone API).

## Preserve / migrate / split / delete

| Surface | Fate |
|---------|------|
| `FileTree` / `FileTreeState` / create/rename/delete/filter/confirm | **Preserved** — composed |
| `Breadcrumbs` / `breadcrumbs_from_path` | **Preserved** — path chrome |
| `SearchInput` | **Preserved** — filter bar |
| `PreviewCard` / `PreviewCardContent` | **Preserved** — selection preview |
| `QuickOpen` / `file_tree_to_quick_open_items` | **Preserved** — palette overlay |
| `List` | **Preserved** — operation queue rows |
| `AlertDialog` | **Preserved** — elevated confirm / conflict |
| `StatusBar` | **Preserved** — summary chrome |
| `layout_resource_browser` / `ResourceBrowserSlots` / `wire_resource_preview` | **Preserved** — thin AppShell geometry only; **not** dual interactive path |
| `ResourceBrowserState` (widgets/blocks) | **Preserved** — generic sidebar/detail; not elevated FileManager |
| Local re-paint of tree/preview | **Forbidden** |
| `std::fs` walkers / trash / recursive delete | **Host-owned** |
| `FileManagerState` · `render_file_manager` | **Added** (`patterns/file_manager`) |

    example_quick_open_from_entries, seed_conflict_state,
    render_file_manager, file_manager_layout_density,
};

let mut state = FileManagerState::new();
state.cwd = "/project".into();
// state.density = Some(FileManagerDensity::Narrow);

let entries = example_file_entries();
let ops = example_file_ops();
let (preview, _, _) = example_file_preview();
let qo = example_quick_open_from_entries(&entries);

render_file_manager(buf, area, FileManagerSurfaces {
    system: &system,
    state: &mut state,
    entries: &entries,
    ops: &ops,
    preview: Some(preview),
    quick_open_items: &qo,
});

match state.handle_key(key, &entries, &ops, &qo) {
    FileManagerOutcome::CopyRequested { sources, dest } => { /* host copy */ }
    FileManagerOutcome::MoveRequested { sources, dest } => { /* host move */ }
    FileManagerOutcome::DeleteRequested { ids } => { /* host delete */ }
    FileManagerOutcome::RenameRequested { id, from, to } => { /* host rename */ }
    FileManagerOutcome::NewRequested { kind, parent, name } => { /* host create */ }
    FileManagerOutcome::OpCancel { op_id } => { /* cancel queue item */ }
    FileManagerOutcome::OpRetry { op_id } => { /* retry failed */ }
    FileManagerOutcome::ConflictResolved { op_id, resolution } => { /* apply */ }
    FileManagerOutcome::Navigate { path } => { /* re-list */ }
    FileManagerOutcome::FilterChanged { query } => { /* reproject */ }
    _ => {}
}

### Densities

| Density | Width | Panes |
|---------|-------|-------|
| `Normal` | ≥ 96 | Breadcrumbs · Search · Tree · Preview · Queue · Status |
| `Narrow` | 52–95 | Breadcrumbs · Search · Tree · Status; Preview drawer (`p` / drawer_open) |
| `Tiny` | < 52 | Search · Tree · Status |

### Laws

| Law | Detail |
|-----|--------|
| Public only | Composes public widgets; no tree/preview paint forks |
| Host FS | Outcomes are requests only; queue progress is host-projected |
| Density=None | Last paint width drives collapse; Tab clamps to visible panes |
| Keyboard parity | Yank/cut/paste/delete/rename/new/preview have status-documented keys |
| Clipboard | `y` yank (copy), `x` cut (move), `v` paste → Copy/MoveRequested |

## Second-pass design review

**Decisions**

1. Elevated pattern peer to Git/Observability workbench — not a second
   `resource_browser` interactive path.
2. Keep `layout_resource_browser` as thin geometry; interactive surface is
   FileManager.
3. Operation queue is host-owned `FileOpItem` list painted via `List` — no
   in-crate FS worker.
4. FileTree owns create/rename/delete/filter/confirm banner; workbench elevates
   multi-delete and conflicts to `AlertDialog`, and owns cut/paste clipboard
   → Copy/MoveRequested.
5. Yazi/ranger/lf inform density and keyboard discoverability, not keymap clone.

**Rejected**

- Embedding walkdir / recursive delete / trash backends.
- Forking FileTree or PreviewCard paint bodies into the pattern.
- Dual-tab Yazi model or plugin system as TermRock API.
- Replacing resource_browser without preserving layout helper.

**Residual limits**

- Preview body is host-projected (`PreviewCardContent`); workbench does not
  read file bytes.
- QuickOpen search results are host-supplied items; palette does not walk FS.
- PTY/fuzz not required; unit + structural gates cover interaction.
