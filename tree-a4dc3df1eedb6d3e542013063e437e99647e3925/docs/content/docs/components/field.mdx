This preview is a persistent Rust demo. Focus it, then use the exact actions shown below; Reset remounts fresh state.

## Usage

```rust
use termrock::widgets::{Field, FieldStatus};

Field::new("email", "Email", value)
    .required(true)
    .help("Work address")
    .error("invalid")      // or .warning / .pending
    .dirty(true)
    .touched(true);
```

## Status

| Variant | Meaning |
|---------|---------|
| `Help` | Neutral help |
| `Warning` | Non-blocking |
| `Error` | Blocking validation |
| `Pending` | Async validation |

Compose inside [`Fieldset`](/docs/components/fieldset) / [`Form`](/docs/components/form). Caption-only chrome without a value row: [`FieldCaption`](/docs/components/field-caption) (Label + Description).

## State and typed outcomes

The demo owns ephemeral widget state between events. The widget owns painted geometry, focus/selection mechanics, and typed outcomes. The host owns domain effects and decides what an emitted outcome means to the application.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Test recipe

Mount `text-input/basic`, dispatch only the actions listed above, and assert both the returned outcome and changed Ratatui cells. Passive demos must reject input without trapping page navigation.
