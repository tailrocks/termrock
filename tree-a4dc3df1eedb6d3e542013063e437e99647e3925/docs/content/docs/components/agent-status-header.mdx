## Live terminal (Ghostty-class)

This is a persistent sample-application demo. Navigate rows, filter through a real TextInput, toggle the sidebar region, and open the effect-free action dialog.

<TerminalPreview story="agent-status-header/basic" interactive caption="AgentStatusHeader · shared Rust demo" />

## Usage

```rust
use termrock::widgets::{
    example_agent_status, AgentStatusHeader, AgentStatusHeaderOutcome,
    AgentStatusHeaderState, AgentStatusAction,
};

let mut state = AgentStatusHeaderState::new();
state.set_snapshot(example_agent_status());
AgentStatusHeader::new(&system).paint(area, buf, &mut state);

match state.handle_key(key) {
    AgentStatusHeaderOutcome::Action(AgentStatusAction::Sessions) => {}
    _ => {}
}
```

## Try it

- `Enter open action` or `click trigger` opens a real ChoiceDialog.
- `S toggle sidebar region` changes visible chrome.
- `↑↓/wheel select row` changes persistent selection.
- `/ filter` focuses a real TextInput; type or paste, then apply with Enter.

Accepted actions update the same mounted Rust value. The status line shows the latest outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted Rust demo owns deterministic sample state. The component/pattern owns its reusable paint and interaction contracts; the consuming host owns domain policy and every external effect.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Test recipe

Mount `agent-status-header/basic`, dispatch only the actions listed above, and assert both the returned outcome and changed Ratatui cells. Passive demos must reject input without trapping page navigation.
