## Try it

- `←→ resize`: Press, drag, and release on the visible handle; geometry/value follows the pointer.
- `Home/End collapse`: Move through the real focus/selection model; the next action uses the new target.
- `drag divider`: Press, drag, and release on the visible handle; geometry/value follows the pointer.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The demo owns ephemeral widget state between events. The widget owns painted geometry, focus/selection mechanics, and typed outcomes. The host owns domain effects and decides what an emitted outcome means to the application.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `split-pane/horizontal`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn split_pane(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let mut state = SplitPaneState::new(SplitRatio::from_percent(38));
    render_split_pane(frame, area, &mut state, system);
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
