## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

<TerminalPreview story="quick-open/basic" interactive caption="QuickOpen · QuickOpen files — live shared Rust state" />

## Try it

- `type to filter`: Focus the editable field, then type or paste Unicode text; the draft remains visible.
- `↑↓ select`: Move through the real focus/selection model; the next action uses the new target.
- `Enter open`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `Ctrl+N/P provider`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `click result`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted widget owns interaction state, focus chrome, hit geometry, and typed outcomes. The host only forwards backend-neutral events and performs no external effects.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `quick-open/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn quick_open_basic(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let providers = example_quick_open_providers();
    let items = example_quick_open_files();
    let mut state = QuickOpenState::new();
    state.set_focused(true);
    let _ = state.apply_results(0, &items, true, Some(items.len() as u64));
    QuickOpen::new(&providers, &items, system).paint(area, frame.buffer_mut(), &mut state);
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
