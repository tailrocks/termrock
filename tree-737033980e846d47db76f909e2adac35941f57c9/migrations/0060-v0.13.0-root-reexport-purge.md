# 0060 — Crate root re-export purge (pre-1.0 Break A)

## Removed surface

All blanket `pub use` re-exports from `crates/termrock/src/lib.rs`:

- `termrock::{…}` capability types (`CapabilityOverrides`, `resolve_capabilities`, …)
- `termrock::{…}` interaction types (`InteractionScene`, `OverlayStack`, `UiIntent`, `FocusRing`, …)
- `termrock::{…}` layout types (`WIDTH_LADDER`, `ViewportClass`, …)
- `termrock::{…}` perf types (`StreamCoalescer`, `FollowMode`, …)
- `termrock::{…}` style types (`Theme`, `DesignTokens`, `DesignSystem`, `Role`, `Density`, …)

The crate root still **exports modules** only. Types are not available as
`termrock::Theme` / `termrock::OverlayStack` / etc.

Crate docs no longer claim “Entry point: Theme”. Entry surfaces are module-path
only: `style::DesignSystem` (paint authority after later milestones),
`interaction::InteractionScene`, `interaction::OverlayStack`, `runtime::run`.

## Canonical replacement

| Was | Now |
|-----|-----|
| `use termrock::Theme` | `use termrock::style::Theme` |
| `use termrock::DesignTokens` | `use termrock::style::DesignTokens` |
| `use termrock::DesignSystem` | `use termrock::style::DesignSystem` |
| `use termrock::Density` / `Role` | `use termrock::style::{Density, Role}` |
| `use termrock::OverlayStack` / `UiIntent` | `use termrock::interaction::{OverlayStack, UiIntent}` |
| `use termrock::FocusRing` | `use termrock::interaction::FocusRing` (removed in a later milestone) |
| `use termrock::WIDTH_LADDER` | `use termrock::layout::WIDTH_LADDER` |
| `use termrock::StreamCoalescer` | `use termrock::perf::StreamCoalescer` |
| `use termrock::resolve_capabilities` | `use termrock::capability::resolve_capabilities` |
| `use termrock::{Theme, widgets::List}` | `use termrock::style::Theme; use termrock::widgets::List` |

Widgets and other modules were already module-path (`termrock::widgets::…`,
`termrock::input::…`, `termrock::keymap::…`) — unchanged.

## Consumer edits

1. Search for `use termrock::{` and `termrock::Theme` / bare root type imports.
2. Move every previously re-exported type under its owning module path (table above).
3. Rebuild. No runtime or logic change is required for this migration alone.

### Before

```rust
use termrock::{Theme, OverlayStack, UiIntent, DesignTokens, List, Density};

let theme = Theme::default();
let tokens = DesignTokens::new(theme, Density::default());
```

### After

```rust
use termrock::interaction::{OverlayStack, UiIntent};
use termrock::style::{Density, DesignTokens, Theme};
use termrock::widgets::List;

let theme = Theme::default();
let tokens = DesignTokens::new(theme, Density::default());
```

## Removed concepts

- Flat crate-root type namespace as a public discovery path.
- Implicit “TermRock is a bag of types” import style.

Ownership signal is now visible: paint lives under `style`, focus/overlays under
`interaction`, host loop under `runtime`, widgets under `widgets`.

## Ownership changes

None. Types did not move between modules; only root re-export aliases were deleted.
