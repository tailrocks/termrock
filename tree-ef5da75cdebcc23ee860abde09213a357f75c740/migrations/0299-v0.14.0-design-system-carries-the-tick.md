# 0299 — The design system carries the frame tick

`MotionPolicy` already rode `DesignSystem` into every widget, but the *clock*
did not. Anything that wanted time had to take a `FrameTick` in its own
signature, so only a handful of widgets could animate at all, and the ones that
tried kept private copies of motion state that could — and did — disagree with
the system they were painted with.

## What changed

`DesignSystem` gains a tick:

```rust
// Once per frame, in the host's render function:
let system = base_system.clone().at(tick);

// Anywhere downstream:
let phase = MotionChannel::Live.phase(system.elapsed_ms());
```

| Item | Meaning |
|------|---------|
| `DesignSystem::at(FrameTick) -> Self` | supply this frame's time |
| `DesignSystem::tick() -> Option<FrameTick>` | the injected tick, if any |
| `DesignSystem::elapsed_ms() -> u64` | wall-clock phase source; `0` when no tick |

**`None` is the default and it means "paint the settled frame".** A widget must
never invent a clock during paint, and snapshot tests stay deterministic without
a special test mode: no tick, no motion.

Widgets that already take a `FrameTick` parameter keep it — this adds a channel,
it does not remove one.

## `DrawerState::set_motion` is removed

`DrawerState` kept its own `motion: MotionPolicy`, defaulted to `Full`
regardless of the design system it was painted with. A host that set
`DesignSystem::motion(MotionPolicy::Off)` still got animated drawer chrome
unless it *also* remembered to call `state.set_motion(..)`.

```rust
// Before
let mut state = DrawerState::new();
state.set_motion(MotionPolicy::Off);

// After — the tier already rides the system
let system = system.motion(MotionPolicy::Off);
```

The handle chrome now asks `system.motion.allows_ambient()`, so the tier has one
source of truth.

## Ownership and rollback

Hosts own the clock and sample it once per frame; TermRock never reads one.
Rollback is source-only.
