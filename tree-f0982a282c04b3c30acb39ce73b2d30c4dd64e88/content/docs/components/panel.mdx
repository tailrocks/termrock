## Live terminal (Ghostty-class)

This preview is a persistent Rust demo. Focus it, move between panels, then activate one with Enter or click; Reset restores the initial focus.

<TerminalPreview story="panel/focused" interactive caption="Panel · Focused panel — move focus and activate the selected surface" />

## Usage

```rust
use termrock::{layout::{panel_stack, PanelStackBlock}, style::{DesignSystem, PanelChrome}, widgets::{Panel, PanelBody, PanelVariant}};

let system = DesignSystem::default();
let rows = panel_stack(area, &[PanelStackBlock {
    content_rows: 3, chrome_rows: 2, min: 3, max: 8, visible: true,
}], 1);
let body = Panel::new(&system)
    .title("Inbox")
    .variant(PanelVariant::Bordered)
    .emphasis(PanelChrome::Focused)
    .body(PanelBody::Empty)
    .body_title("No messages")
    .paint(area, buf, None);
```

## Try it

- `arrow keys`: move the demo's semantic focus.
- `Enter activate`: emit the selected panel activation.
- `click`: focus and activate through the same public interaction path.

Accepted actions update the same mounted Rust value. The status line shows the latest outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The demo owns only ephemeral focus state. `Panel` owns border geometry and semantic focused/unfocused chrome; the host owns routing and any effect caused by activation.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
