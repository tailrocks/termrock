## Usage

```rust
use ratatui_core::text::Line;
use termrock::{style::DesignSystem, input::{KeyCode, KeyEvent, KeyModifiers}, widgets::{ListRow, Picker, PickerOutcome, PickerState, RowRole}};

let system = DesignSystem::default();
let candidates = [("open", "Open file"), ("logs", "Show logs")];
let project = |query: &str| candidates.iter()
    .filter(|(_, label)| label.to_lowercase().contains(&query.to_lowercase()))
    .map(|(id, label)| ListRow { id: *id, label: Line::from(*label), leading: None, secondary: None, badge: None, shortcut: None, trailing: None, role: RowRole::Item, enabled: true, loading: false })
    .collect::<Vec<_>>();
let mut state = PickerState::new(Some("open"));
let mut rows = project(state.query_text());
if matches!(state.handle_key(&rows, KeyEvent::new(KeyCode::Char('l'), KeyModifiers::NONE)), PickerOutcome::QueryChanged) {
    rows = project(state.query_text());
    state.reconcile(&rows);
}
let system = DesignSystem::default();
let picker = Picker::new(&rows, &system);
```

## State and typed outcomes

The demo owns ephemeral widget state between events. The widget owns painted geometry, focus/selection mechanics, and typed outcomes. The host owns domain effects and decides what an emitted outcome means to the application.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Test recipe

Mount `picker/basic`, dispatch only the actions listed above, and assert both the returned outcome and changed Ratatui cells. Passive demos must reject input without trapping page navigation.
