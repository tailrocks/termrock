## Workflow

- `Enter open action` or `click trigger` opens a real ChoiceDialog; confirm/cancel produce different outcomes.
- `S toggle sidebar region` changes the visible application chrome.
- `↑↓/wheel select row` changes the persistent row selection.
- `/ filter` focuses a real TextInput; type or paste, then Enter applies or Escape cancels.

The preview and native Lookbook instantiate the same Rust story and state machine. Outcomes appear in the preview status line.

## Ownership

TermRock owns composition, focus geometry, responsive layout, and reusable state transitions. The consuming application owns records, commands, persistence, secrets, authorization, and side effects.

## Migrated handbook guidance

# ProcessTable

Process / task monitoring table (btop/htop/procs class). Host projects
`ProcessRow` snapshots; TermRock paints, navigates, sorts/filters, and emits
**signal / refresh / details requests** — never enumerates processes or
sends signals itself.


## When to use / when not

| Use ProcessTable | Prefer |
|------------------|--------|
| Live process / task monitor | — |
| Generic multi-column hierarchy | [TreeTable](/docs/components/tree-table) |
| Flat data grid | [DataTable](/docs/components/data-table) |
| Log / output streams | [LogStream](/docs/components/log-stream) / [TerminalOutput](/docs/components/terminal-output) |

## Ownership

| Concern | Owner |
|---------|--------|
| Enumerate processes, metrics, kill/signal | Host |
| Cursor, multi-check, filter, sort, confirm chrome | `ProcessTableState` |
| Stable identity across PID reuse | Host supplies `ProcessKey` (pid + start marker) |

## Stable identity

Selection and multi-check key on `ProcessKey { pid, start_ms }`, **never PID
alone**. When a process exits and its PID is recycled, the start marker differs
so selection does not silently retarget.

On host refresh, call `state.reconcile(&live_rows)`: matching keys are kept;
missing selection falls to nearest-neighbor; checked set drops dead keys.

## Outcomes (requests)

- `SelectionChanged` · `CheckToggled` · `ExpandToggled`
- `DetailsRequested` · `SortChanged` · `ViewModeChanged`
- `FilterChanged` · user/status filters
- `SignalRequested { keys, signal }` (after confirm when destructive/multi)
- `ConfirmRequired` / `ConfirmCancelled`
- `RefreshRequested` · `CopyCommand` · `Scrolled`
