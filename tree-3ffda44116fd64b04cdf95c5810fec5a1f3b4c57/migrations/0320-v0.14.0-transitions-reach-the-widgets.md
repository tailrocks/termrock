# 0320 — Transitions reach the widgets

The motion kernel landed in 0289 and the tick seam in 0299; the widget seams
waited on the row-chrome and overlay rewrites. These are those seams: the
places where a state change had time available and snapped anyway.

## Behavior changes

**Focus borders cross-fade.** `Border → BorderFocused` is the brightest change
a pane makes, and it happened in one frame. The blend lives in the recipes, so
all sixteen panel consumers and every input inherit it:

```rust
let recipe = system.panel_recipe_at(PanelChrome::Focused, elevation, settled);
let field  = system.input_recipe_at(ControlState::Focused, invalid, settled);
```

`settled` is `0.0` at the start of the change and `1.0` when it has arrived;
the existing `panel_recipe` / `input_recipe` are the settled call. Under
`MotionPolicy::Off` or `Basic` the blend is skipped entirely.

**Tab fills arrive.** `TabsState` records the tab being left and when, and the
active pill blends in over 100 ms (`mark_changed_at`, `blend_fraction`).

**The mode chip fades.** `StatusBarState::set_mode(mode, elapsed_ms)` records a
mode change; the chip fades from the canvas over 120 ms instead of swapping in
one frame.

**Determinate progress springs.** A determinate bar reported its target
fraction directly, so a jump from 0 % to 60 % painted as a jump — and a host
reporting every byte made the bar strobe. `displayed_fraction(motion)` advances
a critically-damped spring toward the target, and `is_active()` is now true
while the two differ, so the bar asks for the frames it needs. Reduced motion
settles immediately.

**Sections reveal.** `Collapsible::reveal_rows(state, rows, elapsed_ms, motion)`
returns how many body rows to paint this frame, driven by
`CollapsibleState::mark_toggled_at`. Accordion inherits it. A host that never
marks a toggle gets the settled count.

**Backdrops arrive.** `Backdrop::alpha(alpha, tokens)` blends the wash toward
the canvas, so a modal's ground fades in rather than the lights going out.

**Drawer documentation.** The module said "terminals do not slide-animate",
which contradicted the motion law: there is no slide *geometry*, but the panel
does fade. The doc says that now.

## New surface

- `DesignSystem::{panel_recipe_at, input_recipe_at, blend_role}`
- `TabsState::{mark_changed_at, blend_fraction}`
- `StatusBarState::{set_mode, mode_fade}`
- `ProgressBarState::displayed_fraction`
- `CollapsibleState::{mark_toggled_at, reveal_fraction}`, `Collapsible::reveal_rows`
- `Backdrop::alpha`

## Breaking changes

- `ProgressBar::from_state` and `ProgressBarState::kind` take `&mut
  ProgressBarState` — the spring advances during projection.
- A determinate `ProgressBarState` reports `is_active() == true` while its
  painted fraction is catching up; hosts that asserted determinate bars never
  demand redraw must let it settle first.
