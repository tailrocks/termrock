# 0327 — Tabs restore the focus-aware selection rule

**Version:** `v0.14.0`
**Kind:** behavioral

`Tabs::new` now defaults to `TabsActiveCue::Rule` instead of
`TabsActiveCue::AccentPill`. The selected tab has a bottom border-glyph rule:

- `Role::Accent` while the selected tab owns keyboard focus;
- `Role::Border` while the strip is unfocused.

This restores a persistent selected-tab cue without conflating keyboard focus
with selection. Hover, overflow, manual activation, close controls, and every
alternate active cue remain unchanged.

Consumers that deliberately want the former fill should request it explicitly:

```rust
let tabs = Tabs::new(&items, &system)
    .active_cue(TabsActiveCue::AccentPill);
```

Consumers already selecting an explicit cue need no edit.
