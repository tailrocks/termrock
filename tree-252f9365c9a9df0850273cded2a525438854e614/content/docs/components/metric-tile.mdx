## State and typed outcomes

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `metric-tile/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn metric_tile_basic(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    const SAMPLES: &[f64] = &[38.0, 41.0, 39.0, 44.0, 47.0, 46.0, 52.0];
    MetricTile::new("latency", "p95 latency", "52ms")
        .delta("+8%", true)
        .samples(SAMPLES)
        .health(MetricTileHealth::Warning)
        .view(system)
        .paint(area, frame.buffer_mut());
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not put dashboard, alert-routing, or refresh policy into the tile.
- Do not encode health with color alone; use `MetricTileHealth` so glyph and style cues agree.
- Do not duplicate the tile paint inside a composite; compose this public building block.

## Test recipe

Render card and row presentations at narrow and regular widths. Assert the value, health cue, and sample trend remain deterministic under Unicode and ASCII glyph profiles.
