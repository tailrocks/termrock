## Usage

```rust
use termrock::{style::DesignSystem, widgets::{QuestionFlow, QuestionOption, QuestionStep}};

let system = DesignSystem::default();
let opts = [QuestionOption { id: "y", label: "Yes" }];
let steps = [QuestionStep { id: "q1", prompt: "Continue?", options: &opts, required: true }];
let flow = QuestionFlow::new(&steps, &system);
```

## Try it

- No actions. This component is passive in this demo; the page remains navigable.

Accepted actions update the same mounted Rust value. The status line shows the latest outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The widget owns deterministic paint and layout. The host owns all surrounding state and effects; this demo intentionally exposes no fake cursor, click, or keyboard behavior.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Test recipe

Mount `question-flow/basic`, dispatch only the actions listed above, and assert both the returned outcome and changed Ratatui cells. Passive demos must reject input without trapping page navigation.
