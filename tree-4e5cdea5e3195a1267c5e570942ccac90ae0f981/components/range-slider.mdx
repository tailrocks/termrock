## Try it

- Tab switches the active thumb; `←→` and Home/End change its value.
- Drag either handle to update the same bounded range.

Accepted actions update the same mounted Rust value. The status line shows the latest outcome; **Reset** creates a fresh instance.

## State and typed outcomes

`RangeSliderState` owns active thumb, range, drag, hover, and focus. The host consumes `ValueChanged`/`ThumbChanged` and decides how the range filters domain data.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Test recipe

Mount `range-slider/basic`, dispatch only the actions listed above, and assert both the returned outcome and changed Ratatui cells. Passive demos must reject input without trapping page navigation.
