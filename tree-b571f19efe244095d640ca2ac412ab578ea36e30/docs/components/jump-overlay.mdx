## Usage

```rust
use ratatui_core::layout::Rect;
use termrock::{style::DesignSystem, widgets::{JumpOverlay, JumpOverlayState, JumpTarget}};

let system = DesignSystem::default();
let targets = [JumpTarget { id: "files", area: Rect::new(0, 0, 10, 1), badge: 'f' }];
let overlay = JumpOverlay::new(&targets, &system);
let mut state = JumpOverlayState::new();
state.open();
```

## Try it

- Use the actions shown beside the terminal; mouse, keyboard, paste, drag, and resize are forwarded only when the component supports them.
- Confirm the visual state and typed outcome, then use **Reset** to mount a fresh instance.

Accepted actions update the same mounted Rust value. The status line shows the latest outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted widget owns interaction state, focus chrome, hit geometry, and typed outcomes. The host only forwards backend-neutral events and performs no external effects.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
