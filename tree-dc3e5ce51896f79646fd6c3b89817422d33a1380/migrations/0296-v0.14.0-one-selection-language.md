# 0296 — One selection language for every collection

Selection was a per-widget invention. Nine collections hand-rolled the same
`match system.selection { … }` and repainted the whole row in `Role::Focus`, so
an error line stopped being red the moment the cursor landed on it. Sixteen
more painted a saturated `Role::Selection` slab. Five spelled "current row"
with five different glyphs (`›`, `>`, `•`, `▸`, `*`). The three table widgets
disagreed about their own headers.

They now share one language: **the gutter says selected, the ground says
membership, and the row keeps its own meaning.**

## Selection keeps severity

`widgets::row_chrome::RowChrome` (internal) resolves the shared
`ListRowRecipe` and returns a label style that preserves the row's semantic
foreground, adding weight and the recipe's ground. Adopted by `diff`,
`hex_viewer`, `log_stream`, `terminal_output`, `object_inspector`,
`event_stream`, `diagnostic`, `key_value_table` and `timeline`.

Visible effect: a selected error line stays red, a selected stderr line stays
stderr, a selected warning event keeps its severity — each gains the `▌` gutter
and the selection wash instead of losing its tone.

## `Role::Selection` is opt-in everywhere

These surfaces stop painting the saturated fill and read as a strong label on
`Role::SelectionTint`: `sidebar` (route), `tree_navigation` (route),
`menu_bar`, `menu_nav`, `command_palette`, `quick_open`, `completion_menu`,
`keyboard_help`, `notification_center`, `callout`, `progress_steps` (keeps its
status tone), `tag_chip`, `theme_picker`, `fullscreen_viewer`,
`prompt_composer` (text selection washes instead of slabbing), `data_table`
(selected cell), and `code_block`'s `CodeHighlightKind::Selection`.

## One gutter glyph

`glyphs.selection_gutter()` (`▌`, ASCII `*`) replaces the hand-rolled markers
in `completion_menu`, `checkpoint_timeline`, `data_table`, `object_inspector`,
`sidebar`, `search_results`, `review`, `tree_table`, `transcript`,
`theme_picker` and `detail_table`. `tree_table`'s inversion is fixed —
selection owns the gutter and "checked" is a check glyph, not a bar.
`streaming_markdown`'s caret moves to `▍` so it stops impersonating a selected
row. `design_gate::collections_share_one_gutter_glyph` renders List, Table,
Tree and Timeline side by side and fails if they diverge again.

## Tables converge

`widgets::table_chrome` gives `Table`, `DataTable`, `TreeTable` and
`VirtualGrid` one header language:

- header label is always `Role::TextMuted` on a `Role::Raised` band —
  `TreeTable` no longer brightens its header to `TextStrong` when focused (a
  header is a column label, not a state);
- the sort marker comes from the glyph catalog: `↑`/`↓`, ASCII `^`/`v`.
  It was `▲`/`▼` in `Table`'s `sort_glyph` and hand-spelled in the other two.

```rust
// Before — private helper, fixed glyphs
sort_glyph(direction) // "▲" / "▼"
// After — profile-aware
sort_glyph(system, direction) // "↑" / "↓" / "^" / "v"
```

## VirtualGrid follows the spec

The cursor cell reverses (`TextStrong` + `REVERSED`) instead of painting the
brand accent, and the range washes with `SelectionTint` instead of filling with
`Accent`. **Unfocused, the cursor keeps its gutter marker** in the row-number
column, so losing focus no longer loses your place.

## Sticky rows keep their chrome

`VirtualList`'s pinned rows resolve the same recipe as the body: scrolling a
selected row into the sticky band no longer makes it look unselected, and the
gutter column lines up with the rows below.

## Empty states

`TreeTable`, `KeyValueTable`, `DetailTable`, `VirtualGrid` and `Timeline` gain
`empty_message`, and paint it when they have nothing to show:

```rust
let table = TreeTable::new(&columns, &rows, &system).empty_message("No files match");
```

Defaults: "No rows" (`TreeTable`, `VirtualGrid`), "No fields"
(`KeyValueTable`), "Nothing to show" (`DetailTable`), "No events"
(`Timeline` — its previously hard-coded `(no events)` line). A filtered
`Sidebar` with no matches prints a muted "No matches" instead of an empty rail.

## Split dividers obey the border law

`SplitPane` and `ResizablePanelGroup` painted `┃`/`┋`/`━`/`┅` to mean focused
or hovered — border weight encoding focus, which the design law forbids. Both
now paint one rule glyph (`│`/`─`) in every state and change the role instead:
`Border` → `Focus` (hover) → `BorderFocused` (focus).
