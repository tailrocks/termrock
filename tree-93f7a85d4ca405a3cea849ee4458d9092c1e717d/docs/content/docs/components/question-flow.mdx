## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

## Try it

- `↑↓ choose`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `Space toggle`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `type free text`: Focus the editable field, then type or paste Unicode text; the draft remains visible.
- `Enter answer/submit`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `click option`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `Esc cancel`: Open the transient state first, then cancel it; focus and the underlying state are preserved.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted widget owns interaction state, focus chrome, hit geometry, and typed outcomes. The host only forwards backend-neutral events and performs no external effects.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `question-flow/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn question_flow_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    use termrock::widgets::{QuestionFlow, QuestionFlowState, example_question_set};
    let mut state = QuestionFlowState::new();
    state.open_set(example_question_set());
    state.focused = true;
    frame.render_stateful_widget(&QuestionFlow::new(system), area, &mut state);
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Test recipe
