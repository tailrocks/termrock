## State and typed outcomes

`DropdownMenuState` owns its cascade, cursor, typeahead, and hit geometry. The host owns the command effect and opener-focus restoration after the typed outcome closes the menu.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `dropdown-menu/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn dropdown_menu_basic_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let nodes = example_dropdown_nodes();
    let mut state = DropdownMenuState::new();
    let _ = state.open_from_keyboard(&nodes, area);
    DropdownMenu::new(&nodes, system).paint(area, frame.buffer_mut(), &mut state);
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
