## Try it

- `type or paste path`: Focus the editable field, then type or paste Unicode text; the draft remains visible.
- `Enter validate`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `click Browse`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `click clear`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted widget owns interaction state, focus chrome, hit geometry, and typed outcomes. The host only forwards backend-neutral events and performs no external effects.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `path-input/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn path_input_basic_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let mut state = PathInputState::new()
        .with_style(PathStyle::Unix)
        .with_path("/usr/local/bin");
    state.set_focused(true);
    state.set_fs_status(PathFsStatus::Directory);
    let _ = PathInput::new(system)
        .label("Install dir")
        .ascii(true)
        .paint(area, frame.buffer_mut(), &mut state);
}
```

## Migrated handbook guidance

# PathInput

**Purpose.** Path entry for installers, connection setup, and FilePicker shells.
TermRock owns typing, history, completion/browse *signals*, and pure path
helpers. Hosts own all filesystem I/O and sandbox policy.


## Ownership

| Concern | Owner |
|---------|--------|
| Field text, history, browse/complete outcomes | PathInput |
| `std::fs` / remote / sandbox lookups | Host |
| Existence, type, destructive risk | Host projection |

## Host loop sketch

```rust
match state.handle_key(key) {
    PathInputOutcome::Changed => {
        state.set_fs_status(PathFsStatus::Pending);
        host.lookup(state.path()); // async; later set_fs_status
    }
    PathInputOutcome::CompletionRequested { prefix, .. } => {
        let names = host.list_dir(&prefix.directory);
        // show CompletionMenu; on pick:
        state.apply_completion(&names[0]);
    }
    PathInputOutcome::BrowseRequested => host.open_file_picker(),
    PathInputOutcome::Submitted { path } => {
        let resolved = state.resolved_against_base();
        host.use_path(resolved);
        let _ = path;
    }
    _ => {}
}
```

## Destructive targets

Host sets `PathRisk::Destructive` for overwrites or sensitive system paths.
PathInput paints danger chrome and optional “destructive target” caption.

## Pure helpers
