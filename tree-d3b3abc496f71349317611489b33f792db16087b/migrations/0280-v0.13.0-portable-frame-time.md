# 0280 — Portable frame time

TermRock's public frame-time contract is now portable across native targets and
`wasm32-unknown-unknown`. `termrock::runtime::Instant` is the canonical clock
type used by `FrameTick`, `FrameClock`, `Presence`, timed widgets, and deadline
helpers.

## Removed assumption

Consumers must not name `std::time::Instant` at a public TermRock time boundary.
It remains source-compatible on native targets because `web-time` delegates to
the standard monotonic clock there, but `std::time::Instant::now()` is not a
working browser clock.

## Canonical replacement

```rust
use std::time::Duration;
use termrock::runtime::{FrameClock, FrameTick, Instant};

let start = Instant::now();
let mut clock = FrameClock::from_start(start);
let tick = FrameTick::manual(start, Duration::ZERO, Duration::ZERO);
let _ = (clock.tick_at(start), tick);
```

Before:

```rust
use std::time::{Duration, Instant};
use termrock::runtime::FrameTick;

let tick = FrameTick::manual(Instant::now(), Duration::ZERO, Duration::ZERO);
```

After:

```rust
use std::time::Duration;
use termrock::runtime::{FrameTick, Instant};

let tick = FrameTick::manual(Instant::now(), Duration::ZERO, Duration::ZERO);
```

Apply the same import change to `next_deadline`, `started_at`, `shown_at`, and
hover/debounce timestamps passed to TermRock. Duration remains
`std::time::Duration`.

## Ownership and rollback

Hosts still own clock sampling and inject one immutable `FrameTick` per frame;
widgets never start timers or schedule browser work. Native behavior is
unchanged. A rollback is source-only: restore the previous revision and change
portable `Instant` imports back to `std::time::Instant`; no data or persisted
state is migrated.

## Validation

```sh
cargo test -p termrock --all-features --lib runtime
cargo check -p termrock --no-default-features --target wasm32-unknown-unknown
cargo check -p termrock-lookbook-web --target wasm32-unknown-unknown
(cd docs && bun run check:preview-metrics)
```
