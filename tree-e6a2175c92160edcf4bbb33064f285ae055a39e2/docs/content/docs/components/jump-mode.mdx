## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

<TerminalPreview story="jump-mode/multi" interactive caption="JumpMode · JumpMode multi-key — live shared Rust state" />

## Try it

- `F/M jump`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `click target`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `Esc dismiss`: Open the transient state first, then cancel it; focus and the underlying state are preserved.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted widget owns interaction state, focus chrome, hit geometry, and typed outcomes. The host only forwards backend-neutral events and performs no external effects.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `jump-mode/multi`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn jump_mode_multi(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    frame.render_widget(
        Panel::new(system)
            .title("Jump multi-key")
            .emphasis(PanelChrome::Normal),
        area,
    );
    let labels = generate_jump_labels(30);
    let targets: Vec<_> = labels
        .iter()
        .enumerate()
        .map(|(i, k)| {
            let row = (i as u16) % area.height.saturating_sub(2).max(1);
            let col = ((i as u16) / area.height.saturating_sub(2).max(1)) * 6;
            JumpTarget::new(
                i,
                Rect::new(
                    area.x.saturating_add(1).saturating_add(col),
                    area.y.saturating_add(1).saturating_add(row),
                    5,
                    1,
                ),
                k.clone(),
            )
        })
        .collect();
    let mut state = JumpOverlayState::new();
    state.open();
    // Prefix first letter of a multi-key label for dim demo
    if let Some(t) = targets.iter().find(|t| t.keys.len() >= 2) {
        let ch = t.keys.chars().next().unwrap();
        let _ = state.handle_key(
            termrock::input::KeyEvent::new(
                termrock::input::KeyCode::Char(ch),
                termrock::input::KeyModifiers::NONE,
            ),
            &targets,
        );
    }
    frame.render_widget(
        JumpOverlay::from_state(&targets, system, &state).ascii(false),
        area,
    );
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
