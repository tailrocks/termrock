## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

## Try it

- `↑↓ select`: Move through the real focus/selection model; the next action uses the new target.
- `Enter preview/confirm`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `R restore`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `W rewind`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `C compare`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `F follow`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `click row`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The mounted widget owns interaction state, focus chrome, hit geometry, and typed outcomes. The host only forwards backend-neutral events and performs no external effects.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `checkpoint-timeline/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn checkpoint_timeline_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    use termrock::widgets::{CheckpointTimeline, CheckpointTimelineState, example_checkpoints};
    let mut state = CheckpointTimelineState::new();
    state.set_checkpoints(example_checkpoints());
    state.focused = true;
    frame.render_stateful_widget(&CheckpointTimeline::new(system), area, &mut state);
}
```

## Migrated handbook guidance

# CheckpointTimeline

Session checkpoint browser. Outcomes are **requests only**; host owns
persistence and restore I/O. **Never** clears PromptComposer draft.


## When to use / when not

| Use CheckpointTimeline | Prefer |
|------------------------|--------|
| Agent session restore / rewind | — |
| General deploy/CI chronology | [Timeline](/docs/components/timeline) |
| Field value history | [HistoryPicker](/docs/components/history-picker) (if present) |
| Patch compare | [DiffReview](/docs/components/diff-review) via CompareRequested |

## Modes

| Mode | Mutates session? |
|------|------------------|
| Browse | No |
| Preview | No (draft preserved) |
| Confirm | Request only — host executes |

Confirm defaults focus to **Cancel**.

## Boundaries

Soft · Dirty workspace · External effects · Irreversible (blocked)

## Keys

j/k · Enter preview · r restore · w rewind · c compare · Esc · confirm ←/→ Enter

## Related

Timeline · DiffReview · migration `0229`

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

Mount `checkpoint-timeline/basic`, dispatch each listed action, and assert the typed outcome, changed Ratatui cells, persistent follow-up state, pointer hit geometry, and Reset behavior.
