## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

## Try it

- `Space/Enter toggle`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `click toggle`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `drag outside cancels`: Press, drag, and release on the visible handle; geometry/value follows the pointer.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The demo preserves widget state between events. The component owns hit geometry, focus/selection mechanics, and typed outcomes; the host applies domain effects.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `switch/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn switch_basic_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let mut off = SwitchState::new(false);
    let mut on = SwitchState::new(true);
    on.set_focused(true);
    let h = area.height.max(1);
    let row0 = Rect::new(area.x, area.y, area.width, 1.min(h));
    let _ = Switch::new("dark", "Dark mode", system)
        .description("Follow system appearance")
        .paint(row0, frame.buffer_mut(), &mut off);
    if area.height >= 3 {
        let row1 = Rect::new(area.x, area.y.saturating_add(2), area.width, 1);
        let _ =
            Switch::new("sync", "Background sync", system).paint(row1, frame.buffer_mut(), &mut on);
    } else if area.height >= 2 {
        let row1 = Rect::new(area.x, area.y.saturating_add(1), area.width, 1);
        let _ =
            Switch::new("sync", "Background sync", system).paint(row1, frame.buffer_mut(), &mut on);
    }
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Test recipe

Mount `switch/basic`, dispatch only the actions listed above, and assert both the returned outcome and changed Ratatui cells. Unsupported input remains ignored without trapping page navigation.
