# 0311 — Picker columns hold still, and notifications get a clock

## Behavior changes

**`HistoryPicker` reserves its pin slot on every row.** The star occupied two
cells when a row was pinned and nothing when it was not, so every column to its
right — kind badge, text, meta — sat two cells further left on unpinned rows. A
list with one pinned entry read as a ragged list. The slot is reserved either
way now, and a test pins it: the kind badge starts at the same column on every
row.

**`NotificationCenter` shows an age, not an epoch.** Rows ended in `t1755201` —
the host's raw clock seconds, printed verbatim. Rows now read `just now`,
`3m ago`, `2h ago`, `5d ago` when the host keeps the widget's clock current,
and fall back to a plain `{n}s` age otherwise. Never an epoch.

## New surface

```rust
// The host owns time; TermRock has no clock of its own.
state.set_now_secs(host_now_secs);
```

`NotificationCenterState::set_now_secs` closes the API gap that plan 009
recorded: the widget already received `now_secs` when ingesting archives but
had no way to keep it, so paint had nothing to subtract from. Without it the
row still states a duration rather than a timestamp.

## Consumer edits

- A host asserting on `t{secs}` in a notification row: the format is relative
  now, or `{n}s` when no clock is set.
- Snapshots of an unpinned history row: text starts two columns further right,
  in line with the pinned rows.

## Validation

```sh
cargo nextest run -p termrock --all-features pinned_and_unpinned
mise run check
```
