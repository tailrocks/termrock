# 0314 — Examples only compose

`patterns/` was neither a widgets catalog nor a set of examples: 36 files that
hand-rolled paint belonging in widgets — four identical private `Panelish`
structs, three copies of a destructive-confirm overpaint, bespoke metric tiles,
a hand-built status strip, four private filter rows — while four "patterns"
shipped geometry with no paint at all. An example that hand-rolls chrome
teaches the wrong thing, and the design language loses its enforcement point.

After this change every file under `patterns/` composes public widgets and
nothing else, and gates keep it that way.

## Moved to `termrock::widgets`

| Type | Was |
|---|---|
| `MetricTile`, `MetricTileHealth`, `MetricViz` | `termrock::patterns` |
| `MetricTileView`, `MetricTilePresentation` | new |
| `StatusStrip`, `StatusSegment` | inline in `agent_status_header` |
| `ConfirmPrompt`, `ConfirmFocus`, `ConfirmPromptHits`, `CONFIRM_PROMPT_ROWS` | three private copies |
| `ChromeRow`, `ChromeRowKind` | four private filter rows |
| `PanelTitleSpec` | ad-hoc title strings |
| `PanelChrome::for_focus` | a two-armed conditional in every focusable container |
| `DesignSystem::paint_row` | `Buffer::set_stringn` at 174 call sites |

```rust
use termrock::widgets::{ConfirmPrompt, MetricTile, MetricTilePresentation, StatusStrip};

// A metric card or a metric row, from the same projection.
tile.view(&system)
    .presentation(MetricTilePresentation::Card)
    .focused(true)
    .paint(rect, buffer);

// One destructive confirmation for the whole library.
let hits = ConfirmPrompt::new("Delete branch", "Delete", &system)
    .detail("history is not recoverable")
    .paint(area, buffer);
```

## Behavior changes

- **Metric tiles** state value in `TextStrong`, unit in `TextMuted`, and delta
  with a `▲`/`▼` glyph *before* its colour; health is confined to the tile's
  status letter, and the sparkline reads as a data series rather than as an
  alarm.
- **Status strips** drop by stated priority instead of by position, spend at
  most one status hue and one accent, and reserve room for their overflow hint.
- **Confirmations** are two real `Button` chips with `Cancel` resting focus and
  danger on the confirm chip; the old bracket-wrapped words are gone.
- **Filter and rename rows** share one vocabulary: a query sits in a `Sunken`
  well with the caret as its only live cell; a rename is a mode (muted), not a
  warning (yellow).
- **Panel titles** may be composed: `Name(scope)[count] /filter`, with the name
  loud, the scope quiet, the count faint and the filter accented only while it
  filters.
- **`SetupWizard`, `SettingsScreen`, `AuthEntry`** ship real primary buttons
  (`Continue`/`Finish`, `Apply`, `Sign in`) instead of chord-only actions. The
  chords still work.
- **`OpsDashboard`** Tab no longer stops in the metrics strip or the status
  bar; those regions own no interaction.
- **`ops_dashboard`, `resource_browser`, `agent_shell`, `studio_shell`** gain
  `render_*` reference paints over their existing `layout_*` slots. The
  geometry-only entry points remain for hosts that paint themselves.

## Breaking changes

- `MetricTile`, `MetricTileHealth` and `MetricViz` import from
  `termrock::widgets`, not `termrock::patterns`.
- Snapshots of any listed surface change: tone ladders, real buttons, and the
  shared confirm/query chrome all differ from the hand-rolled versions.
- `AGENTS.md` and `docs/design/building-block-vs-example-composite.md` now
  state the zero-raw-paint clause; a consumer copying an example inherits it.

## Gates

- `design_gate.rs::patterns_only_compose` — no `set_stringn` / `cell_mut`
  anywhere under `patterns/`.
- `design_gate.rs::patterns_have_charter_docs` — every example opens with
  `//! Teaches:`.
- `design_gate.rs::widgets_never_import_patterns` — the dependency runs one
  way (boundary law §6).
