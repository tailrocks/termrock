# 03 — Termrock seams and old-rev render capability

Questions: (1) current frame-export seam schema and CLI; (2) frame-JSON → ANSI replay feasibility and existing Buffer→ANSI code; (3) what exists at old rev 5ff94ee (jackin's pin); (4) smallest honest old-rev render path; (5) changed-files → affected-stories detectability for a bless-required CI gate; (6) lookbook story coverage for the jackin-used subset.
Informs: jackin-termrock-parity
Method: codebase read (+ git archaeology at 5ff94ee117fd4a1b72fdd0d1b1847815055a93ac via `git show`, `git ls-tree`, and a scratchpad worktree that was built, exercised, and removed)
Vetted: 2026-08-16

## Findings

### Q1 — Current frame-export seam (`crates/termrock-lookbook/src/frame.rs`)

- `FrameCell` schema: `ch: String` (grapheme cluster), `fg: [u8;3]`, `bg: [u8;3]`, and four bools `bold`, `dim`, `underline`, `reversed` — nothing else — `crates/termrock-lookbook/src/frame.rs:30-50` (confidence: HIGH)
- `TerminalFrame` schema: `story_id`, `title`, `component`, `cols`, `rows` (padded totals), `story_cols`/`story_rows` (inner), `cells: Vec<FrameCell>` row-major with `len == cols*rows`, `interactive: bool`, `theme: String` label — `frame.rs:53-75`. Verified live: `target/debug/termrock-lookbook frame --story panel/focused` emits exactly those keys, 50×9 = 450 cells (confidence: HIGH)
- Paint path: `paint_story_frame` builds a ratatui `TestBackend` terminal at story size + `STORY_PAD` (=1, `frame.rs:27`), paints a `PREVIEW_CARD` charcoal ground, fills the inner rect with `Role::Canvas`, then calls the story's real interactor `render` — `frame.rs:238-288`. `paint_story_after_keys` replays browser-style `PreviewKey`s through the same interactor before painting — `frame.rs:292-343` (confidence: HIGH)
- Colors are fully resolved at encode time: `resolve_cell_paint` swaps fg/bg when `REVERSED` (flag kept "for hosts", `frame.rs:47`) and pre-darkens fg by 0.6 when `DIM` — `frame.rs:173-199`; named ratatui colors map to phosphor-flavored RGB and `Indexed` goes through an xterm-256 table — `frame.rs:201-228`, `palette256.rs` (confidence: HIGH)
- Modifier losses: `resolve_cell_paint` reads only `REVERSED|DIM|BOLD|UNDERLINED` (`frame.rs:180-198`); `ITALIC` and `CROSSED_OUT` are dropped from the JSON, while the sibling SVG exporter does emit italic (`svg.rs:231-232`) and bold/underline (`svg.rs:225-230`). Italic is in real use in stories (e.g. `stories.rs:22190 .italic()`) (confidence: HIGH)
- No cursor channel: `TerminalFrame` has no cursor field (`frame.rs:53-75`); TermRock paints cursors as styled cells ("a cell cursor is a cell", `crates/termrock/src/style/tokens.rs:183`; `cursor: Style` token `tokens.rs:609`), so cursors survive as reversed/styled cells in the grid (confidence: HIGH)
- No wide-char flag: `encode_buffer` pushes one `FrameCell` per grid coordinate with `cell.symbol()` as-is (`frame.rs:151-171`); there is no `skip`/width field, so a raster renderer must infer double-width from the grapheme itself (confidence: HIGH)
- CLI surface (`main.rs:23`): `terminal | list | render | check | frame | export-posters`. `frame --story <id> [--cols N] [--rows N] [--keys k1,k2]` prints one `TerminalFrame` JSON to stdout, theme hard-fixed to `RolePalette::default()` (phosphor) with no `--theme` flag — `main.rs:186-241`; `export-posters --out <dir> --story <id>...` writes `<slug>.json` per explicitly listed story — `main.rs:243-284`; `render --theme <phosphor|slate> --out` is the SVG path — `main.rs:139-160` (confidence: HIGH)
- Every registered story is frame-exportable via `story_by_id` over `stories()` (`frame.rs:230-234`): 1066 `Story::new` registrations (counted with a regex over `stories.rs`), 1133 ids listed by the prebuilt `target/debug/termrock-lookbook list | wc -l` (extra ids are generated "in application" variants, `stories.rs:279-` `IN_APP_SCENES`) (confidence: HIGH for 1066; MED for 1133 — binary may predate HEAD)
- A raster consumer of exactly this JSON already exists: `docs/src/components/TerminalPreview.tsx` draws `FrameCell` grids onto an HTML canvas (cell type mirror at `TerminalPreview.tsx:45-51`, canvas paint ~`:119-155`), with fixed cell metrics mirrored in Rust (`CELL_WIDTH_PX=9`, `CELL_HEIGHT_PX=18`, `frame.rs:346-348`). 184 committed poster JSONs live under `docs/public/preview-posters/` (counted with `ls | wc -l`), including one per jackin-subset widget's primary story; regenerated via `mise.toml:97 [tasks.export-preview-posters]` (confidence: HIGH)

### Q2 — Frame JSON → ANSI replay; existing Buffer→ANSI code

- No Buffer→ANSI serializer exists anywhere in the repo. `crates/termrock/src/ansi_text.rs` is inbound-only: it parses/strips ANSI SGR bytes into styled spans for safe paint ("without letting escape sequences leak to the host terminal", `ansi_text.rs:4-8`; strip `:33-35`; parse `:53-64`). Searches for `to_ansi|write_ansi|encode_ansi|as_ansi` hit only `terminal_output.rs:459 to_ansi_mode` (a parse-mode enum) and `style/quantize.rs:269 rgb_to_ansi16` (color quantization, not byte emission) (confidence: HIGH)
- Live terminal output goes through ratatui's crossterm backend at runtime (`runtime/presenter.rs:410-430` cursor plumbing); there is no offline "Buffer to escape-sequence string" utility (confidence: HIGH)
- Mechanical replay of the frame JSON as ANSI is possible (each cell has grapheme + truecolor fg/bg), but the JSON is post-resolution: `REVERSED` is already swapped into fg/bg (`frame.rs:180-183`) and `DIM` already darkened fg (`frame.rs:184-189`), so an emitter that forwarded both the RGB values and the SGR flags would double-apply those effects; italic/strikethrough are unrecoverable from the JSON (Q1). The unresolved `ratatui::Buffer` (full `Color` + `Modifier`) exists in memory one line before encoding (`frame.rs:274`) — that is the seam where full-fidelity ANSI bytes could be produced; no such writer exists today (confidence: HIGH)

### Q4 — Smallest honest old-rev render path (evidence only)

- The old rev builds today, unmodified: `cargo build -p termrock-lookbook` in a scratchpad worktree at 5ff94ee1 exited 0 (7.59s, warm dep cache; measured in this session) (confidence: HIGH)
- The old binary produces deterministic per-story renders out of the box: `termrock-lookbook render --theme phosphor --out <dir>` wrote 45 SVGs; two consecutive runs were byte-identical (`diff -r` clean; measured). The same double-render diff is the pin-era-to-current CI determinism gate shape (`.github/workflows/docs.yml:115-118`) (confidence: HIGH)
- Old SVG fidelity limit: old `buffer_to_svg` emits colors only — grep for `Modifier|font-weight|text-decoration|font-style|bold|underline|dim` over old `svg.rs` returns nothing — so bold/dim/underline/reversed/italic are all absent from old-rev SVGs, whereas current `svg.rs` emits bold/underline/italic (`svg.rs:225-232`), dim darkening (`:303-309`), and reversed resolution (`:288`) (confidence: HIGH)
- Buffer-level seam at the pin: `render_story_to_buffer(story, theme)` uses ratatui `TestBackend` with the same PREVIEW_CARD ground and 1-cell pad as today (old `svg.rs:15-22, 43-60`), but is `pub(crate)` inside a binary-only crate — not importable without patching (confidence: HIGH)
- Standalone widget renders against the old `termrock` lib are constructor-feasible: the library crate is public and every jackin-subset widget has a public theme-parameterized constructor at 5ff94ee1 — sampled 13 files: `list.rs:436`, `text_input.rs:324`, `toast.rs:125`, `dialog.rs:222`, `progress.rs:44`, `tabs.rs:104`, `status_bar.rs:85`, `viewport.rs:31`, `diff.rs:43`, `detail_table.rs:301`, `action_bar.rs:57`, `hint_bar.rs:73`, `panel.rs:30`; state types (`ListState::new`, `TextInputState::new`, `ChoiceDialogState::new`, …) are likewise public (old `mod.rs` exports) (confidence: HIGH)
- Pairing anchor: **every one of the 45 old story ids still exists at HEAD**, including all 25 old ids belonging to the jackin subset (set intersection of `Story::new` id regex extractions from both revs; 0 missing) (confidence: HIGH)
- Padding/ground continuity: `STORY_PAD = 1` and `PREVIEW_CARD = Rgb(28,28,28)` are identical at both revs (old `svg.rs:30`, old `style/palette.rs:40`; current `frame.rs:27`, `style/palette.rs:88`) (confidence: HIGH)

### Q5 — Detectability of "affected widgets" for a bless-required CI gate

- Widget file boundaries are clean: `crates/termrock/src/widgets/` holds 151 files (counted with `ls | wc -l`), essentially one file per widget; within the jackin subset the mapping is 1:1 by snake_case stem except `dialog.rs`, which hosts four story components (`Dialog`, `Backdrop`, `ChoiceDialog`, `MessageDialog` — struct grep) (confidence: HIGH)
- component → stories is already machine-readable: `termrock-lookbook list --format json` emits `DemoDescriptor { id, component, … }` per story (`demo.rs:49-83`); `docs/scripts/check-catalog.ts:14-31` consumes it, derives the 136-widget public inventory from `docs/api/public-api.txt` impl-Widget lines (`check-catalog.ts:24-28`, hard-asserted `== 136` at `:28`), and enforces every public widget has ≥1 story (`:29-31`). `docs/scripts/sync-component-contracts.ts:22-33` builds the same component→variants map (confidence: HIGH)
- file → component is only partially machine-readable: `ComponentContract` in `crates/termrock/src/registry/catalog.rs` carries `files` (with `Primary` role, `contract.rs:127-138`) plus `stories` (`contract.rs:271`) — e.g. Panel: primary `widgets/panel.rs` + 5 story ids (`catalog.rs:69-75, 126-132`) — but only 30 contracts exist (counted with `rg -c "ComponentContract {"`), and among the jackin subset only `Panel` (`catalog.rs:61`) and `ScrollArea` (`catalog.rs:141`) are covered. For the rest, file→component is naming convention only (confidence: HIGH)
- No changed-file selection exists in CI today: no `paths:`/paths-filter/`git diff` logic in any workflow (grep over `.github/workflows/*.yml`); existing gates run globally — docs.yml double-render determinism diff (`docs.yml:115-118`), hygiene.yml single frame smoke + poster-fixture presence (`hygiene.yml:80-81`) (confidence: HIGH)
- Enforcement precedent for repo-law gates lives in `crates/termrock/tests/design_gate.rs` (e.g. `patterns_only_compose` scanning for raw-paint calls, `:1637-1648`) (confidence: HIGH)

## Dead ends and contradictions

- Checked for a `Buffer` → ANSI-bytes writer under `crossterm/`, `runtime/`, `osc/`, lookbook, and lookbook-web: none exists; `ansi_text.rs` is strictly an inbound parser despite the suggestive name (its `tests.rs` confirms parse-direction only).
- `registry/official/` on disk contains only a README — the real contract data is compiled into `registry/catalog.rs`, so there is no per-widget JSON manifest to key a file→story map off today.
- First glob for `check-catalog.ts` missed it (bad glob); it does exist at `docs/scripts/check-catalog.ts` and is the strongest existing inventory gate — earlier "not found" impression was wrong and is corrected above.
- Old-rev SVGs initially looked like a ready-made comparison baseline; they are, but only at color fidelity — the old exporter drops every modifier, so modifier-level regressions are invisible in old SVG output (buffer-level capture at the pin requires a patch or side harness).
- `component-contracts.json` (docs/api) looked like a file map; it is a six-axis coverage matrix (focus/keyboard/mouse/narrowTerminal/nonColor/unicode) keyed by component, no file paths.
- No embedded instructions or secrets were encountered in any file read; all quoted content is data.
