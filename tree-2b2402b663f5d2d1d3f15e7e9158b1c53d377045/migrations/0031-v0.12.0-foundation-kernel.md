# 0031 — Foundation kernel: design tokens, UiIntent, scene, overlay controller

## Removed surface

None required. `ListState::handle_key` behavior is preserved via
`default_list_intent` → `handle_intent`. `FocusRing::pop_scope` is now public
and returns `FocusOutcome` (was private, no return).

## Canonical addition

### Docs

- `docs/design/architecture-foundation.md` — hybrid kernel + design system + progressive capability reduction

### Style

- `DesignTokens`, `SpacingScale`, `GlyphSet`, `SelectionChrome`, `ListRowRecipe`
- `DesignTokens::list_row_recipe` — one chrome recipe vertical slice

### Interaction

- `UiIntent`, `NavigationMove`, `PageMove`, `default_list_intent`
- `ListState::handle_intent`
- `SemanticScene`, `SemanticElement`, `SemanticRole`
- `OverlayController`, `OverlayEscResult` (Esc peels one overlay, then cascade; optional focus scope restore)
- Public `FocusRing::push_scope`, `pop_scope`, `scope_depth`

## Consumer edits

Prefer:

```rust
if let Some(intent) = default_list_intent(key) {
    list.handle_intent(&rows, intent);
}
// or map keys through your Keymap into UiIntent
```

Use `DesignTokens` for density/glyph/selection recipes. Use `OverlayController`
instead of ad-hoc Esc stacks. Register paint targets in `SemanticScene` each frame.
