# 0283 — The contrast floor

Contrast defects used to arrive one at a time: disabled text lost on the
canvas, elevation steps a rounding error apart, a hovered button label
repainted onto a fill it could not be read against. TermRock now measures
every foreground/background pair the design language paints and holds it to a
documented minimum, so the class is closed instead of the instances.

## New surface

```rust
use termrock::style::{Rgb, RolePalette, Role, contrast_ratio, relative_luminance};

let palette = RolePalette::tailrocks_phosphor();
let text = Rgb::from_color(palette.style(Role::Text).fg.unwrap()).unwrap();
let canvas = Rgb::from_color(palette.style(Role::Canvas).bg.unwrap()).unwrap();
assert!(contrast_ratio(text, canvas) >= 7.0);
let _ = relative_luminance(canvas);
```

`Rgb::from_color` returns `None` for indexed and named ANSI colors: those
resolve in the operator's terminal, so they carry no value TermRock can
measure.

## The floor

Theme authors shipping a custom `RolePalette` are held to the same table the
built-in presets are (`style/contrast_floor.rs`):

| Pair | Floor |
|---|---|
| `Text` / `TextStrong` on any surface role | 7.0 |
| `TextMuted` on Canvas/Surface | 4.5 |
| `TextDisabled` on Canvas/Surface | 2.5 |
| `Danger` / `Warning` / `Info` / `Success` on Canvas/Surface and on their own tints | 4.5 |
| `Text` / `TextStrong` on `SelectionTint` / `HoverTint` | 4.5 |
| Recipe label fg on the fill it is painted over | 4.5 (2.5 disabled) |
| `Border` against its surface | 1.3 |
| Adjacent ladder surfaces | 1.15 |

All text tiers are held to 7.0 in the `high_contrast` preset.

## Behavior change

**Hovered buttons no longer repaint their label with the link hue.** A primary
button resolved a hovered label of `LinkHover` cyan over its `ActionFocused`
green fill — 1.02:1, an invisible label. Only `ButtonRecipeVariant::Link`
brightens its label on hover now; unfilled variants (`Secondary`, `Quiet`,
`Outline`) take a `HoverTint` ground instead, and filled variants (`Primary`,
`Destructive`) keep the label they already had.

```rust
// Before: label = Role::LinkHover for every variant.
// After:
let recipe = system.button_recipe(ButtonRecipeVariant::Primary, ControlState::Hovered);
assert_eq!(recipe.label, system.style(Role::ActionFocused));
```

## Recorded shortfalls

Twenty-five pairs cannot clear their floor with the palette values on this
branch today — the pre-graphite text ladder, the near-flat surface ladder, and
the light preset's web-picked status hues. They are listed exactly in
`KNOWN_SHORTFALLS`, each attributed to
`plans/002-role-palette-foundation.md`, and the test asserts they *still*
fail: when a palette change fixes one, its line must be deleted in the same
commit. Baseline ratios are recorded next to each entry (for example
`TextDisabled` on Canvas at 2.43:1 against a 2.5 floor).

## Consumer edits

- A custom palette that fails the floor now fails `cargo test` in this crate
  only; consumer palettes are unaffected until they run the same table.
- Snapshots pinning a hovered primary/secondary button's label color must be
  re-blessed.
