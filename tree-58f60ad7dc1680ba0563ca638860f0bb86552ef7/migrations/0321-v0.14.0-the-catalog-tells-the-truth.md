# 0321 — The catalog tells the truth

The lookbook is how the design work becomes visible, and it was showing
something else: a design system nobody ships, stories matted onto black
whatever the palette, an exporter that dropped weight and underline and painted
every indexed colour white, an inspector that reported three hardcoded strings,
and a "deterministic preview check" that diffed a render against itself.

## Behavior changes

**One host system, preset-true.** 167 sites built their own with
`DesignSystem::from_palette(theme)`, which takes a palette's colours and none
of the preset's other decisions — so every preview painted a `SelectionChrome`
no shipped preset uses, and the selection language of plans 004/006 never
appeared in a single story. `termrock_lookbook::design::lookbook_system(theme)`
answers once: the phosphor preset's shape, the picked palette's colours.

**Stories sit on their palette's canvas.** Three `Clear` calls painted the
story ground terminal-black, so a light preset's preview was matted on dark.
The ground is `Role::Canvas` now, in the SVG exporter, the demo session and the
native app; the SVG page background derives from the palette too.

**Three story opt-outs are gone.** The hint-bar story blanked four `Hint` roles
under phosphor — hiding the exact ladder it documents; the viewport story
repainted `Role::Border` as `BorderFocused`, making the focus language
unreadable; the no-colour chart rebuilt its system from a bare palette. Each
now paints what the palette actually says.

**The SVG exporter is faithful.** Bold emits `font-weight="700"`, underline
`text-decoration="underline"`, italic `font-style="italic"`. `Color::Indexed`
resolves through a shared xterm-256 table
(`termrock_lookbook::palette256::xterm256_to_rgb`) instead of collapsing to
white, so quantized and ANSI-16 profiles are previewable at last — which is the
whole point of a capability ladder.

**The inspector reports reality.** `DesignInspectorFrame::from_system(&system)`
reads capability, density and selection chrome off the system that is painting;
the demo's frame metadata carries the palette the host actually picked instead
of the literal `"phosphor"`.

## New surface

- `termrock_lookbook::design::lookbook_system`
- `termrock_lookbook::palette256::xterm256_to_rgb`
- `DesignInspectorFrame::from_system`
- `Density::id`, `SelectionChrome::id`

## Gates

`crates/termrock-lookbook/tests/goldens.rs` diffs 15 flagship stories against
committed cell dumps under `crates/termrock-lookbook/goldens/`. `mise run
preview-goldens` runs it and is wired into `mise run gate`; `mise run
bless-previews` regenerates the baselines when a paint change is intended.
`TESTING.md` says what the gate does now, which it did not before.

## Consumer edits

None — the changes are in the catalog crate and in two additive `id()`
accessors. Hosts that render lookbook stories will see the preset's selection
chrome and the palette's canvas.

## Validation

```sh
mise run preview-goldens
cargo nextest run -p termrock-lookbook --all-features
rg -n "from_palette" crates/termrock-lookbook/src | wc -l   # → 2 (the helper)

```
