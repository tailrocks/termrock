## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

<TerminalPreview story="text-input/basic" interactive caption="TextInput · Text input — live shared Rust state" />

## Try it

- `type Unicode`: Focus the editable field, then type or paste Unicode text; the draft remains visible.
- `paste`: Focus the editable field, then type or paste Unicode text; the draft remains visible.
- `←→ move caret`: Dispatch this action to the mounted Rust state machine and inspect its visible typed result.
- `click place caret`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

`TextInputState` owns the draft, grapheme-safe caret, selection, and validation. The host owns submission effects. The browser paints only the caret emitted by the Rust widget buffer.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `text-input/basic`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn text_input_basic_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let mut state = TextInputState::new("filter term");
    state.set_focused(true);
    let _ = TextInput::new("Query", system)
        .placeholder("Search…")
        .show_clear(true)
        .paint(area, frame.buffer_mut(), &mut state);
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
