## Usage

```rust
use termrock::style::DesignSystem;
use termrock::widgets::{Combobox, ComboboxState, CompletionCandidate};

let system = DesignSystem::default();
let mut state: ComboboxState<&str> = ComboboxState::new();
state.set_focused(true);
// DraftChanged { generation } → host fetch → apply_suggestions(generation, …)
let _ = Combobox::new(&system).label("Language");
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Migrated handbook guidance

# Combobox & Autocomplete

**Purpose.** Free-form or constrained values with suggestions. TermRock owns
draft typing, menu navigation, and race-safe apply. Hosts own fetch/rank and
OverlayStack.


## Three values

| Value | API |
|-------|-----|
| Draft | `draft()` |
| Active suggestion | `active_suggestion()` |
| Committed | `value()` / `value_label()` |

## Async race gate

```rust
// on DraftChanged { generation }
host.fetch(text, generation);

// on response
if state.apply_suggestions(generation, &cands) {
    // fresh
} // stale generation → false, ignored
```

## Modes

- **Combobox** — `ComboboxState::new()`: exact-required, not creatable by default  
- **Autocomplete** — `ComboboxState::autocomplete()`: creatable free text
