## Usage

```rust
use termrock::style::DesignSystem;
use termrock::widgets::{TreeNavigation, TreeNavigationState, example_project_tree};

let system = DesignSystem::default();
let nodes = example_project_tree();
let mut state = TreeNavigationState::new(Some("main"));
state.set_focused(true);
state.reconcile_route(&nodes);
let _ = TreeNavigation::new(&nodes, &system);
```

## State and typed outcomes

The widget owns deterministic paint and layout. The host owns all surrounding state and effects; this demo intentionally exposes no fake cursor, click, or keyboard behavior.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Migrated handbook guidance

# TreeNavigation

**Purpose.** Project explorers, schema browsers, settings trees, documentation
outlines. **Not** the multi-select data [`Tree`](/docs/components/tree) widget.


## Route ≠ focus

- `route()` — active destination (survives filter when still in projection)
- `focus()` — keyboard cursor
- Enter on routeable leaf → `RouteChanged`

## Arrows

- **←** collapse or parent  
- **→** expand / lazy load / first child  
- **↑/↓** move focus  

## Lazy children

`LazyLoadRequested { id, generation }` → host loads → `apply_lazy_result` + new
projection → `reconcile_route` keeps selection when possible.
