# 0257 — Product composites move from `widgets` to `patterns`

## Mission

Default `termrock::widgets` is **generic building blocks only**. Product-shaped
composites (connection manager, session picker, DB query/schema/result, metrics
dashboard, agent status, approval queue, etc.) live under
`termrock::patterns` as **example recipes** assembled from generics.

## Moved modules (widgets → patterns)

| Module | Primary types (non-exhaustive) |
|--------|--------------------------------|
| `connection_manager` | `ConnectionManager`, `ConnectionEntry`, … |
| `session_picker` | `SessionPicker`, `SessionEntry`, … |
| `metrics_dashboard` | `MetricsDashboard`, `MetricTile`, … |
| `query_editor` | `QueryEditor`, … |
| `schema_browser` | `SchemaBrowser`, … |
| `result_grid` | `ResultGrid`, … |
| `agent_status_header` | `AgentStatusHeader`, … |
| `integration_status` | `IntegrationStatus`, … |
| `approval_queue` | `ApprovalQueue`, … |
| `working_state_card` | `WorkingStateCard`, … |
| `plan_review` | `PlanReview`, … |
| `prompt_queue` | `PromptQueue`, `AgentBusyState`, … |
| `activity_shelf` | `ActivityShelf`, `ActivityItem`, … |
| `background_task_panel` | `BackgroundTaskPanel`, … |
| `subagent_card` | `SubagentCard`, … |
| `terminal_run_card` | `TerminalRunCard`, … |
| `process_table` | `ProcessTable`, … |
| `task_rail` | `TaskRail`, … |

Already-example recipes (`AuthEntry`, workbenches, dashboards, launchers, …)
remain under `patterns`.

## Consumer edits

```rust
// Before
use termrock::widgets::{ConnectionManager, SessionPicker, QueryEditor};

// After
use termrock::patterns::{ConnectionManager, SessionPicker, QueryEditor};
// Generics stay:
use termrock::widgets::{Panel, List, TextInput, Button};
```

## Validation

```bash
rtk cargo check -p termrock -p termrock-lookbook
rtk cargo test -p termrock --lib patterns::
```
