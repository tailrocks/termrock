# 0322 — Overlays survive any terminal

**Version:** `v0.14.0`
**Kind:** behavioral fix (no API change)

## What changed

Opening any workbench overlay — the permission gate, the plan review, the diff
review — used to **panic** when the terminal was narrower than the overlay's
own minimum width. The modal placement computed

```rust
let width = width.clamp(w_min, area.width.saturating_sub(2));
```

and `u16::clamp` panics when the minimum exceeds the maximum. A 20-column
terminal is a real size, not a programming error, so this took the entire host
application down the moment an agent asked for permission in a narrow pane.

Modal placement now yields to the terminal:

```rust
let max_width = area.width.saturating_sub(2).max(1);
let width = width.clamp(w_min.min(max_width), max_width);
```

The overlay is drawn as wide as the terminal allows and its content contracts
through the paths that already existed for narrow frames.

## Why it is here

Nothing in the public API moved, but the observable behaviour of every
`render_agent_workbench` call with an open overlay changed from *abort* to
*paint*. Consumers who worked around the panic by gating overlays on a minimum
terminal width can remove that guard.

## Consumer edits

Remove any width guard that existed only to avoid the panic:

```rust
// Before
if area.width >= 44 {
    surfaces.permission = Some(&mut permission);
}

// After
surfaces.permission = Some(&mut permission);
```

## How it was found

`crates/termrock-showcase` — the flagship application added in `plans/019` —
renders every scenario at `20×5` in `tests/scenes.rs`. The panic showed up on
the first run. This is the showcase working as designed: an application built
only from public API finds the defects a widget test suite cannot, because a
widget test never opens an overlay inside a terminal that small.

## Validation

```sh
cargo nextest run -p termrock --all-features
cargo nextest run -p termrock-showcase --all-features
mise run check
```

The regression test is
`patterns::agent_workbench::tests::modals_survive_a_terminal_narrower_than_their_minimum`.
