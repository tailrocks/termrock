## Usage

```rust
use termrock::style::DesignSystem;
use termrock::widgets::{
    Action, FullscreenViewer, FullscreenViewerState, SourceContext, ScrollAnchor,
    ViewerContentKind, open_fullscreen_viewer_overlay,
};

let system = DesignSystem::default();
let actions = [Action { id: "copy", label: "Copy", enabled: true, style: None }];
let mut state = FullscreenViewerState::new();
state.zoom_mut().set_content_kind(ViewerContentKind::Code);
let ctx = SourceContext::new("main.rs")
    .scroll(ScrollAnchor::at(42, 0))
    .path(["repo", "src", "main.rs"]);
let _ = state.enter_fullscreen(ctx, "main.rs");
let _ = state.open_on_stack(&mut stack, bounds, Some("list"));
FullscreenViewer::new(&system, &actions).paint(entry.rect, buf, &mut state);
// Host: CodeBlock::…paint(state.body_area(), buf, &mut code_state);
```

## Try it

- No actions. This component is passive in this demo; the page remains navigable.

Accepted actions update the same mounted Rust value. The status line shows the latest outcome; **Reset** creates a fresh instance.

## State and typed outcomes

The widget owns deterministic paint and layout. The host owns all surrounding state and effects; this demo intentionally exposes no fake cursor, click, or keyboard behavior.

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.

## Test recipe

Mount `fullscreen-viewer/basic`, dispatch only the actions listed above, and assert both the returned outcome and changed Ratatui cells. Passive demos must reject input without trapping page navigation.
