## Live terminal (Ghostty-class)

This preview mounts one persistent Rust state machine. Focus it, use the current actions shown by the runtime, inspect the typed outcome, and use **Reset** for fresh state.

## Try it

- `↑↓ select`: Move through the real focus/selection model; the next action uses the new target.
- `Enter activate`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `Esc close`: Open the transient state first, then cancel it; focus and the underlying state are preserved.
- `click row`: Activate the focused or pointed target; inspect the changed cells and typed outcome below the terminal.
- `wheel`: Scroll over the preview; its own viewport moves while the docs page stays put.

Every accepted action reaches the same mounted Rust value. The status line shows the latest typed outcome; **Reset** creates a fresh instance.

## State and typed outcomes

`MenuState` owns open state, cursor, and hit rows. Scene focus and the effect behind `Activated(id)` remain host-owned.

## Usage

The Code view above and this source excerpt use the exact paint setup registered for `menu/roving`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn menu_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    let tokens = system.clone().density(Density::default());
    let items = [
        MenuItem::new("a", "Open"),
        MenuItem::new("b", "Disabled").enabled(false),
        MenuItem::new("c", "Save"),
    ];
    let mut state = MenuState::new();
    Menu::new(&items, &tokens).render(area, frame.buffer_mut(), &mut state);
}
```
