## Usage

The Code view above and this source excerpt use the exact paint setup registered for `collapsible/inline`. Interaction state is long-lived in the catalog interactor; the host only forwards backend-neutral events.

```rust
use ratatui::prelude::*;
use termrock::{input::*, interaction::*, runtime::*, style::*, widgets::*};

// Exact paint setup used by the shared catalog story.
fn collapsible_inline_story(frame: &mut Frame<'_>, area: Rect, system: &DesignSystem) {
    use ratatui::widgets::Widget as _;
    use termrock::widgets::{Collapsible, CollapsibleState};
    let mut state = CollapsibleState::new().initially_open(true);
    state.set_focused(true);
    let body = Collapsible::new("Tool details", system).paint(area, frame.buffer_mut(), &mut state);
    if body.height > 0 {
        Paragraph::new("args: --json\nstatus: ok")
            .style(system.style(Role::TextMuted))
            .render(body, frame.buffer_mut());
    }
}
```

## Common mistakes

- Do not treat separate Lookbook stories as runtime states or a slide sequence.
- Do not duplicate hit testing, focus, or keyboard rules in the host.
- Do not infer an action from visual styling; handle the widget's typed outcome.
