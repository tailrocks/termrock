# 0191 — KeyValueTable dense detail surface

## Mission

Dense interactive detail table for metadata, settings, headers, and object
properties: key · value · type · source · status · copy · edit · secret
redaction · nested groups · validation · compare/diff · column→stacked
contraction · single focus target per row (action chords).

Research: inspector panels, HTTP clients, cloud consoles, DetailTable / KeyValueList.

## Preserve / migrate / split / delete

| Surface | Fate |
|---------|------|
| `KeyValueList` / `KvEntry` / density / layout | **Preserved** — lighter summary list |
| `DetailTable` / `DetailRow` | **Preserved** — dialog selection/copy/link surface |
| `KvDensity` / `KvLayout` / `KvStatus` | **Reused** by KeyValueTable |
| `KeyValueTable` / `KvtField` / `KeyValueTableState` | **Added** (flagship detail) |
| `KvtMode` View\|Compare | **Added** |
| `KvtValidation` Ok\|Warning\|Error | **Added** |
| Nothing deleted | Prefer KeyValueTable for new HTTP/DB/process/permission/agent panels |

## Consumer API sketch

```rust
use termrock::widgets::{
    KeyValueTable, KeyValueTableState, KvtField, KvtMode, KvtValidation, KvStatus, LoadState,
};

let fields = [
    KvtField::group("g", "Request"),
    KvtField::pair("auth", "authorization", "Bearer …")
        .value_type("secret")
        .source("header")
        .secret()
        .copyable()
        .depth(1),
    KvtField::pair("ct", "content-type", "application/json")
        .editable()
        .depth(1),
    KvtField::pair("len", "content-length", "-1")
        .validation(KvtValidation::Error)
        .validation_message("must be >= 0")
        .depth(1),
];
let mut state = KeyValueTableState::new().with_cursor("auth");
state.mode = KvtMode::View; // or Compare with .compare("…") on fields
// c copy · e edit · r reveal · d compare · / filter · j/k nav
KeyValueTable::new(&fields, &system).render(area, buf, &mut state);
```
