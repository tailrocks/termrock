# 0237 — SettingsScreen elevated searchable settings block

## Mission

Complete searchable settings experience composed from **public** TermRock
widgets only: Sidebar, SearchInput, Form sections/fields, validation, dirty /
modified cues, reset-to-default **requests**, conflict and restart-required
banners, deep links, keyboard help, responsive drawer nav, no-results guidance.
Integrates ThemePicker and KeybindingRecorder. Persistence and restart policy
remain **application-owned**.

Research: Zellij config UIs, btop options, editor settings, shadcn settings
layouts (experience references).

## Preserve / migrate / split / delete

| Surface | Fate |
|---------|------|
| Thin `SettingsShellState` / `SettingsShellOutcome` in `widgets/blocks` | **Deleted** |
| `SettingsShellState` type alias | **Added** in `patterns::settings_screen` → `SettingsScreenState` |
| `SettingsShellOutcome` type alias | **Added** → `SettingsScreenOutcome` |
| `render_settings_screen`, layout, filters, fixtures | **Added** |
| Form / Sidebar / SearchInput / ThemePicker / KeybindingRecorder / KeyboardHelp | **Preserved** — composed, not forked |
| Registry package id `settings-shell` | **Preserved** dest path; source elevates to SettingsScreen API |
| Persistence / restart apply | **Host-owned** (unchanged) |

## Consumer API

```rust
use termrock::patterns::{
    SettingsScreenState, SettingsScreenSurfaces, SettingsBodyMode, SettingsDensity,
    SettingsRegion, SettingsScreenOutcome, layout_settings_screen,
    render_settings_screen, example_settings_categories, filter_settings_nav,
    settings_query_matches, example_settings_appearance_fields,
};
use termrock::widgets::{Fieldset, BUILTIN_THEME_PRESETS};

let mut state = SettingsScreenState::new();
let nav = example_settings_categories();
let fields = example_settings_appearance_fields();
let fieldsets = [Fieldset::new("Appearance", &fields)];

// Deep link
let _ = state.open_deep_link("appearance");

// each frame
render_settings_screen(buf, area, SettingsScreenSurfaces {
    system: &system,
    state: &mut state,
    nav: &nav,
    fieldsets: &fieldsets,
    theme_presets: BUILTIN_THEME_PRESETS,
    theme_paint: Some(&preview_system),
    status_slots: &[],
    status_state: &mut status,
    section_title: "Appearance",
});

// keys — outcomes are requests only
match state.handle_key(key, &nav, &fieldsets, BUILTIN_THEME_PRESETS) {
    SettingsScreenOutcome::SaveRequested => { /* host persist */ }
    SettingsScreenOutcome::ResetSectionRequested => { /* host defaults */ }
    SettingsScreenOutcome::DiscardRequested => { /* host reload */ }
    SettingsScreenOutcome::SectionSelected(id) => { /* load section model */ }
    SettingsScreenOutcome::SearchChanged => {
        let q = state.search.query();
        // host refilters nav / fieldsets
    }
    _ => {}
}
```

### Densities

| Density | Width | Layout |
|---------|-------|--------|
| `Normal` | ≥ 80 | Sidebar + search + body + footer |
| `Narrow` | 48–79 | Body; `Ctrl+B` drawer for categories |
| `Tiny` | < 48 | Body only (+ drawer optional) |

### Body modes

`Form` · `Theme` · `Keybinding` · `NoResults`

### Laws

| Law | Detail |
|-----|--------|
| Host owns values | Fields **project** strings; Form never stores domain state |
| Save / reset / discard | Outcomes only — no disk / process |
| Restart | Banner from host-projected flags / field help text |
| Conflicts | Banner + field `FieldStatus::Warning("conflict…")` |
| Esc | One layer: help → drawer → search blur |

### Stories

`settings-screen/{basic,search,validation,conflicts,theme,keybinding,narrow,tiny,no-results,help}`

## Breaking edits

1. `termrock::widgets::SettingsShellState` removed — use
   `termrock::patterns::SettingsScreenState` (or type alias
   `SettingsShellState` from `patterns`).
2. `handle_key` now requires `nav`, `fieldsets`, `theme_presets` slices.
3. Thin `search: String` / `search_focused` replaced by `SearchInputState`.
4. Registry fixture `settings-shell` API elevated (same package dest).
